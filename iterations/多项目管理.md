# 迭代：多项目管理

> 优先级 P0 | 对应 iterations/README.md 中的 [P0] 条目

## 目标

sync_tool 应支持在同一个界面中管理多个项目的同步，而不是每次切换项目都手动改配置。

## 用户工作流

```
启动 sync_tool
    │
    ▼
┌─────────────────────┐
│  项目管理首页        │
│  ┌─────────────────┐│
│  │ ▲ Project A     ││  ← 点击进入 A 的同步操作
│  │ ▲ Project B     ││
│  │ △ (空)          ││  ← 空槽位，点击添加新项目
│  └─────────────────┘│
│  [+ 添加项目]        │
└─────────────────────┘
         │
         ▼ 选择项目后
┌─────────────────────┐
│  扫描/对比/同步界面   │  ← 现有操作界面复用，但数据源改为当前选中的项目
│  (现有功能不变)       │
└─────────────────────┘
```

## 改动范围

### 1. config.py — 配置模型重构

当前（单项目）:
```python
@dataclass
class Config:
    backup_path: str = ""
    project_name: str = "Vernier"
    commit_format: dict = ...
    force_exclude: list = ...
    sync_base: str = ""
```

目标（多项目）:
```python
@dataclass
class ProjectConfig:
    name: str
    workspace_path: str = ""
    backup_path: str = ""
    commit_format: dict = ...
    force_exclude: list = ...
    sync_base: str = ""

@dataclass
class Config:
    projects: list[ProjectConfig]
    current_project: str = ""
```

向后兼容：启动时检测旧格式（顶层有 `backup_path` 字段），自动迁移为 `projects[0]`。

### 2. GUI 重构（gui_main.py）

- 新增 `ProjectListWidget`：项目列表首页
- 项目卡片：名称、工程版路径、正式版路径
- 添加项目表单
- 点击项目 → 进入 `MainWindow`，数据源绑定到该项目
- MainWindow 增加"返回项目列表"按钮

### 3. CUI 重构（cui_main.py）

- 启动先打印项目列表，让用户选择或添加
- 选择后进入现有交互流程

### 4. 同步操作适配

现有 `scan_workspace` 用 `Path.cwd()` 获取工程版路径，改为从 `ProjectConfig.workspace_path` 读取。`sync_to_backup` 对应同理。

## 不做的事

- 不做项目删除以外的高级管理（导入/导出等）
- 不修改 core.py 的核心算法
- 不做云端同步

## 验证

1. 启动 exe，空状态 → 添加项目 A
2. 添加项目 B
3. 在 A/B 之间切换，分别执行同步
4. 关闭重开，确认项目列表持久化
5. 旧版单项目配置文件自动迁移
