# File mutation

## Read effect state

Use the error's actual execution/effect state.

## Recompute against current bytes

A rejected compare-and-swap edit requires rereading the current target and recomputing the candidate against that version; use the returned current SHA-256 where the schema requires it. An absent edit anchor calls for a smaller current anchor, not an unconditional whole-file overwrite.

## Patch validation and uncertain effects

For PATCH_CHECK_FAILED, inspect preserved validation diagnostics and repair paths, headers and hunks, or use bounded native edits under the same checks. Patch preflight success is not semantic or lesson validation. A concurrent or uncertain post-commit change requires inspecting current bytes and receipts before retrying. Do not switch to shell or another write path to bypass a check.

## Cooperating writer lock

For FILE_MUTATION_BUSY, respect the existing writer lock. Inspect the active writer or wait through normal scheduling, then refresh the target version before a justified resubmission. Do not remove the lock or spin on identical writes.

## Batch commits and recovery references

A patch is privately projected and checked as a whole before its first formal
write. This does not make a multi-file commit an atomic filesystem transaction.
For FILE_MUTATION_FAILED, FILE_CHANGED_AFTER_COMMIT, or a partial/ambiguous
result, inspect each file result, current bytes and retained trash references.
Preserve completed effects; do not replay the whole patch or overwrite current
files to simulate rollback. A recovery reference with unknown recovery state
must be inspected before claiming that restoration is available.

For PATCH_UNSUPPORTED, the bounded text interface cannot represent the action
(binary/symlink/mode changes are not text candidates). Do not repackage it as
shell execution to evade the file checks. PATCH_TIMEOUT is a private projection
failure before any formal commit; inspect and narrow the patch before retrying.

## Compatibility names and execution authority

FILE_SERVICE_REQUIRED means the native handler does not own formal commit
authority. Use the registered canonical or compatibility file-service tool
through the normal ToolPipeline. Do not expose canonical state to the sandbox
or retry the same handler through a shell. Compatibility names retain the same
checks, writer locks, scope and exact user-grant requirements as their canonical
operation; the alias does not expand the current capability profile.

A legacy append to an existing file needs the current expected_sha256 and
constructs a complete frozen replacement candidate. Refresh the file after a
version mismatch. UNSUPPORTED_ENCODING requires an explicit supported text
representation; this service does not silently convert arbitrary encodings.

## Frozen document candidates

FILE_CANDIDATE_STALE means the original frozen document bytes or their
owner/specification/baseline binding cannot be reused. Inspect the current target
and original receipt. Regenerate only intentionally, without the stale feedback
reference; never present regenerated bytes as the already inspected candidate.
Office/PDF libraries execute only in a private native workspace. Producer
launch, cleanup and access retirement are separate from formal commit effects.
Unconfirmed native lifecycle keeps the private workspace and recovery journal,
and prevents formal commit. Binary candidates cannot pass text-only mandatory
checks by using an empty text view. Exact user approval cannot make an unknown
mandatory check complete. If DOCUMENT_CANDIDATE_RETIRE_FAILED is reported,
the document is already committed; preserve it and inspect storage maintenance
rather than replaying generation or writing.


## Formal DAG promotion

promote_agent_changes reuses the complete candidate checks and cooperating
writer locks. A child review is not a waiver of formal-workspace lesson checks.
For LESSON_FEEDBACK_REQUIRED, inspect the returned group diagnostics, then
resubmit the same process_ids with lesson_feedback_id only after the feedback
has entered a provider request, or revise the affected child. Adding another
DAG output changes the group binding. Unknown mandatory binary/link checks
cannot be approved as passed. PROMOTION_CANDIDATE_UNAVAILABLE is a pre-effect
representation/budget failure; preserve the sealed child result.

PROMOTION_EFFECT_AMBIGUOUS retains the existing prepared promotion and actual
per-file observations. Do not replay blindly or delete current outputs to make
reconciliation pass. PROMOTION_METADATA_PENDING reports a verified formal
effect whose acknowledgement is pending: keep those outputs and reconcile the
exact original request. Existing-file recovery_ref identifies the retained Git baseline representation;
it is not a raw disk-byte backup or the file service's rename-trash reference.
New prepared revisions pin raw before/after digests as well as Git versions.
Legacy revisions report git_representation_legacy and cannot retroactively
claim that their original raw-byte versions were recorded.


Native producer execution approval is separate from a lesson exception on concrete file bytes. Approving an original script or custom program does not suppress later output checks. A violating output remains unsubmitted; revise the producer or use the existing explicit file-candidate path. Failed or unknown mandatory coverage still blocks submission.

Git and Gitgo metadata paths are reserved for registered project/state services. PROTECTED_PATH is a boundary rejection, not a request to try another writer or a shell. Ordinary business files keep the same candidate and lesson workflow.
