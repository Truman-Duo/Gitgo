# Coordination

## Inspect owned child facts

Inspect owned child state, contracts and artifacts through existing child tools or decision_evidence(children); stale conversation is not current child state. Waiting for an active child is different from approving its delivery.

## Review the outcome

The supervisor inspects the completed outcome and cites real child receipts in review_child_outcome. Send concrete feedback if revisions are needed. This supervisor review does not require another independent Reviewer unless the active policy separately requires one.

## Promote and resolve interfaces

Approved isolated changes requiring promotion use promote_agent_changes and its actual conflict/permission checks. Inspect the resulting worktree/receipts before completion. Resolve interface revisions through owned coordination events; do not invent event IDs or accept another task's evidence. Do not change user scope just to satisfy a gate.

## Artifact readiness

CHILD_ARTIFACT_NOT_READY means the selected execution has no completed artifact available; it is not a tool crash. For active work, use wait_agents and handle any owner-action interruption. For failed or cancelled work, inspect its actual outcome and decide whether an authorized continuation is appropriate. Do not repeatedly read an incomplete artifact or infer that an existing result file proves completion.

## Changed validation input (GITGO-E6110)

VALIDATION_INPUT_CHANGED means an explicitly pinned input no longer matches the result being promoted, or cannot be checked. Read the named input and inspect the affected child result. Revalidate or continue unpromoted work against the current input; an already promoted baseline may require a new task snapshot. Rereading alone does not certify the old output. Preserve user edits and earlier committed promotions; do not replay, overwrite inputs, or clear pins just to pass the gate.
