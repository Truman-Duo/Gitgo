# Review

## Read the verification requirement

The existing verification policy decides whether independent review is required. Self-review is sufficient where policy permits it; do not create a reviewer for every task.

## Obtain real independent review when required

If the current gate requires independent review, initiate request_review using its mounted schema, inspect the real reviewer result and address concrete findings. Saying that the work was reviewed is not review evidence.

## Distinguish review responsibilities

Keep independent Reviewer approval separate from a supervisor's review_child_outcome for B's delivery. After actual approval, recheck current completion evidence and submit the claim; do not weaken the policy or mark an unperformed review as passed.

## Keep approval bound to the reviewed version

Independent approval certifies the reviewed task/version, not all later work by that process. A changed target or contract, an unavailable version witness, or a historical approval with no binding requires a current review when the policy still requires independent review. Use request_review after the affected work is ready; do not copy an old Reviewer ID or repeatedly submit the same stale claim.
