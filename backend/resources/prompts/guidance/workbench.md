# Workbench recovery

Use the current tool schema and returned details. These diagnostics do not grant permissions or certify working notes as facts.

- **WORKBENCH_REVISION_CONFLICT / GITGO-E7601**: the candidate did not replace the sheet. Open the current sheet, compare it with the expected historical revision, reconcile the changes, and submit the intended complete notes with the newly observed expected_revision. Do not retry the same stale write or discard concurrent notes silently. Unreferenced candidate blobs may remain for normal storage maintenance; they are not committed revisions.
- **WORKBENCH_INVALID_INPUT / GITGO-E7602**: check required fields, bounded text/cell counts, unique cell IDs and exact references. List sheets in this session/process if the reference was lost. A sheet from another process/session is unavailable here; do not invent its reference or change owner identity. The tool never repairs invalid notebooks or grants authority from note metadata.
- **WORKBENCH_UNAVAILABLE / GITGO-E7603**: persistent sheets need the Runtime-bound project storage and installed nbformat dependencies. Do not bypass storage or install software without the normal authorization. Bounded arithmetic remains available. Continue using sufficient existing evidence/available tools, or explain a material limitation.

A new sheet or revision preserves working material, not an execution receipt or a checked answer. Carry exact references across compaction and inspect needed pages before relying on old notes. For a final numeric/set claim relying on a pinned result, use workbench.check_delivery on the intended public candidate and scope. Runtime retains that association and rechecks the actual delivered text and current source applicability. Correct a contradiction in the candidate; changing an internal claim or omitting an associated scope cannot repair the public answer. Do not narrate this internal procedure to the user.

For qualitative requirements summaries, inspect_delivery(candidate=draft) supplies exact current dialogue evidence beside the Agent's interpretations, proposals and unresolved choices. You compare meaning and correct the final response; the returned evidence is not a semantic pass. No sheet or auxiliary model is required. Preserve the original actor/action/conditions and do not turn an evidenced effect into an unstated later workflow. A request to stop discussion is not reopened by inspection.

Accepted values use literal source words/listed selections. Extra Agent paraphrases remain unverified interpretation proposals and are read only when needed; they are not current user-confirmed rules. To repair an already stored interpretation of the same receipt, use answer_updates with correct:true and the exact quote. Runtime supplies its existing source identity, keeps the old record and invalidates dependent evidence. revise:true instead requires a newer actual user change. Do not combine the two or ask the user to repeat unchanged evidence.

When confirmed_excerpt is returned, Runtime assembles that source section at delivery, including when the draft has no Markdown headings. It quotes real confirmed inputs and excludes delegated choices; it does not publish the Agent's paraphrase as user fact. Put defaults, inferences and proposals in other sections. Optional answer_updates binds newly received facts before preparing the excerpt. Do not spend another call copying its heading or quote syntax. Delivery rechecks actual text and source basis; it does not certify other prose.

Use scope_update={quote:"exact current request"} for a response built from recorded decision status. No result draft or mode selection is required. If the user requests comparison/advice, add discussion:"that discussion only" to this object; its exact body is version-bound and appended to status. Original arguments stay in Trace. A valid scope persists without resubmission. Do not duplicate status lists, add future rules or treat technical delegation as acceptance of behavior changes. Graph and source/scope versions are checked; unknowns outside recorded discussion are not certified as solved.

- **WORKBENCH_EXPRESSION_CANDIDATE_INVALID / GITGO-E7606**: supply a nonempty public draft within the stated 64000-character bound; the operation returns evidence without echoing the full draft.
- **WORKBENCH_EXPRESSION_SCOPE_UNAVAILABLE / GITGO-E7607**: use the current task/process's dialogue. Do not copy another owner's state or invent receipts.
- **WORKBENCH_EXPRESSION_SOURCES_CHANGED / GITGO-E7608**: no evidence view was issued; inspect the newly current sources. Do not reuse an old view as approval.
- **WORKBENCH_EXPRESSION_EXCERPT_CHANGED / GITGO-E7609**: copy the returned source excerpt unchanged in the actual confirmed section. Put additions in an advice/assumptions section; do not recheck only an internal draft.
- **WORKBENCH_EXPRESSION_EVIDENCE_STALE / GITGO-E7610**: current user facts changed after the excerpt was prepared. Inspect again after resolving current answer_updates; copying the old wording cannot refresh its evidence.
- **WORKBENCH_EXPRESSION_STATUS_TOO_LARGE / GITGO-E7611**: the complete recorded status exceeded the summary bound. No partial status was certified. Use the existing scoped workflow status reads; retain full sources and obligations. Do not truncate records, invent confirmation, remove requirements or repeat the user's answer to bypass the bound. Explain the material limit if this requested complete summary cannot be delivered within it.

- **WORKBENCH_SOURCE_UNAVAILABLE / GITGO-E7604**: inspect the exact source reference and its original producer. Resolve missing records or refresh the producer through its ordinary authorized tools. Do not read a filesystem path through the workbench as a bypass. A previously stored snapshot remains historical material.
- **WORKBENCH_INVALID_DATA / GITGO-E7605**: inspect the snapshot, JSON Pointer and explicit reducer/null policy. Inputs are bounded JSON with unique object keys, finite bounded numbers and bounded nesting. Numeric strings, booleans and structured objects are not silently numeric. Correct the real input or query; do not delete inconvenient rows to manufacture a passing total.
- **WORKBENCH_SOURCE_RECHECK / GITGO-W7601**: storage/computation may have succeeded. Preserve that committed revision. Determine whether the question is explicitly historical or needs current evidence. For the latter, refresh the original source, import a distinct source cell and compute a new result against the newly observed sheet revision; do not retry a successful append or assume an upstream change repaired a defect. A matching source hash alone does not validate its dependency graph, completeness or interpretation.

The exact aggregate applies only to the selected stored JSON array, after declared privacy filtering and null handling. Numeric output is exact for those recorded values; source extraction, units and narrative interpretation remain separate. A saved result of four does not authorize an answer claiming six. Use the shared final-answer check against the bound result.

- **WORKBENCH_MATERIAL_AUDIT_INCOMPLETE / GITGO-W7602**: the material observation exists durably; its audit append failed. Preserve signal_id and use the existing history/storage recovery path. Do not resubmit a changed selection, reset lifecycle or create another approval to disguise the audit failure.

Material submission selects a pinned revision and actual cell IDs. Submission is not knowledge confirmation. The existing task-end worker may summarize it into an unconfirmed proposal; use the normal user review/BTW flow. A material payload larger than the declared limit must be narrowed meaningfully, not truncated to hide contrary evidence. Notes without independent sources remain unverified even after being stored; source and qualification checks remain separate from user acceptance.
