# Workbench recovery

Use the current tool schema and returned details. These diagnostics do not grant permissions or certify working notes as facts.

- **WORKBENCH_REVISION_CONFLICT / GITGO-E7601**: the candidate did not replace the sheet. Open the current sheet, compare it with the expected historical revision, reconcile the changes, and submit the intended complete notes with the newly observed expected_revision. Do not retry the same stale write or discard concurrent notes silently. Unreferenced candidate blobs may remain for normal storage maintenance; they are not committed revisions.
- **WORKBENCH_INVALID_INPUT / GITGO-E7602**: check required fields, bounded text/cell counts, unique cell IDs and exact references. List sheets in this session/process if the reference was lost. A sheet from another process/session is unavailable here; do not invent its reference or change owner identity. The tool never repairs invalid notebooks or grants authority from note metadata.
- **WORKBENCH_UNAVAILABLE / GITGO-E7603**: persistent sheets need the Runtime-bound project storage and installed nbformat dependencies. Do not bypass storage or install software without the normal authorization. Bounded arithmetic remains available. Continue using sufficient existing evidence/available tools, or explain a material limitation.

A new sheet or revision preserves working material, not an execution receipt or a checked answer. Carry exact references across compaction and inspect needed pages before relying on old notes. Follow the existing shared final-answer check; do not narrate this internal procedure to the user.

- **WORKBENCH_SOURCE_UNAVAILABLE / GITGO-E7604**: inspect the exact source reference and its original producer. Resolve missing records or refresh the producer through its ordinary authorized tools. Do not read a filesystem path through the workbench as a bypass. A previously stored snapshot remains historical material.
- **WORKBENCH_INVALID_DATA / GITGO-E7605**: inspect the snapshot, JSON Pointer and explicit reducer/null policy. Inputs are bounded JSON with unique object keys, finite bounded numbers and bounded nesting. Numeric strings, booleans and structured objects are not silently numeric. Correct the real input or query; do not delete inconvenient rows to manufacture a passing total.
- **WORKBENCH_SOURCE_RECHECK / GITGO-W7601**: storage/computation may have succeeded. Preserve that committed revision. Determine whether the question is explicitly historical or needs current evidence. For the latter, refresh the original source, import a distinct source cell and compute a new result against the newly observed sheet revision; do not retry a successful append or assume an upstream change repaired a defect. A matching source hash alone does not validate its dependency graph, completeness or interpretation.

The exact aggregate applies only to the selected stored JSON array, after declared privacy filtering and null handling. Numeric output is exact for those recorded values; source extraction, units and narrative interpretation remain separate. A saved result of four does not authorize an answer claiming six. Use the shared final-answer check against the bound result.

- **WORKBENCH_MATERIAL_AUDIT_INCOMPLETE / GITGO-W7602**: the material observation exists durably; its audit append failed. Preserve signal_id and use the existing history/storage recovery path. Do not resubmit a changed selection, reset lifecycle or create another approval to disguise the audit failure.

Material submission selects a pinned revision and actual cell IDs. Submission is not knowledge confirmation. The existing task-end worker may summarize it into an unconfirmed proposal; use the normal user review/BTW flow. A material payload larger than the declared limit must be narrowed meaningfully, not truncated to hide contrary evidence. Notes without independent sources remain unverified even after being stored; source and qualification checks remain separate from user acceptance.
