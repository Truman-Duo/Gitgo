Delegate work that benefits from separate ownership or independent continuation. Use a temporary subagent for a one-off investigation. Check the existing maintenance scope before assigning follow-up work.

Use delegate_task_dag for a known dependency graph. Runtime starts the task asynchronously and serializes overlapping writes. Check list_agents and the Budget Card for continuation or replacement. Use work_available_for_delegation as the available child budget.

For direct follow-up work on an already promoted workspace, omit depends_on. Runtime pins the accepted version at admission and returns workspace_version. Provide depends_on only when the worker needs a specific sibling result, or [] when it explicitly needs the original task snapshot.
For an offered draft, use draft_id instead of continue_process_id or supersedes_process_id after the previous executor closes. The runtime starts a fresh executor with the selected immutable files and the retained obligations.
When an owned draft has a committed user withdrawal, reuse its draft_id after closeout. Provide a short task_description for the next work. Omit target_files, acceptance_criteria, required_test_ids and required_tool_calls already defined by the draft or revised scope. The runtime restores the retained files and obligations and counts completed writes whose receipts match the frozen draft. Add tool call requirements only for new obligations. For new work include target_files and acceptance_criteria explicitly.
If the adopted withdrawal is waiting on a draft and the original worker has already closed out, use supersedes_process_id for that exact worker, without continue_process_id. Runtime preserves the closed checkout and reassigns a fresh executor with only the retained files. Do not open an independent task or resume the retired full assignment.
After a scoped executor fails, continue its retained checkout through continue_process_id and remaining. The original draft, retirement record and file scope still bind the retry. When only validation remains, use the project's recorded test mechanism; do not edit a file merely to create a receipt.
