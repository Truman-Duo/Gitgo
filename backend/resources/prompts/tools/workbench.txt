Use this workbench when persistent scratch notes, related sheets, or bounded arithmetic help the actual task. Simple answers do not require it. Its schemas describe the mounted API; this task workbench is distinct from the prompt profile named Workbench.
calculate requires expression and runs bounded arithmetic/comparisons, never arbitrary Python. It does not require persistent sheets.
create_sheet requires title and optionally notes [{id,text}]. Notes are model working material, including hypotheses; saving them does not certify facts.
list_sheets recovers this session/process's sheets; after is a sheet-id cursor. open_sheet requires sheet_id and optionally a pinned revision, offset and limit. It returns notebook cells, the exact stored revision, its parent and any transition. Read all needed pages. Reopen after a conflict; reconcile rather than blindly replacing expected_revision.
revise_sheet requires sheet_id, expected_revision and the complete replacement notes list; optional title changes the title. Old revisions remain readable. Notes accept only id and text, with unique ids per sheet. No approval or verification metadata may be supplied.
continue_sheet requires title, source sheet_id, its pinned revision, explicit cell_ids (empty is allowed) and a transition reason; optionally add new notes with distinct ids. It creates a separate sheet with an immutable link to its origin, preserving that selected historical material's status. Independent sheets need no transition.
Before compaction or handoff retain the useful sheet_id and revision, decisions still needing evidence and the intended next step. After restoration list/open the relevant sheets instead of reconstructing lost notes. Main-session sheets survive replacement of the turn process and can be reopened in later user turns of that saved session. Child-process sheets remain private to that child; another session or child cannot adopt them through this tool. A current sheet version does not prove its assertions or underlying sources current. This tool does not execute notebook code, verify the final answer, or approve/save active lessons.

import_context requires sheet_id, expected_revision, a new cell_id and source_ref (an existing application/json context reference, latest or pinned). It captures bounded privacy-filtered JSON and records the actual pinned origin, stored-input digest and any matching reference dependencies. Use original producer records where available; a context record can itself contain model extraction or partial data. No path reading, network fetch or permission upgrade is hidden here.
aggregate requires sheet_id, expected_revision, a new cell_id, source_cell_id, selector and reducer. It calculates over an imported source or explicitly provided data cell, never note text. selector is a JSON Pointer (empty selects the root). count counts every array row including duplicates/nulls; key_count counts object members without classifying their meaning. Both disallow field. Other reducers take an array; optional field selects each row's value. sum/min/max require JSON numbers, never numeric strings or booleans; results are exact decimal strings for the recorded JSON values. distinct_count accepts typed scalars (numeric 1 equals 1.0; strings and booleans remain distinct). Missing fields and nulls default to rejection; null_policy=skip explicitly omits them and reports omitted/used counts. Empty sum is 0 with used_rows=0; min/max require values. Units are not inferred. Read coverage and omission counts before claiming a total.
check_sources requires sheet_id and optionally revision. open_sheet also reports source/result applicability from the current bound references and dependency graph. This is a read-only projection: old revisions/results do not change. A current version is not proof of external freshness, full coverage or semantic truth. Changed, missing or unbound upstream inputs require recheck; an old snapshot may still be calculated for an explicitly historical question. To update current evidence, refresh the original producer and import/recompute under new cell ids/revisions. Never turn a new sheet, computation success or a recheck warning into a repaired-defect claim. Results include the exact input revision/digest and query; the final-answer check still applies because copying a correct result incorrectly remains possible.

submit_material requires sheet_id, its pinned revision, 1..12 selected cell_ids, and purpose. Only the bound main user task may submit; project/task/owner identity is Runtime supplied. Select concrete potentially reusable findings with their evidence and limits, not identity/style preferences or evolving task requirements. This records unclassified working material for the existing task-end harvest; it does not declare knowledge, save an active lesson, confirm a candidate or grant a checker. The normal harvest may classify it elsewhere or produce no candidate. Any candidate uses the existing user-confirmation and BTW review flow. Repeated submission of the same revision/selection is idempotent and cannot reset a lease or confirmation. Larger selections are rejected, not silently truncated. Source/result identities are retained; notes alone have no independent validation. Children report findings through their normal handoff rather than submitting directly.

add_data requires sheet_id, expected_revision, a new cell_id, json_text and description. It stores bounded privacy-filtered JSON assembled by the model (including transcribed user input). Numeric text is parsed exactly; metadata is service supplied. This is explicitly provided data, not independently observed evidence. It can be calculated when that conditional scope answers the task; a source recheck warning does not require needless source hunting for a simple user-supplied dataset.
import_result requires sheet_id, expected_revision, a new cell_id and an existing tool-result:sha256 locator. It reads a bounded complete registered JSON result owned by this process via the canonical result service, verifies identity and retains recorded-output provenance. It cannot read arbitrary paths or another process's result. A retained result is historical execution output, not proof of current external state or a valid semantic conclusion. Use existing authorized source/document tools for other files or attachments; do not bypass them through this workbench.
