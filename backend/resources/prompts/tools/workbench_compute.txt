Run a one-shot computation in a disposable native workspace with the existing permission and resource limits. Use this tool when the task needs a Python transform or a code inventory. The result locator can be imported with workbench.import_result or passed directly as a named input in a later computation.

python requires code defining run(inputs), explicit inputs (possibly empty), and outputs. Each input has a unique name and either a pinned cell {sheet_id, revision, cell_id} or a registered JSON result locator. An optional JSON Pointer selector chooses a subvalue. Use basis=historical for a pinned old input when comparing snapshots. The code receives only those named JSON values. It returns a dictionary with exactly the declared output names. Output declarations can include units. JSON fractions are loaded as Decimal. Keep arithmetic in Decimal for decimal results and explicitly convert if an approximate binary float is intended. The record identifies which numeric representations were returned. Use the installed Python standard library for filtering, grouping, joining and comparing. State is discarded after each call. Use existing authorized tools for workspace access or business effects.

code_size requires a project-relative directory path, with "." for the project root. In a Git workspace it scans tracked ordinary files as they exist in the working tree. include_untracked also includes non-ignored untracked files. In a non-Git workspace it scans the declared directory. The optional exclude list contains exact project-relative file or directory prefixes. The result reports the effective scope, source hashes, per-file and per-language counts, and missing, changed or unprocessed paths. Use a narrower directory if the snapshot exceeds the result budget. Compare only scans with the same scope and options. Report code size separately from quality or complexity.
