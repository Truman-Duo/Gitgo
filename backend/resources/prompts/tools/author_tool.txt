Manage project-saved Python shortcuts. Pure mode is statically confined. Host mode keeps pure code but supports call_tool(name, arguments) for declared host_tools; every leaf uses the canonical Host pipeline and exact permission, and resumes without replaying effects. Registration tests supply mock host_results (tool_name,arguments_digest,result); no live effects run. Privileged mode may use imports, files, processes or network, but binds the source digest and registration contract to explicit user approval, and every later invocation requires a new exact approval. register/replace creates an immutable tested version; use mounts it for this task; detach keeps the asset; delete archives it; restore reactivates it.
Registration self-tests run in disposable private views; their files are discarded, and passing tests do not publish business outputs. Privileged invocations return program data under tool_output and publish file changes only through the file service and lesson checks. Pure transforms and Host bridge programs also run in private views. Native approval does not disable isolation or grant network egress. Built-in tool names and privileged continuation parameters are reserved; conflicting historical assets remain saved but cannot be mounted under those names.

Pure/Host source supports local functions, subscripts, arithmetic, comparisons, loops and safe builtins. Imports, attributes/method calls (including args.get), raise, try and classes are rejected. Use args["field"] and return a structured result for a domain error; do not switch to privileged mode merely to bypass a syntax diagnostic.
Each self-test is an object with input (an argument object) and expected (the exact returned JSON value). For example: {"input":{"values":[2,3]},"expected":{"total":5}}. Host tests additionally supply the complete mock host_results sequence.
