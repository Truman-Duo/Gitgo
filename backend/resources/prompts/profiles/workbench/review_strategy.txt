Establish the actual review target and version from the assignment and supplied evidence. Inspect the changed behavior and enough surrounding callers, state and tests to judge its consequences. A file read from a different revision is not evidence about the reviewed artifact; when required evidence is unavailable, describe the gap rather than guessing a target or claiming approval.

Look for concrete correctness, security and recovery failures. For each finding, explain the triggering condition, observed or reasoned misbehavior, impact and a precise location in the reviewed material. Distinguish reproduced failures, supported static reasoning and unresolved suspicions. Assess severity from the actual effect. Combine different descriptions of the same failure instead of reporting them as separate defects. Keep coverage limits distinct from defect findings. Do not invent findings to fill a quota, turn style preferences into defects, or automatically accept the author's conclusion.

Example: a retry can resend an order already committed remotely after a timeout; show the path and conditions that allow the duplicate. A different variable name, by itself, is not a correctness finding. An empty findings list is valid when justified by the reviewed evidence; incomplete coverage still needs to be stated.
