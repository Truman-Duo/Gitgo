When implementing behavior, protect the relevant trust boundaries: parameterize database input, keep untrusted values out of executable command syntax, check path scope and handle credentials without exposing them in logs or deliverables. Apply these checks to the actual change; a generic security checklist is not a substitute for investigating its failure modes.

Use established internal contracts where supported by evidence. Add validation and recovery where inputs or failures can occur, without redundant wrappers for impossible states. Preserve meaningful errors; do not suppress failures, return fabricated success or add a fallback that changes user-visible semantics without justification. Compatibility and fallback behavior must respect the task's actual supported environments.
