以下测试可用于检查 README 中的能力陈述。它们随上述全量回归执行；真实模型行为和正式界面使用各自的验收记录。

| 机制 | 测试入口 | 检查内容 |

| 问题与答案采用 | [问题轮次](../tests/test_alignment_rounds.py)、[回答复用](../tests/test_answer_review_cache.py) | 可回答前沿、改答失效、权限边界、失败通知、复用所需的原始解释与用户回执 |

| 状态与事件 | [运行事实](../tests/test_runtime_facts.py) | 过期写入拒绝、状态与事件原子回滚、消费者失败重放事实、取消与终态保护 |

这些测试验证特定契约与故障边界；总体质量、长任务可靠性和单位任务成本需要另做同模型对照。后台事件用于测量，事件数量本身不作为质量结论。

## 复测

后端和前端分别使用仓库现有测试入口：

```text
<gitgo-python> -B -m pytest tests -q
cd cli/dashboard
bun test
```

相关源码真实 API 测试入口：

```text
<gitgo-python> -B scripts/check_provider_failover.py --source --real --project <configured-test-project>
<gitgo-python> -B scripts/evaluate_alignment_behavior.py --project <configured-test-project> --cases all
```

真实 API 会计费。应先检查脚本参数、输出和项目选择，使用隔离数据和可写测试工作区，不直接拿私人项目内容作测试材料。部分其他评估脚本仍有固定测试项目约定，本轮没有修改这些代码，不能认为所有脚本都已通用化。

正式界面从 `run_dashboard_native.bat` 启动。可复用终端测试 BAT，但它们使用独立测试环境，不能作为正常安装历史连续性的证明。

人工检查：问候直接回答；模糊需求提出一题；答“个人离线 Markdown 阅读器，先给完整方案，其余自行决定，不要再问”后采用委托并交付；问题卡无重叠，已回答可收起，正文/思考区分；方案可滚动到底，拖选复制和单/多行粘贴正常。问题内容由模型生成，不要求固定问法。
