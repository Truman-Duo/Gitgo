# 配置

Gitgo 的用户级配置使用 `~/.gitgo/config.json`。Dashboard 保存设置与运行入口使用同一配置模型；项目身份和历史数据不因终端选择改变。

## General

首次启动在 Terminal 行选择检测到的可用终端：左右切换、Enter 保存、R 重新检测。初次保存可以转到所选终端；日后在 `/config → General` 修改时保留当前窗口，下次启动采用新选择。

发现或验证失败会提示原因。不要通过手填未经验证的 Bash 路径绕过检查。旧配置兼容保留 `auto/current/windows_terminal/custom`；可选项取决于当前系统发现结果。

Verbose 控制思考、工具等内容的默认展开程度，不改变任务或历史事实。

Diff Layout 选择 `Split`（默认，左右对照）或 `Unified`（逐行增删）。保存后立即更新当前对话中的 diff，重启后保留；窄屏下 Split 自动回退为 Unified。普通模式使用同一个 diff 框展示有界预览，省略内容会明示。

## 绑键

`/config → 绑键`（或 `/config keybindings`）读取当前生效的动作、键位和适用条件。Tab、方向键和 Enter 的作用取决于场景与焦点。

- 选中动作并确认，按下新组合键；页面显示终端实际收到的键，再按原始 Enter 保存，原始 Esc 取消。粘贴不会被当成绑键。
- 键盘输入检测仅保留内部诊断能力，常规配置页不再提供测试入口。终端未发送或已折叠的按键信息不能由运行时还原。
- 保存前检查同一场景的冲突；不同时生效的场景操作可复用键位。为避免影响普通打字，通用动作不允许绑定到无 Ctrl、Alt 或 Super 的普通字符。
- 删除键恢复所选动作默认值；“恢复全部默认绑键”重置全部覆盖。列表中的键位及提示随当前绑定更新。

保存成功后立即生效，重启保留；失败继续使用原绑定。旧方案配置可读取并迁移，但不再提供额外预设选择。本页不切换运行模式。

终端、系统或终端自身的快捷键可能拦截输入。更换 JavaScript 运行时不能恢复未送达的按键信息，应在实际终端中验证绑定。

任务对话默认使用 `Shift+Tab` 切换 Auto/Manual；表单中的 `Shift+Tab` 仍为上一字段，BTW 的上一区域使用 `Alt+M`。命令候选使用方向键和 Enter，不再用 Tab 轮换；子进程对话不再用 Shift+Tab 切换输入焦点。这些动作可以分别换绑，`/help` 与配置页读取同一份生效设置。

状态栏左起第二格显示橙色 `AUTO` 或灰白色 `MANUAL`，不使用底板色块；输入框配色不随推进模式改变。标识在后端确认切换后更新；失败显示原因。同一会话续接及其绑定的子进程共享推进模式，其他独立任务保持原模式。

Manual 在下一次产生变更的工具调用前等待推进确认，普通读取继续进行。切换不会取消正在生成的模型响应或重复已开始的调用。切回 Auto 可以继续等待推进确认的工作；真实权限确认和方向问题仍由用户决定，工具权限与沙箱限制继续生效。

子进程继续使用原工作树和沙箱生命周期，等待上一轮清理后恢复。进程重启、原生清理证据不足或提交结果不明时，仍按现有恢复限制处理；切为 Auto 不会自动重放这些工作。

`/runtime → 任务机制` 可查看当前任务的计划、增量需求、关联工作与维护状态。进入详情后可暂停、恢复或卸载机制；操作按当前任务及版本提交，卸载不能删除未完成义务。自然语言修订继续在主对话中提出，执行仍受既有授权和沙箱限制。

BTW 默认只读；选择纳入主任务后，先显示待处理要求，主任务需要同步范围、计划与验收条件才算采用。重复采用同一讨论不会重复添加，目标任务或版本变化会要求重新核对。

## Providers

创建项目、服务商新增／编辑、知识导出等多字段表单统一使用：方向键或 Tab 选择字段，Enter 进入修改，闪烁标记表示正在编辑；再按 Enter 暂存当前字段，最后按 Ctrl+S 提交整张表单。修改时 Esc 撤销当前字段，退出修改后 Esc 取消表单。提交失败会显示原因并保留输入；提交期间不重复发送。`/config keybindings` 可换绑“保存表单”，界面提示随实际绑定更新。

创建项目时，“接入已有目录”要求目录存在，“创建新目录”要求路径不存在或目录为空。归档项目仍保留名称和目录登记，冲突时从 `/bin` 恢复或选用其他名称／目录。新项目使用当前配置的模型服务商。

在 `/config → Providers` 输入 `/new`，先选择服务商模板或自定义连接，再填写名称、API 地址、密钥和协议。模板列表只显示名称，不展示网址或序号计数。进入填写页立即拉取模型；未填密钥时读取与地址匹配的公开参考型号，填入密钥后核对实际账号列表。自定义连接需要先填写地址，获取失败仍可手填。

Enter 暂存当前字段；Ctrl+S 提交整份 API 连接。名称、API 地址或所需密钥缺项时，暂存当前字段并定位到缺项。连接已填好但尚无模型时，Ctrl+S 直接进入模型候选页，自动获取并显示等待、成功、空列表或失败状态；成功后勾选型号，获取失败可在同页手填。Ctrl+S 合入本次选择后，再保存整份 API；不会自动把全部候选写入配置。模型选择不要求先保存连接或先填写名称：地址和协议用于获取候选，密钥字段确认后用于核对账号列表；即使获取失败或连接信息尚未填完，也可以先手填型号。

后台列表读取使用已暂存的连接信息；进入地址、密钥或协议编辑时取消旧预览，确认字段后按新连接重新核对。无密钥且公开参考不可用时显示待填写提示，不匿名请求账号模型接口。列表失败只在模型区域显示原因，不表示字段暂存或配置保存失败，也不阻止手填。OpenAI 的请求基址为 `https://api.openai.com/v1`；`https://platform.openai.com` 是平台网站，不能用作请求基址。

页面只显示一份竖排模型集合，不在配置页选择运行模型或显示默认标记。“添加模型”打开可搜索的批量选择页，Enter 勾选多个候选，Ctrl+S 保存本次选择并合入草稿；Esc 取消本次选择。手动型号在候选页内直接填写，支持每行一个型号和多行粘贴；Enter 暂存字段，Ctrl+S 校验、去重并加入草稿，返回主配置页后再保存整份连接。取消添加不改变原集合。选中已有型号按 Enter 不跳页，只有“高级”入口打开 JSON；按 Del 从草稿移除；实际按键以绑键设置为准。

选中模型行或添加入口按 `Ctrl+R` 重新读取候选并检查连接，刷新键可以换绑。刷新不会把全部候选写进配置，也不会因本次列表缺失就删除已有模型。各模型参数独立保存，新增时自动填写参数默认值；服务资料缺失时使用 Gitgo 回退值，公开参考资料不代表实际部署能力。

“高级 · 配置 JSON”进入独立的完整 JSON 编辑页，复用现有 Dracula 语法高亮，不显示位置计数，保存进度与错误按实际状态显示；包含 API 的可配置属性和 `models` 数组。上下文上限、输出预算、思考强度和请求参数都在这里修改。Enter 换行，Ctrl+S 校验并一次保存整份 API，成功保存只返回上一层 API 配置页；失败保留原文，Esc 取消本次 JSON 修改并回到原草稿。正文支持鼠标滚轮有界浏览，键盘移动后光标重新进入可见范围。已有参数不会因打开编辑器或刷新列表而重置。密钥由专门字段管理，不导出到 JSON。

每个模型的 `request_preferences.reasoning_effort` 留空表示服务默认；`request_preferences.body` 默认 `{}`，可按服务支持填写，例如 `{"temperature":0.2,"top_p":0.9}`。上下文上限使用该模型的 `context_window`，输出预算使用 `max_output_tokens`。body 不能覆盖模型、消息、工具、流式开关和输出预算等由 Gitgo 管理的字段。

配置说明通过 `/help` 查看，表单不另设帮助字段。只有字段文本编辑、命令和搜索需要底部文本框；全页 JSON 编辑直接在正文输入，不再同时显示第二个底部输入框。

连接检查自动在后台逐个进行，不需要选中模型后按 Enter；状态点分别表示灰色未知、橙色检查中、绿色收到模型响应、红色失败。只检查已加入配置的模型，同一编辑器内每个稳定的连接／模型／参数组合只自动尝试一次，不对整份服务商目录循环发起付费请求。修改身份或显式刷新可重新检查；保存可取消未完成的检查并继续，连接成功不代表工具或流式能力全部验证通过。

`/model`、`/effort` 仅在项目列表和具体项目主对话提供，并出现在命令推荐和帮助里。两者均在命令推荐所在的底部区域展开，保留上方正文。`/model` 用有界可搜索列表显示当前 API 已保存的模型；新建连接静默采用第一个，已有选择在其仍存在时保留。`/effort` 显示加宽刻度，只有三角着色，不增加“服务默认”选项。初始选中已有设置或服务声明的默认档位；均缺失时优先 high，其次 medium，最后首个可用档位，只在可用档位中选择。左右调整、Enter 持久保存该模型设置，Esc 取消且不写入。运行中的请求保持原参数，运行客户端从下一次模型请求读取新强度，不停止 daemon；重启后仍使用保存值。`/model` 切换仍要求任务空闲，不能通过中断 LLM 强行切换模型。

模型选择、思考强度、中断确认和会话撤回均展开在文本框下边线与原场景状态栏之间，不遮住或替换两者。模型选择沿用命令推荐的文字选择布局，使用灰白选中色，不显示协议或序号计数；思考强度首尾档位贴边，内部档位随数量均匀分布。撤回只有显式确认才提交，具体影响通过对应 `/help` 查看。

这些模块、Provider 配置和 Publish 的使用步骤及按键说明通过各自的 `/help` 查看，正文不重复显示常驻操作教程。帮助保留原页面草稿、选择及滚动位置；退出字段编辑后调用，文本或 JSON 编辑中的 `/help` 是普通内容。读取、保存、失败、过期及结果待核对等实际状态仍在原页面显示。

创建、导出、用量、更新及运行信息等菜单也通过局部 `/help` 查看操作说明。带页签的菜单使用左右切换、Enter 进入内容、Esc 逐级返回；方向键和 Tab 不从页签直接进入正文。普通命令推荐使用与命令框边线同色的绿色文字和低亮蒙版底，模型切换列表保留灰白选择。

模型服务商页选中 API 后按 Enter 切换主连接；等待回执时显示进度，成功后显示临时确认。重复按键不会重复提交；选择已经生效的 API 不重写配置或重启运行时。切换其他 API 仍需等待任务处于空闲边界。

新建远端 API 时，Esc 按实际层级返回：撤销当前字段 → API 配置 → 选择 Provider → 模型服务商页 → 配置页头。重新选择同一服务商保留草稿；从配置内部打开的服务商选择、模型选择、帮助和 JSON 返回配置页。已有 API 直接编辑、以及本地 API 的直接入口，返回实际调用者。

凭据单独保存；Windows 使用当前用户 DPAPI 加密，不写入项目文件。密钥在表单与输入框中脱敏显示。更换服务地址后需要显式填写密钥，避免把原连接凭据自动转发到新地址。

支持 OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages 风格协议。模型原生搜索、独立 Provider 搜索和外部检索是不同能力，取决于配置和实际服务支持。

主 Provider 与备用设置分别保存。开启自动 failover 并设置备用顺序后，失败请求才允许转到所选节点。自动路由不改写配置主模型。每个主 API 单独配置最多两个有序备用，在 API 行下按顺序缩进展示连接名，不重复标注“备用 1/2”；顶部总开关独立控制是否自动切换。关闭后备用项变灰，仍可选择和编辑。详见 [备用切换](provider-routing.md)。

本地端点有部分接口和兼容服务测试，但实际本地模型验收延期，不能按正式支持承诺。

## 项目与数据

项目配置包含工作区、提交格式及发布偏好，不应保存凭据。不同终端使用相同项目身份和状态根目录时共享历史。显式指定 `GITGO_STATE_HOME` 会产生独立数据环境，测试隔离环境不能冒充正常安装历史。

修改运行中的 Provider 配置可能被拒绝，应等待任务结束或明确取消。终端选择仅影响下次启动，不应为切换终端同时启动另一个写入同一数据环境的窗口。
