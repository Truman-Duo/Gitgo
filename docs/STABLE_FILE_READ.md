# 文件读取能力与限制

更新日期：2026-10-18。范围：原生 `read_file` / `file_read`；不覆盖任意文件操作。

## 支持的读取

读取通过既有原生 runner，在已授权资源根内获取文件对象。
类型、对象身份、实际读取和内容 SHA-256 使用同一打开对象，避免仅检查路径后再按名称读取。
需要显式审批的读取还受[审批文件对象绑定](APPROVED_FILE_READ.md)约束。

只支持已存在、单硬链接的普通文件。创建、写入、删除不属于此读取合同。
路径逃逸、链接/重解析、特殊文件或缺少必需系统能力时返回拒绝，不退回普通 Host 读取。
外部文件的逻辑 grant 不扩展 AppContainer 或 Linux namespace 的实际访问范围。

## 平台与大小边界

- Windows：支持普通本地驱动器路径；拒绝 UNC、设备命名空间、drive-relative、ADS、DOS 保留名称及尾部点/空格等别名。对象身份无法取得时拒绝。
- Linux：需要支持当前 ABI 的 `openat2` 和可用 procfs；拒绝链接、magic link、根内跨挂载访问和不支持的解析约束。
- macOS：生产原生沙箱未开放。

每次读取最多 16 MiB，并检查读取中的实际累计字节。协议输出限制仍可能更早拒绝，文件上限不扩大传输上限。
前后元数据变化会导致拒绝，不返回部分内容。

## 不提供的保证

对象绑定不冻结内容；同一文件可以被正常编辑。元数据检查是常见并发修改检测，不是事务快照。
它也不冻结完整挂载拓扑、ACL 或 Git 元数据，不使任意子进程获得只读文件系统。
硬磁盘配额、任务聚合容量和完整工具持久化准入不由此接口提供。

## 验证

对象测试覆盖正常读取、同名/父目录替换、链接和硬链接拒绝、大小/增长边界及失败释放。
源码 runner 与实际 frozen Host 的原生用例另行覆盖正向读取和越界拒绝；平台 skip 不计成功。
当前候选的验证范围见[沙箱验证摘要](SANDBOX_ARCHITECTURE.md#验证版本与结果)，原生运行前提见[配置说明](NATIVE_SANDBOX.md)。
