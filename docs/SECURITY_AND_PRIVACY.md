# 安全与隐私

## 凭据与数据

Windows Provider 凭据使用当前用户 DPAPI 加密存储。不要把密钥写入项目配置、源码、公开日志或文档。项目历史、数据库、Trace 和用户工作区内容保持本地，公开问题只提供脱敏复现信息。

## 权限与执行

用户的语义委托不等于高权限授权。组合和发明工具不能通过外层名称获取额外权限，叶操作仍需原有范围与审批。暂停后恢复不能重复执行已完成副作用。

审批、路径检查与普通子进程不能代替 OS 隔离。当前原生后端的能力、未启用范围和已验证版本见[沙箱摘要](SANDBOX_ARCHITECTURE.md)；不能把某个入口的验收推断为完整开发沙箱已经可用。安全停止或接受明确不完整结果也不能把失败测试、缺失回执写成成功。

## 发布检查的实际范围

当前已有忽略规则、文件/内容扫描以及产品同步和推送路径的检查。它们能拦截部分凭据和私有指令，但不构成完整隐私证明：公开文档对私有资料的引用尚未全面覆盖，不同检查入口覆盖范围也不同。

发布前必须检查实际候选内容及引用。批准一个文件公开，不表示批准它引用的私人资料。不能仅凭忽略规则或一次扫描通过宣布安全；普通外部 Git 命令也不会自动经过产品门禁。

本版不包含完整自动文档维护。相关限制见 [已知限制](KNOWN_ISSUES.md)。

Gitgo 自有状态应放在用户级状态目录、项目 `.gitgo/` 或 Git 管理区。卸载与项目删除是不同操作：卸载器不得遍历或删除用户项目。

## 原生工具隔离

Shell 与可执行自定义工具的 OS 边界、显式配置、平台差异及安全验收见 [原生沙箱](NATIVE_SANDBOX.md)。
## 恢复和卸载

数据库恢复应保留副本、相关伴生文件及证据，不能清空数据伪装成功。卸载不应遍历删除用户项目、worktree 或历史。

安全问题使用 [私有报告说明](../SECURITY.md)，不要在公开 Issue 附原始凭据或项目内容。
