# 安全与隐私

## 三层发布边界

Gitgo 的发布保护不是 `.gitignore` 的替代品，而是叠加的三层边界：

1. **版本控制边界**：默认忽略密钥、数据库、WAL/SHM、Trace、私有说明、构建产物和本地归档。
2. **内容级隐私扫描**：发布前按内容识别凭据、隐私片段与禁止上传的 Agent 文件，避免改名后绕过文件名规则。
3. **出站策略**：所有 commit/push/publish 路径使用统一策略，记录排除规则、例外指纹和扫描结果。

任何一层通过都不代表可以跳过其他层。发现不确定内容时应默认阻止发布并要求用户确认。

## 凭据

- Provider 密钥不写入源码、项目配置、SQLite、Trace、测试快照或文档。
- Windows 使用当前用户 DPAPI 加密 secret store；密文不能作为跨账号可移植备份。
- 日志和错误只允许显示凭据引用或脱敏摘要，不得回显完整值。

## SQLite 与写入安全

- SQLite 文件、`-wal`、`-shm` 和迁移备份全部保持本地，不进入 Git。
- 运行时拒绝已知不安全的 SQLite WAL-reset 版本。
- 高频流式 token、动画帧和原始协议包不得逐条同步落盘。
- 写入采用批处理、事务、保留上限和可观测写入预算，避免静默写入放大。
- 数据库损坏恢复必须保留可审计备份；不得用空状态伪装读取失败。

## 项目与卸载

Gitgo 自有状态应放在用户级状态目录、项目 `.gitgo/` 或 Git 管理区。卸载与项目删除是不同操作：卸载器不得遍历或删除用户项目。
