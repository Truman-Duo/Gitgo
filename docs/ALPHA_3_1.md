# Alpha 3.1

产品版本为 `1.0.0-alpha.3.1`，Windows 文件版本为 `1.0.0.5`。本期在 Alpha 3 上整合任务机制维护、Publish、Provider 配置、运行时输入与终端标准件修复。发行包的提交、源码树、平台结果和文件摘要以 [Release](https://github.com/Truman-Duo/Gitgo/releases/tag/v1.0.0-alpha.3.1) 附带的验证摘要为准；源码回归、冻结包检查和人工终端观察分别记录。

## 使用变化

- `/config providers` 管理 API 连接；每个连接可配置多个模型，并关联最多两个备用连接。进入表单后自动获取候选，支持多选及批量手填；Ctrl+S 保存。高级入口提供可编辑的配置 JSON，包含请求参数、上下文上限、输出预算和思考强度。
- 项目列表和项目主对话中的 `/model` 只列当前 API 的已配置模型；`/effort` 调整当前模型的强度并持久保存。两者使用输入框与状态栏之间的局部选择区。强度变更从下一次模型请求生效，已经发出的请求保留其参数。
- Shift+Tab 切换 AUTO/MANUAL，状态显示在底栏；工具授权仍经过同一权限与沙箱边界。BTW 默认只读，采用侧讨论中的需求须明确更新主任务范围和验证要求。
- `/publish` 集中处理工作区记录整理、正式提交、协作 PR、版本发布和配置；图中的选择连接相应操作。具体权限和操作条件来自现有 Git 与协作服务。
- 表单、枚举、选择、局部帮助、滚动和反馈沿用共享终端组件；创建及多字段配置使用 Ctrl+S 提交，Esc 逐级返回。开发测试 BAT 不进入公开源码或发行资产。

## 更新与恢复

Alpha 3 的既有固定更新器不能直接完成这次升级；请保留旧安装和数据备份，按[安装说明](INSTALL.md)建立独立的 Alpha 3.1 管理安装，不覆盖 `active` 或复制单个 EXE。沿用已有发布者公钥，私钥不随源码、包或 CI 上传。

Alpha 3.1 的更新通路包含升级器能力交接、业务数据兼容及迁移、完整包校验和事务恢复，不以“代码只允许小改”为升级前提。后续候选须按其真实数据与程序差异提供兼容声明和必要迁移；未知格式或缺失逆向迁移时明确拒绝，不能覆盖旧数据蒙混通过。程序回滚保留用户当前数据，不能用旧快照替换后续工作。

双包升级/回滚测试验证已有事务能力，不冒充尚未发布的 Alpha 3.2 实际升级结果。Alpha 3.2 发布时还须验证真实的 3.1→3.2 和 3.2→3.1 链路。预览与稳定渠道分开；预览清单最多七天有效，续签须递增序号，版本与包摘要保持一致。

## 平台和验证边界

原生发行目标为 Windows x64、macOS 26 ARM64、Linux x86_64 和 Linux aarch64。每个目标须单独构建并在原生 worker 验证，不能以 Windows 结果代替其他系统结果。

macOS 的安全文件读取依赖内核 beneath/no-symlink 能力；它不等于通用工具执行沙箱。macOS 通用执行沙箱及受保护 Git 后端仍缺失，相关操作明确拒绝；不回退为无隔离运行。macOS 新版管理启动器（API 13）在 Gitgo 正常退出后交给可更新的升级引擎执行替换，再用原命令打开。启动器仅代为执行固定类型的受限健康探针，不提供任意命令入口。旧启动器（API 6、9、11）仍须重启 Mac；早期 API 12 的升级引擎固定在初装版本，切换到 API 13 须先手动安装一次完整发行包。Windows 和 Linux 的隔离仍各有操作员前提，详见[原生沙箱](NATIVE_SANDBOX.md)。

任务机制已接入动态维护与权限生命周期，但开发/回归题通过不证明任意任务的语义判断正确。独立人工标注保留集尚未提供，独立语义评估未完成；已有真实 API 记录仍按开发与回归证据处理。缓存问题的证据目前来自特定机制热插拔与审阅链路，不能据此推断全系统均低于目标，也不能把局部暖缓存结果当成全系统达标。
