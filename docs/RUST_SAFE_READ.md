# Rust 安全读取：阶段二开发说明

本分支依赖阶段一最新修复 `5881283f0a22cc751bfb3313ee037907fe5cf12e`。已接入业务读取、审批及 Publish 包读取；跨平台源码、真实隔离子进程与最终包按同一候选提交分别验收，结果在 PR 中记录。不修改授权决定、审批记录或持久化恢复权威。

## 已实现的候选接口

保留阶段一 C ABI 1，增加 `safe_read_version=2` 能力声明和读取扩展。适配器必须先核对扩展版本，不接受没有扩展的旧模块，也不回退到原有读取器。

- `read_root`：获取宿主选定的具体绝对目录对象。
- `read_open`：相对于已有目录对象获取元数据 pin 或可读文件对象，返回文件身份与进程内资源 token。
- `read_size`：获取已经持有的可读对象的有界大小，仅作为内存分配提示，内容读取仍重新验证。
- `read_hash`：在同一文件对象上计算最多 512 MiB 的流式 SHA-256，不输出原始内容。
- `read_close`：退休 token，阻止新操作。已进入调用的操作保留自己的共享所有权直到结束；此响应不是进程树清理或底层关闭故障的验收凭据。
- `gitgo_native_read`：独立的有界二进制内容接口，最多 16 MiB；先检查输出容量，读取后检查对象状态，成功前不复制内容到调用者缓冲区。元数据 pin 不具备这个读取能力。单独的 `gitgo_native_package_read` 支持既有 272 MiB 包预算，不放宽普通读取接口。

资源表最多持有 8192 个活动条目，token 单调递增且不复用，退休 token 无法关闭后来打开的对象。目录与文件拥有各自生命周期，文件保留所需的目录和元数据描述符。独立文件对象有独立读取位置；单个对象的操作通过互斥锁串行执行。

Unix 路径按原始文件系统字节传输，Windows 路径按 UTF-16LE 传输；两者都独立校验路径边界与大小。资源 token 不写入审批、数据库或子进程请求；它不是访问授权。

## 三个平台的实现

| 平台 | 候选机制 | 需要的真实验证 |
| --- | --- | --- |
| Linux x86_64 / aarch64 | `openat2` 全路径约束；元数据对象检查后经保留描述符获取可读对象；禁止链接及文件系统穿越 | 内核实际执行、挂载/替换竞态及最终包 |
| Windows | 非特权 NT 目录相对打开；保留目录句柄、不共享删除；拒绝 reparse 与多重硬链接；检查 128 位文件身份及修改/变更时间 | Windows 实际执行、句柄生命周期及最终包 |
| macOS 26 | beneath/no-symlink/O_UNIQUE；实际正反逃逸探针；元数据与可读描述符身份核对；仅处理既有固定系统别名 | 本机已做核心测试；仍需集成、故障及最终包验收 |

读取前后核对文件身份、类型、链接数、大小和修改/变更时间。这里没有承诺任意并发写入条件下的原子内容快照。缺少必需内核能力时拒绝，不添加普通路径 `open` 后备方案。macOS 通用执行与受保护 Git 仍属于后续阶段。

机制依据：[Linux openat2](https://man7.org/linux/man-pages/man2/openat2.2.html)、[Apple XNU fcntl 定义](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/fcntl.h)、[Microsoft NtCreateFile](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile)。

## 集成与剩余验收

`ReadRoot`、审批元数据 pin、普通读取、哈希和 Linux Git 配置捕获均使用 Rust。既有审批过期、撤销和准入记录不变；Native token 不穿过授权协议。Windows DLL 加载前的最小可信 bootstrap 继续使用独立 WindowsReadApi，避免循环加载依赖。三个平台的实际原生实现身份均进入原有执行合同摘要。

Windows 受限子进程不能自行打开盘符根目录。可信启动器在创建任何子进程之前，固定已注册运行时中的模块文件及全部祖先目录，验证模块 SHA-256/大小与 Host 实现一致，并将这些资源保留在原有 Native Job 所有者内；只有观察到整树退出后才释放。子进程只继承最多16个 `READ_ATTRIBUTES` 模块文件句柄，不能用它读取内容、修改文件、列举目录或更改 ACL。私有环境字段只传递受限内核句柄号码，不选择模块路径，也不构成授权；Host 覆盖外来同名字段并使用显式继承白名单。子进程依据真实 TokenIsAppContainer 分派，必须将固定安装路径打开的文件身份与继承对象核对后才能加载，加载后继续核对实际模块身份。没有匹配对象、预算超限、字节不一致或关闭结果不明时均拒绝。祖先目录句柄不传给子进程，不能借此扩大其系统访问范围。

继承预算明确限制为3个stdio、最多16个既有安装租约及最多16个模块元数据句柄。普通读取 token 不参与这个加载前协议。关闭错误不会在下一次调用中变成成功，未确认的 Job/模块保护保留在原有进程恢复边界。独立 Windows 真实测试验证元数据句柄不能 ReadFile；最终 ZIP 测试验证真实 AppContainer 的正常读取、拒绝及审批。

Publish 的读取使用独立包内容接口。新文件写入继续使用不提供内容读取的 `WriteRoot`，保持原有“只新建、不覆盖”的语义；执行/写入机制不因本次读取迁移而扩大权限。未知关闭结果保留对象记录、封闭加载实例并拒绝重放，不将其描述成已完成底层清理。

原 Python `os.open` 故障注入已迁至 Rust 实际调用区间：同长度且元数据明确改变、读取中增长、Darwin 忽略 beneath 以及元数据 pin/可读打开间替换均有原生测试。同长度写入不保证在每个平台立即产生不同的时间戳，测试显式改变修改时间以验证约定的元数据检查，不能据此宣称检测任意并发内容变化。Python 集成测试仍检查大小提示后的增长、生命周期、授权撤销及不回退行为。

候选使用独立三平台测试流水线。最终发行包的 smoke 增加真实 frozen Host 中的 Rust 读取、哈希、元数据不可读、硬链接拒绝和替换拒绝。跨编译、模拟关闭异常、平台跳过和实际执行必须分开报告；真实 Windows/Linux 集成及最终包结果齐备后，才可判断第二阶段是否完成。macOS 通用执行与受保护 Git 的缺口不属于本阶段。
