# Linux 管理更新与回滚

关联 [Issue 21](https://github.com/Truman-Duo/Gitgo/issues/21)。支持 x86_64 和 aarch64 的新管理安装，API 6/schema 5；普通旧目录不接管。安装与操作见[管理安装](managed-installation.md)和[手动更新](update-preparation.md)。

## 行为

初始安装固定发行公钥和地址，缺少策略时不联网。确认退出后，必须证明拥有的进程范围完整清理、取得独占运行租约，再切换程序。其他实例仍运行时返回 busy，不杀无关进程。

坏候选恢复旧程序；显式回滚只恢复最近保留版本，不还原用户配置或数据库，不降低渠道防重放记录。启动器在启动当前程序前恢复未完成事务。失败处理见[更新恢复](update-transactions.md)。

## 验证摘要

[基线自动化 38728012455](https://github.com/Truman-Duo/Gitgo/actions/runs/38728012455) 在 Ubuntu 24.04 原生 x86_64/ARM64 runner 上，对 PR #32 的 `000d80f` 与目标 `0b7c2ab` 的合并候选完成源码、Dashboard 测试/构建、两份干净构建真实包及四项双版本验收：升级并回滚、坏 Dashboard 恢复、切换中断后冻结启动器恢复，以及编译 Dashboard 确认交接。基线证据不覆盖后续修复提交。

实际编译界面的隐藏 PTY 测试证明进程/输入链，不代替可见终端视觉验收。测试使用一次性签名、注入传输和隔离资料，不调用付费模型，也不发布安装包。

## 发布边界

维护者仍需配置真实签名发行源并验证其重定向、有效期和下载行为。私钥不能进入客户端、源码、聊天或日志。生产 CDN/企业代理、可见终端人工验收、物理掉电耐久性及所有发行版兼容性尚未由上述测试证明。后台自动更新保持关闭。
