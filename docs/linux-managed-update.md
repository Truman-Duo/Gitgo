## 复测发现与修复

最初 ARM64 环境误选了 x86_64 搜索二进制，现按原生架构选择官方固定摘要的 ARM64 ripgrep。新版 Python 会分块读取 PAX 扩展，原有单次读取上限不足以限制一个完整记录；现于标准库读取前检查 PAX/GNU 声明大小，并保留总元数据与展开上限。PAX、GNU 长名称和长链接三个超限案例均覆盖。

自动界面测试的固定半秒等待及直接删除 ANSI 的解析方式也造成超时；最终等待实际版本状态，并沿用已有终端屏幕解析器的有限滚屏记录。升级、回滚、数据保持与失败恢复断言均保留。此前失败运行不作为通过证据。

同一运行代码在 [Windows Actions 38670519313](https://github.com/hanyujason/Gitgo/actions/runs/38670519313) 通过 48 项原生专项、1772 项源码和 7 项实际包验收（488 项平台/工件条件跳过）；Dashboard 265 项通过。Windows 测试 head 为 `e2d216aaad25e8341e60578f51109a03e2a78bf1`，后续 Linux 改动仅涉及测试读取方式。macOS 同一运行代码源码回归为 2167 通过、93 跳过；本轮没有重新构建 macOS 包或重复人工重启验收。

## 发布前仍需确定

维护者需确定真实 HTTPS 更新清单、签名文件和安装包地址，以及稳定/预览渠道的发布安排。可评估使用现有 GitHub Releases，无须预设必须购买独立服务器；仍应核实实际重定向域名、有效期和下载行为。

客户端已实现 Ed25519 清单验签。维护者保管私钥并签署发布清单，初始安装只固定公钥和允许的地址；私钥不能进入源码、客户端、聊天或 CI 日志。缺少正式策略时不联网检查更新。测试成功不等于正式更新源已配置或安装包已发布。

Windows 可见终端人工验收暂缓，仍未计为通过；Linux 本轮也不声称完成可见终端人工验收、真实物理断电或所有发行版兼容性测试。正式发布、生产传输验收和维护者审查分别进行。
