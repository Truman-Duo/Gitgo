## P5-A.0：事件名归一化 — ⚠️ 首发

### 背景

审计发现 `--stream` 事件命名不一致，不应将三种命名风格写入 v1.0 协议：

| 操作 | 当前起始事件 | 当前结束事件 |
|------|-------------|-------------|
| `sync` | `"started"` | `"complete"` |
| `scan` | `"operation_started"` | `"complete"` |
| `push` | `"operation_started"` | `"complete"` |
| `daemon` | `"daemon_started"` | `"daemon_stopped"` |

### 归一化方案

统一为三事件模型：

| 事件 | 格式 |
|------|------|
| `operation_started` | `{"event": "operation_started", "op": "<op>", "project": "<name>"}` |
| `progress` | `{"event": "progress", "op": "<op>", "current": int, "total": int, "message": "<>"}` |
| `operation_complete` | `{"event": "operation_complete", "op": "<op>", "status": "success"\|"failed"}` |

daemon 保持其特殊生命周期事件（`daemon_started` / `daemon_stopped`），但内部的 `_run_once()` 操作仍使用上述三事件。

### 修改内容

**`cli/commands.py`：**
- `_cmd_sync` 流式输出：`"started"` → `"operation_started"`, `"complete"` → `"operation_complete"`
- `_cmd_scan` 流式输出：`"complete"` → `"operation_complete"`
- `_cmd_push` 流式输出：`"complete"` → `"operation_complete"`
- `_cmd_daemon` 单次模式：`"daemon_started"` / `"daemon_stopped"` 保持不变

**`backend/core/daemon/__init__.py`：**
- `_run_once()` 内部事件：`"operation_started"` / `"operation_complete"` 检查一致性

### P5-A.0 认证标准

- [x] sync/scan/push 流式输出全部使用 `operation_started` / `operation_complete`
- [x] daemon 事件不变（其生命周期模型不同）
- [x] 现有测试套件全绿

## P5-A：Protocol Specification — 低风险，依赖 P5-A.0

### 产出

**`docs/Gitgo_Protocol_v1.0.md`** — 六种 schema 的统一协议规范：

| Schema | 内容 | 数据来源 |
|--------|------|---------|
| State | `gitgo status --json` 输出 + `semantic` 子块字段 | `SyncSession.status_dict()` |
| Operation | 全部 16 个 CLI mode 的 `--json` 输入/输出 + 错误码 | `cli/commands.py` 各 `_cmd_*` |
| Stream | 3 种标准事件格式 + 支持流式的操作列表 | `_stream_progress()` + `_cmd_*` |
| Daemon | 8 种 command + 10 种 event + 生命周期 | `daemon/__init__.py` |
| Suggestion | 3 种 context + 2 种 response + 错误码 | 迁移自 `docs/AI_Protocol.md` |
| Governance | 4 种治理类型的输入/输出 schema | `governance/` 四个模块 |

### 协议头部

```markdown
# Gitgo Protocol v1.0

版本化策略：
- 主版本 v1.0。新增字段不 bump 版本（agent 忽略未知字段）。
- 删除/重命名字段 → v2.0，旧字段标注 @deprecated 保留一个版本。
- 每个 schema 有独立版本标签，共享主版本号。
```

## P5-D：State Bundle — 低风险，依赖 P5-A

### 目标

定义自包含的治理状态导出格式，可直接序列化为 JSON。新增 collector 函数一次收集，CLI 做薄调用。

### 实现

**`backend/core/governance/state_bundle.py`** — **新建**：

```python
def collect_state_bundle(project_name: str, minimal: bool = False) -> dict:
    """收集项目的完整治理状态快照。
    
    - minimal=True: 不含 history/suggestions，仅 status + governance summary
    """
    session = ...  # 创建或恢复 session
    bundle = {
        "gitgo_protocol_version": "1.0",
        "exported_at": datetime.now().isoformat(),
        "project": {...},
        "current_state": session.status_dict(semantic=True),
        "governance_summary": {
            "quality": compute_quality_metrics(load_suggestion_pairs(project_name)),
            "patterns": build_patterns_report(project_name),
        },
    }
    if not minimal:
        entries = HistoryManager.load()
        bundle["recent_history"] = [
            asdict(e) for e in entries if e.project_name == project_name
        ][-50:]
        bundle["recent_suggestions"] = [
            asdict(e) for e in entries
            if e.project_name == project_name and e.operation.startswith("suggest_")
        ][-20:]
    return bundle
```

### CLI

```bash
gitgo --mode export --export-type state-bundle --project X --json
gitgo --mode export --export-type state-bundle --project X --json --minimal
```
