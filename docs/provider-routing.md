# Provider 与备用切换

适用于当前源码候选。不同下载包的支持范围以版本说明为准。

## 配置

进入 `/config → 模型服务商` 直接显示全部 API 连接；不需要再打开概览详情。顶部“自动备用切换”是独立总开关，Enter 进入修改、左右选择、Enter 保存，Esc 取消当前修改。

每个 API 下缩进展示“备用 1”“备用 2”。选中备用位按 Enter，再左右选择其他 API 或“未配置”，Enter 保存。两个备用按顺序尝试，不允许重复或指向自己。A、B 各自保存自己的备用，切换主 API 不复用其他主 API 的队列；不会递归使用备用的备用。

旧版全局队列只归属迁移时的主 API，前两个有效备用继续使用，完整原顺序保留在迁移记录中。读取不重写原配置；后续正常保存会持久化新结构。开关关闭时队列仍保留。

API 根行 Enter 切换当前 API，`/new` 新建连接，`/edit` 编辑所选连接。多字段 API 表单仍用 Ctrl+S 提交。保存备用关系时若任务正在运行或路由版本已变，明确拒绝并保留草稿，不能中断正在执行的请求。

## 运行行为

配置主模型保持不变，实际请求可以使用所选备用。每个 Provider 使用自己的配置和凭据，不能借用其他节点的搜索凭据。上下文、工具能力、预算和错误类别都可能影响是否允许切换。

已接收输出的流不保证透明重放。取消或上下文超限不应当作节点宕机。持续使用同一备用不会每轮重复提示切换；实际生效节点变更会通知。配置主模型与当前回答模型应区分显示。

路由状态属于当前项目运行服务，不是厂商健康保证。界面显示路由已启用、失败后暂时停用、正在检查恢复等真实状态；没有运行记录时不显示“尚未观察”后缀。

## 验证与限制

真实故障测试采用无效首节点和真实备用，覆盖失败转移、下一轮继续、身份与搜索绑定。完整结果见 [测试结果](VALIDATION.md)。实际本地模型验收延期，不把兼容 HTTP 服务当作实际模型通过。

切换失败请报告公开错误码和配置类型，不要粘贴密钥、完整请求或私人对话。
