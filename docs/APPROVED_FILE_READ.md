# 审批文件对象的存活期与原生交接

状态：2026-10-14，Issue #17 的现有文件读取阶段实现。限于显式声明 `read_existing_file` 的 `read_file` / `file_read` 原生 handler。不是统一 effective manifest、持久化准入或全沙箱安全验收完成声明。

## 授权与资源的分工

`ExecutionContract.file_action` 显式声明文件动作；Host 工具与原生 handler 的声明必须一致。不能根据业务 effect、工具名称或 `read_only` 猜测权限。现有 permission request、用户 decision 和 approval grant 仍是唯一授权链。

`AgentProcess._read_approval_pins` 仅保存这些记录依赖的短期 OS 资源。它不替代 grant、不写入 checkpoint、不从模型参数恢复，不启动高权限 broker。单个 process 最多保留 64 项，最长 30 分钟，任务结束、拒绝、取消和到期时撤销。普通工作区读取不因此增加新的用户确认。

审批卡展示实际文件资源和调用参数。对于已绑定读取，任务授权仅允许重复相同参数、相同文件对象的读取；不自动允许同工具下的另一文件或另一个行窗口。卡片明确说明内容可因正常编辑而改变。需要扩大范围时必须重新申请。

## 对象保护与实际读取

```text
Host 请求审批
  → 取得工作区、读取根和文件的 metadata-only 活跃句柄
  → 将对象身份、精确参数摘要、工具版本及期限绑定到原有请求
  → 用户选择，最多生成一个 grant
  → 既有前置检查与整组授权准入
  → 复核名字当前指向的对象，取得本次存活期引用，再消费 grant
  → Host 通过独立协议字段发送不可变 ReadPlan 的有界描述
  → 原生子进程按 OS 策略打开文件，核验已批准身份，再读取同一描述符
  → 子进程清理结束，本次引用释放；单次授权对应的审批资源也释放
```

Host 只申请元数据访问，不读取目标内容。Windows 文件 pin 不请求 `FILE_READ_DATA`；Linux 使用 `O_PATH`，不打开 procfs 转换得到可读描述符。目标必须是单硬链接普通文件；链接、重解析、特殊文件和不支持的根依然拒绝。

审批身份包括工作区目录、读取根目录及文件的 OS 身份。身份值本身不授予权限，活跃句柄负责避免对象删除后的 ID 重用混淆。Windows 元数据句柄可能允许文件重命名；因此不能依赖“禁止删除共享”推断所有名字都被冻结。准入前和子进程实际打开后都核对身份，名字换成别的普通文件时拒绝。Linux 目录/文件重命名也按相同规则处理。

原生子进程不接收 Host 的整数句柄，不继承额外文件描述符。`ReadPlan` 使用封闭版本/字段集合、字符串长度及整数范围检查，并由读取上下文消费。模型参数中的私有字段先由 ToolPipeline 清除，不能覆盖协议顶层计划。当前只读计划是局部合同，不包含网络、Git、写操作、安装身份、完整挂载身份或聚合资源配额。

仍由原生 OS 后端决定能否打开对象。外部路径 grant 和正确对象身份都不能让 AppContainer/namespace 读取原本禁止的 Host 文件，也不存在退回普通 Host 读取内容的分支。

## 取消、并发、过期和恢复

授权选择及扣减沿用现有 grant 锁；一个单次授权并发只有一个调用获准。OS 资源锁只负责引用和释放，不能独立授予调用权限。每个调用通过 `AdmissionResources` 在所有返回/异常路径释放本次资源。

同一任务授权的并发调用可以持有独立引用。拒绝/过期/取消立即禁止新的准入；已有引用仍保留 OS 对象，直到对应原生调用完成清理。runner 限制运行时间不超过授权剩余期限，并在监督循环检查撤销，先终止进程树再允许调用层释放引用。

Host 重启后不能恢复 OS 句柄；仅反序列化请求、File ID 或 grant 不能复活授权。恢复出来的已绑定请求和 grant 在缺少活跃 pin 时失效，需要新审批。实现不尝试把旧路径授权自动升级成对象授权。源码/frozen 实现和声明改变也使工具摘要失效。

授权消费仍只是进程内原子性。消费之后、日志/启动之前的故障窗口、跨 Host 准入事务，以及 Host 强杀后的完整子进程清理证明仍属于现有 StorageRuntime/Host envelope 后续工作。不能依据此次存活期管理宣称 B4/B6 完成。

## 正向与对抗验证

真实文件系统测试覆盖：元数据获取不读内容；正常修改同一文件；单次/任务授权；重复用户回复；同名文件替换；父目录与根替换；过期定时释放；拒绝、取消、终止；重启后旧请求失效；活跃引用延迟释放；并发一次性消费；篡改身份、期限、范围；封闭协议 schema；启动失败的释放。

原生 source runner 与实际 frozen Host 使用相同正向及替换用例，覆盖两个读取 handler。协议级单测不能代替真实 AppContainer/Linux 原生执行结果；每次交付在 PR 记录当前 head 对应的平台证据与 skip。

## 保留边界

- 内容可合法改变；前后元数据检查只检测常见并发修改，不提供事务快照。
- 文件/根对象相同不等于完整挂载拓扑、ACL 或 Git 元数据不可变。
- 目录枚举、搜索、写入、创建、删除、Git 关联对象及其他入口尚未全部迁移。
- macOS 生产后端仍不可用；能力审计成功不能替代生产隔离验收。
- 尚需统一权限计划和持久化准入，不把局部 `ReadPlan` 标记为完整 effective manifest。
