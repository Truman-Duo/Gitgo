# 进程路由与连续协作：#55 分阶段设计

接纳目标为 `Truman-Duo/Gitgo:feat/process-routing`。本系列起始基线为
`15e5a82a5510adaa658535d87f5b657e5c21e545`。本页说明候选设计与覆盖边界，
不表示整个 #55 已验收或已经发布。

## 事实源与第一阶段行为

分工仍由主模型决定，合同和权限仍由现有 Host 机制接纳；不新增调度器、
第二份预算账本或每次分工的模型审阅。

- `execution_mode` 的明确选择与 `routing_advice` 的建议分开。省略复杂度或
  工作流数表示没有提供事实；复杂度 `unknown`、工作流数 `null` 表示明确未知。
  `operation=revise` 继续保留省略字段，`append` 复用既有增量合同事务。
  明确委派不因“小任务”建议被改成自行执行。相互矛盾的明确选择返回纠正信息。
- `routing_compilation` 保留原字段并增加 `effective`，其值为
  `self_execute`、`delegate`、`continue_worker` 或 `undecided`。
  `either` 不会凭默认值授予执行权；自行执行仍需要既有能力租约。
- “先调查再委派”使用当前任务实际成功、已提交的业务工具收据。
  只读调查可以构成进展；声明合同和失败委派尝试不构成进展。
- 一个执行的 `status=completed` 仍可能在收尾。共同的 closeout 判定用于
  等待、结构化审阅、父任务交付与代码推广。只有可靠收尾的终态可以被消费。
  落盘失败不会伪造 `lifecycle_finalized=true`；依赖者得到失败而非无限等待。
- 终端共享 `closeout_state`，显示收尾中和收尾失败。进程列表按每次子执行展示，
  详情列出会话身份及同会话执行次数，主对话子进程栏保留尚未可靠收尾的执行。
- 项目摘要统计全部已记录的 A/B 执行历史，在线时用实时状态覆盖同一执行。
  与会话数量、只显示 B 的进程列表不是同一个统计量。在线/离线使用相同历史集合。
  历史读取损坏时不隐藏仍运行的工作，但以 `count_scope=live_executions` 和错误说明
  标记局部统计；项目列表中的近似活动数量带 `~`。
  项目统计每轮最多读取 16 MiB 不重复的、经过所有权和内容摘要验证的对象；
  超限或校验失败明确退回局部实时统计，离线时保留带过期标记的缓存。
  冷启动的终态缺少收尾证据时按等待计数，不把旧的 completed 标签当作已完成收尾。

## 整批任务的接纳

DAG 应按“完整校验 → 准备全部节点 → 持久化整组关系 → 启动”处理。
校验复用单任务的实际准入逻辑，包括工具计数、能力、路径、预算和续办约束，
避免另一套预检遗漏规则。确定性错误在任何子执行启动前返回。

动态准备或启动仍可能失败。失败结果应区分没有启动与部分启动，列出实际启动的
节点；不把取消称为撤销外部效果。已开始执行的责任、收据及预算消耗必须保留。
尚未启动的节点释放未使用额度，已经公开的身份与历史不凭空抹去。
只要有节点实际启动，未启动节点的原验收义务也必须保留，不能用一部分成功成果
交付整批任务；只有整批完全未启动时，才撤销准备中的接纳并恢复被替代的旧合同。

## 续办与后续交接

会话表示持续身份，process/task 表示一次执行。旧收据不会直接冒充新执行的证明。
失败或取消后的续办必须保留尚未处置的旧验收义务；已经可靠完成并验收的历史工作
不应无限累加为新任务要求。对已产生外部效果却未完成的工作，必须先核对效果，
不能靠复制工具调用数量强迫重复执行。

当前的保守实现复用 `delegate_task` 的 `continue_process_id` / `supersedes_process_id`：

- 省略 `continuation_mode` 时，未完成或未验收的执行采用 `remaining`，合并直属上一
  合同的验收条件、测试、工具数量上下界、目标、依赖及冻结接口定义，并保留原任务描述。
  工具范围不能扩大，原树预算继续累计；旧收据不作为新执行的完成证明。
- 可靠完成、主进程已经结构化批准且写入成果已推广后，默认采用 `follow_up`。
  新任务不累加已验收的旧条件。`replace` 同样要求此前成果已被接受，当前不能用来
  撤销未完成责任。明确要求丢弃旧责任会返回可操作的错误。
- 省略父任务必需标志时继承原值，包括可选任务；不能把必需成果静默改成可选。
  已提交的外部效果或结果不明的效果须先核对，不能自动重放。
- 用户从 B 详情直接开启新任务也检查旧责任；未完成的工作转回原主进程的剩余工作
  准入路径，不通过新预算绕过旧义务。已验收的 B 保留直接后续对话能力。

例如 A 委派“查找问题并验证修复”，B 失败后新增“补充复现步骤”：剩余工作仍包括
原验收条件。若 B 已完成且 A 已批准，再问一个新问题，则不强迫重新执行旧验收。
若上一轮已经发出外部请求但结果不明，当前实现明确阻断自动续办，等待效果核对。

完整双向交接仍需在后续阶段形成一致公共契约，覆盖：

1. 指定剩余义务、原负责人、接收者与合同版本，而不是只有一条取消指令。
2. 原执行停止并可靠释放资源；核实在途或未知外部效果。
3. 已有代码成果、依赖输入版本和未发布工作树的接收条件。
4. 原义务的继承、已履行证明、明确替换或取消，以及共享预算的已消耗历史。
5. 以同一持久事务提交责任转换，并对重复请求、重启与版本冲突提供幂等恢复。

不能先将原合同标记可忽略，再假设新的负责人会自行记住它。取消清理和业务责任
转移必须分别确认。新增交接公共协议需按 #55 的协作要求协调；此阶段不以隐式
权限提升或自动重放未知效果来模拟交接已经完成。

下一阶段建议在现有主合同内区分稳定的业务责任、当前执行负责人和历史执行。
`superseded_by` 不应同时表示“换了一次执行”和“旧验收义务已核销”。候选交接输入
应绑定主合同版本、源责任、目标负责人、剩余义务、可复用成果版本、真实变更来源
和幂等键；已有字段由 Host 绑定，模型提交语义差量。这个候选设计尚未实现。

必须先验证的反例包括：同版本并发交接只有一次成功；旧执行恢复后不能重复领取
责任；已成功的外部发送不能因重启重放；已经验收后的可选追加不能抹掉旧成果；
准备、责任提交、启动和首个效果后的崩溃都能恢复唯一负责人及累计预算。
共享身份、义务核销和跨负责人权限/预算语义需要维护者协调后再实施。

## 验证和兼容

回归覆盖真实组件间的同步屏障、终态持久化故障、依赖失败、明确路由与缺省字段、
在线/离线摘要、终端列表/详情/主对话状态。单元及组件测试不替代真实模型行为对照，
也不替代正式彩色终端交互验收。

新增投影字段是可选字段；旧客户端仍读取原 status。新客户端对没有收尾证据的
持久化终态保守显示待收尾，恢复仍由既有恢复服务负责。没有数据库迁移。
回滚代码不会撤销已经执行的外部效果或改写持久历史。

核心故障回归可以自动运行，不需要用户重复操作界面：

```sh
python -B -m pytest -q -p no:cacheprovider \
  tests/test_process_closeout.py tests/test_dag_admission.py \
  tests/test_process_routing_choices.py tests/test_continuation_obligations.py \
  tests/test_process_routing_projection.py tests/test_optional_delegation_contract.py
```

这些测试通过现有 fixture 使用临时配置与状态目录。前端继续使用项目现有的
`bun test`、`bun run build` 和 TypeScript 检查；运行工具版本应符合仓库要求。
真实模型、正式终端以及平台验证结果应另列，不能用上述回归替代。

尚需连续真实模型场景、正式终端、跨平台受保护 Git 路径，以及完整交接、订阅
错投/改派与事件重复/乱序测试。分阶段测试通过不能视作整个 #55 完成。
