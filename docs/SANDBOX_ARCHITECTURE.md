# 沙箱能力与验证摘要

更新日期：2026-10-18。范围：Issue #17 的执行安全基础设施及 Windows 单任务最小验收。
配置步骤见[原生沙箱](NATIVE_SANDBOX.md)，审批边界见[执行与审批](EFFECTIVE_EXECUTION_PLAN.md)。

## 当前能力

| 范围 | 当前状态 |
| --- | --- |
| 执行入口 | ToolPipeline 使用已注册的 ExecutionContract；原生调用将参数、工具版本、任务作用域、超时和 OS 策略固定后交给 runner。未知合同拒绝执行，审批不能关闭隔离。 |
| Windows 原生执行 | AppContainer 与 Job Object 提供文件/网络边界、整树内存/进程/CPU 限制及生命周期管理；需要先显式配置专用运行时和可丢弃工作区。 |
| 文件读取 | `read_file` / `file_read` 按实际打开对象读取；显式审批绑定文件对象和参数，不能用同名替换扩大权限。 |
| 执行结果 | 业务结果、原生启动/退出、效果状态、证据提交和清理分别报告；工具输出不能自造权威结果或子回执关系。 |
| 失败与恢复 | 证据提交失败不触发重跑；清理未知保留所有权与资源债务，阻止后续原生启动。Host 重启不复活旧执行授权、不自动重放未知调用。 |
| 受保护 checkpoint | Windows 上通过显式 StorageRuntime 入口提供有严格容量边界的保存和恢复；不是默认存储迁移或完整工具启动事务。 |

Linux 已有 bubblewrap/cgroup/seccomp 后端和独立 CI，必须满足对应系统前提。
macOS 生产沙箱保持关闭；能力审计通过不表示生产后端可用。
这些平台结果不能互相代替。

## 使用限制

- 当前验收目标是 Windows 11 x64、一个活动任务。不同任务的共享身份、复杂并发和全平台等价不在此承诺范围。
- 授权工作区允许写入。读取工具的对象绑定不使任意进程变成只读，也不保证工作区 Git 配置、hooks 或其他元数据可安全交给 Host 执行。
- 运行时与可写工作区必须分离；不要暴露含凭据的通用运行时。环境变量白名单不能代替对运行时内容的检查。Windows 向应用包开放的部分系统资源仍可访问。
- 已有内存、进程、CPU 和输出限制；没有通用硬磁盘/文件数配额或任意工作负载容量保证。
- 完整工具持久化准入、隔离项目修改与补丁交付、pytest/Bun 开发项目兼容、指定 API 和正式安装包中的完整流程尚未作为本版能力验收。
- 数据库提交和 OS 启动不是原子事务。计划摘要、数据库 fencing、超时或请求终止均不能独立证明进程已经退出。

受保护 checkpoint 的 16 KiB 输入、8 对象和 32 物理代际限制只约束该显式存储接口，详见[存储能力与限制](CAS_LIFECYCLE.md)。
