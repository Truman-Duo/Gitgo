# 原生沙箱：配置、限制与验证

更新日期：2026-10-22。能力概览见[沙箱摘要](SANDBOX_ARCHITECTURE.md)。
本页针对源码与实际 frozen Host 的受限能力，不代表已发布安装包自动启用全部功能。

## 执行范围

Shell、exec、测试、自定义可执行工具及搜索等外部进程通过原生 runner 进入 OS 边界。
注册测试使用同一入口；审批不能关闭隔离，不支持的能力明确拒绝，不回退为普通 Host 子进程。
普通文件工具和匿名公共检索仍按各自合同判断，不能由某个原生入口的通过推断全部工具已具备同等隔离。

工具执行继续使用[既有执行与审批链](EFFECTIVE_EXECUTION_PLAN.md)。
`read_file` / `file_read` 的[对象读取](STABLE_FILE_READ.md)及[显式审批](APPROVED_FILE_READ.md)另有更窄的接口限制。

### 文件服务与原生执行的区别

`edit_file`、`write_file`、`delete_file`、`apply_patch` 和 `document_create` 使用命名文件服务检查并提交冻结候选。
旧 `file_edit/file_write/file_delete` 调用保留参数适配；已有文件的覆盖、追加、编辑和删除需要当前版本，旧名称不增加默认能力或权限。
原生 runner 中的新旧文件修改名称返回 `FILE_SERVICE_REQUIRED`，应通过正常工具流水线调用文件服务，不能为继续运行把私有状态暴露给沙箱。

文本补丁先在工作区之外投影，再检查全部候选，最后逐文件提交；投影用固定 Git 数据命令，不加载项目仓库配置。
该补丁接口限 UTF-8 文本，补丁不超过 2 MiB、输入/输出各不超过 16 MiB、最多 128 个目标文件；二进制、链接和模式变化尚不属于该文本接口。
删除保留恢复引用。批量提交不是原子文件系统事务；中途失败或取消保留已完成效果，并分别报告未提交、部分提交或未知，不能盲目重放或假称回滚。

`document_create` 的文本输出复用相同文件服务；Office/PDF 格式库在私有原生工作区运行，确认进程清理和访问授权撤销后，才把实际生成的字节作为候选提交到正式目标。二进制候选最多 8 MiB，绑定任务、进程、会话、目标基线、生成参数和工具实现版本。经验提醒往返复用同一份已冻结候选，不重新生成后冒充同一输出；默认标题仍取正式目标文件名。

冻结候选使用现有项目存储与容量/GC 管理。成功提交后按引用版本释放待提交根；尚未解决的候选继续占用存储，释放根也不等于立即物理删除。候选失效需重新检查后有意重建，不能将旧提醒引用用于新候选。缺少二进制文本检查视图时，可能适用的必需文本检查保持未知，正式目标不提交；用户授权不把未知检查变成通过。

私有生成进程与正式文件效果分别记录：复用缓存不能声称本次又启动了原生进程。生成进程或访问撤销未确认时保留私有目录/恢复记录，并接入既有清理债务与恢复阻断。宿主在新进程检查点前退出时，已经持久化的清理未知事实仍从调用日志恢复，不自动重跑。

`promote_agent_changes` 在主进程审查后，对整个正式变化复用同一经验检查、反馈和文件写锁，再通过可信 Git 应用二进制/模式等补丁。当前变化最多128个文件、每文件16MiB、前后候选累计64MiB。检查失败不创建新的正式效果；提醒后可携原反馈引用继续相同候选，主进程批准子结果不能替代该检查。 重命名同时检查旧路径删除和新路径写入，不能只记录新名字。

晋升沿用原 prepared/committed 记录和跨进程租约，确认回应丢失时核验原请求、不重复应用。新记录同时保存原始字节摘要与 Git 版本；旧记录只提供原有 Git 表示的证据，不追认历史原始字节。恢复引用指向 Git 基线表示，不能当作原始字节备份或文件删除服务的回收引用。

当前注册的命令、自定义可执行工具和文档生成使用私有执行视图，正式文件差异经同一候选服务提交；注册测试在私有视图取证，测试写入不作为正式产物。旧应用同步/Git传输及外部插件不是这些受控工具的等价入口，不能从工具验收推断其已具备相同边界。晋升已有真实主子工作树组合验证；普通安装、完整恢复组合和正式终端仍需验收。

### 命令的私有执行区

`exec_command` 与 `shell_script` 先在正式目标之外的普通业务文件视图运行。确认进程与访问授权退休后，实际文件差异复用同一文件服务、经验检查、输入版本核对及写锁，再由服务提交。原生进程不能直接写正式目录；自定义可执行工具也复用该候选服务；纯计算工具不因此获得文件权限。

经验提醒返回 `candidate_ref` 和 `lesson_feedback_id`。检查提醒后，可用原参数及这两个引用继续同一冻结输出，无需再次运行命令；更改参数表示另一份候选，旧引用不能沿用。命令已完成、输入仍适用、输出是否发布分别记录；未发布的候选不充当正式验证通过。失败保留有界命令诊断；中途正式提交失败按原调用日志处理，不自动回滚或盲目重跑。

该视图不复制 Git 元数据或 Gitgo 状态；应使用相对工作区路径，脚本/argv 内的绝对路径不被改写。最多4096个普通文件、8192个枚举节点、每文件16MiB、总计128MiB；变化最多128文件，前后候选共64MiB。不支持的链接/特殊文件、目录删除、纯空目录或模式变化明确拒绝。大依赖项目、普通 Git 命令和部分绝对路径用法可能不适用；这不是完整开发环境或磁盘配额保证。

Windows 下命令与文档候选使用原项目状态内的短目录。私有用户/临时目录超出支持的进程启动路径边界时，在执行前明确拒绝；可通过更短的状态存储位置处理，不能改为无隔离执行。wrapper 已启动但结果丢失时，命令完成状态保持未知，不误报未启动。

成功的只读命令可以满足合同中的调用次数要求，同时保持正式文件效果为未提交。它不能代替合同要求的实际文件修改；不要为完成流程创建无关文件。

## Windows：AppContainer 与 Job Object

文件访问受 AppContainer SID 与 ACL 共同约束，默认没有网络 capability。
Job 在用户代码开始前绑定，限制整棵进程树，并禁止 breakaway。
当前策略默认内存 512 MiB、进程数 32；累计 CPU 预算由 Host 根据调用超时确定，原始策略默认 120 秒。
CPU 带宽不超过系统一颗逻辑 CPU 的份额，外层 Job 可能进一步收紧。
内存、进程数及带宽硬限制与累计 CPU 监督分别生效；50 ms 检查间隔和调度会产生终止延迟。
必需的 Job 限制无法建立时拒绝启动，包括部分 DFSS 环境。

正常返回、取消、超时和 Host 消失均受整树生命周期管理。
终止请求不等于清理完成：必须观察 Job 活动进程归零并成功关闭句柄，才能确认清理。

只给专用运行时读取/执行权限，给本次工作区修改权限。
Windows 向 ALL APPLICATION PACKAGES 开放的部分系统资源仍可访问，不能承诺系统文件一律不可读。

### 日常访问准备与动态子工作树

日常准备可使用仅处理 DACL/MIC 的入口。它要求当前操作员已持有目标对象的
READ_CONTROL、WRITE_DAC、WRITE_OWNER，不请求 UAC、不启用备份/恢复权限，也不修改 owner/group 或审计策略。
仍须使用无凭据的专用运行时，并先停止目标项目的使用者；私有记录放在暴露目录之外。

```text
DEDICATED_PYTHON scripts/provision_sandbox.py --workspace PROJECT --record PRIVATE_HOST_DIR/access.json --access-only --current-runtime --apply
```

请从实际要使用的专用 Python/源码布局执行此入口。`--current-runtime` 与 child 自动准备复用同一布局；移除 `--apply` 可预览，不创建 profile、记录或修改权限。显式指定目录仍可使用 `--runtime`，不能与 `--current-runtime` 混用。

正式 Daemon 会在其管理的 Windows 子工作树开始执行前准备独立身份的访问，结束后撤销该任务授权和 profile；准备/清理失败不发布成功。
源码模式的自动准备只暴露 backend 和专用 Python 依赖，代码根目录本身的访问不继承到仓库其他材料。
profile 的创建/撤销由访问准备或操作员配置负责；每次原生启动只派生同一个 SID，不重复创建 profile。派生失败仍拒绝，不切换身份或回退无隔离执行。
原生进程启动函数仍不修改 ACL，LLM 和工具参数不能指定额外授权树。
这不表示所有安装目录都能以普通用户修改，也不替代运行时内容审查。

需要人工处理遗留访问时，在停止使用者后可按该类记录撤销：

```text
python scripts/provision_sandbox.py --access-only --restore PRIVATE_HOST_DIR/access.json --apply
```

此入口只移除本次配置的 SID 授权并删除 profile，保留其他任务授权；**不恢复工作区完整性标签或完整安全策略**。
未确认的原生清理、权限冲突或不完整撤销保留私有记录供检查，不以重跑业务操作恢复。
已确认撤销的记录压缩为摘要，避免每个任务长期保留整棵运行时的权限快照。
下面的完整描述符恢复工具继续保留原权限和未变化树的要求。

### 完整描述符的显式配置

采用专用、可丢弃工作区与专用 Python/安装运行时。
不要授予用户主目录、磁盘根目录或包含凭据的通用 Python 环境。
Source 模式还需要独立 Gitgo source root；venv 需要其专用 base Python；frozen 模式需要完整安装目录及依赖。

可写工作区与可信源码、Python、冻结运行时不得互为父子，链接/目录联接别名也会检查。
开发 Gitgo 自身时从工作区外的可信安装启动 Host。
路径分离不等于完整供应链、硬链接或运行时内容审计。

在受信任操作员终端先预览：

```text
python scripts/provision_sandbox.py --workspace PROJECT --runtime DEDICATED_RUNTIME --runtime GITGO_SOURCE
```

预览不创建 profile、修改 ACL 或建立恢复记录。
应用前停止所有相关进程，并在现有的外部 Host 私有目录指定一个新恢复文件；
它不得位于工作区或暴露的运行时树，已有记录不得覆盖：

```text
python scripts/provision_sandbox.py --workspace PROJECT --runtime DEDICATED_RUNTIME --runtime GITGO_SOURCE --record PRIVATE_HOST_DIR/project-acl.json --apply
```

应用需要独立授权的操作员令牌已有 SeSecurityPrivilege、SeBackupPrivilege 和 SeRestorePrivilege。
脚本不请求 UAC，Agent 工具也不自动配置权限。
它保留并检查对象身份、owner/group、DACL、审计、MIC 和继承状态；不能无损处理或存在冲突时拒绝。
最多处理 100000 个对象，恢复记录最多 64 MiB。记录含私有路径/SID，仅保存在 Host 私有目录。

### 恢复和配置失败

先预览，再显式恢复：

```text
python scripts/provision_sandbox.py --restore PRIVATE_HOST_DIR/project-acl.json
python scripts/provision_sandbox.py --restore PRIVATE_HOST_DIR/project-acl.json --apply
```

恢复只支持记录中的原对象与预期权限状态。新增、删除、原子替换、链接/重解析、多硬链接或外部权限冲突会拒绝；
不能给新对象套用旧 ACL。版本 1/2 记录不支持自动恢复，需保留后人工核验。已完成记录不能重复应用。
失败保留明确状态和恢复材料，不把部分回滚报告为成功。

这支持配置失败回滚和未变化树的恢复，允许保留同一对象的内容编辑；
它不是产生新文件后工作区的通用卸载器。
配置和恢复期间必须停止所有相关使用者，现有互斥与对象检查不能冻结其他程序修改 ACL。
profile 保留以免影响共享使用者；撤销全部相关 ACE 并停止所有使用者后，由操作员单独审查删除。
不要手动丢弃恢复记录，或递归修改权限来绕过拒绝。

### 工具兼容

Windows `shell_script` 使用系统 PowerShell，禁用用户 profile，固定系统模块并使用 UTF-8。
调用方须迁移 Bash 语法并重新审批。Git Bash/MSYS 的共享全局对象与该 AppContainer 不兼容。
`exec_command` 接受明确 argv；运行时不可访问或程序不兼容时返回错误。

Home、AppData、Temp 和模块缓存重定向到工作区内的沙箱目录。
凭据等环境变量不在继承白名单中；但磁盘上的运行时内容仍需单独检查。
旧版 DOC 的外部转换器也必须位于已配置的可读运行时范围，未验收任意转换器发行包。

## 可信 Git 工作树操作

内部工作树服务使用独立于任意脚本执行的受保护 Git 路径。Windows 源码实现会在
每次命令期间保持 Git 配置、存在的包含文件及工作树引用不可改写/替换，隔离继承的
Git 环境控制，关闭钩子、文件监视器、签名、外部 diff/textconv、自动维护和按需联网取对象。
保留有界的内容/路径偏好；不更改用户配置，不把已批准的任务解释为执行仓库程序的授权。

自定义 clean/smudge/process 过滤器在此可信路径禁用；文件实际需要这些过滤器时明确失败，
不静默提交未过滤内容。缺失、循环/重复、超限或不支持展开的仓库包含配置会拒绝执行；
启用 worktreeConfig 时要求可保护的实际配置文件。需要支持 `--no-lazy-fetch` 等当前 Git 参数。
非 Windows 尚无等价的受保护配置后端，隔离工作树操作会拒绝，无裸执行或共享工作区回退。
这不表示 Linux 原生脚本沙箱已停用，也不代表所有旧应用 Git 入口已迁入这一受控路径。

该边界防止仓库配置把程序带入可信工作树服务，不能替代正式修改服务、晋升检查、
原生进程隔离和清理。它不是任意仓库、任意 Git 版本的安全证明。

## Linux：系统前提

需要可信系统 bubblewrap、当前 ABI 的 libseccomp、用户 namespace，以及已委派的 cgroup v2 scope/service。
缺少 cpu/memory/pids 控制器、`cgroup.kill` 或必要过滤能力时拒绝执行，不降级。

后端提供私有文件系统/PID/网络/IPC namespace、只读运行时、可写工作区和私有临时目录。
每次调用有独立 cgroup 的内存、进程和 CPU 限制，后代受同组监督。
只允许受限 socket domain/socketpair 组合；Unix socket 服务、io_uring 和兼容 32 位 ABI 当前不支持。
取消需终止进程树；清理必须确认 cgroup 为空并完成移除。

在已支持用户委派的系统中，可使用现有包装器：

```text
systemd-run --user --scope -p Delegate=yes python scripts/run_linux_sandbox_scope.py -- python -m backend.core.native_host_entry
```

包装器不申请 root 或修改祖先委派策略。系统管理员仍需预先提供授权的委派范围，
Host 使用 `GITGO_SANDBOX_CGROUP_ROOT` 指向该范围。
独立子树配置可用 `scripts/provision_linux_sandbox.py` 预览；仅导出变量不能跨越委派边界。
Linux source/frozen 使用同一原生边界，Windows 结果不能代替 Linux CI。

## macOS

生产入口返回 `SANDBOX_UNAVAILABLE`。
CI capability audit 只记录系统能力和当前缺口，不是原生后端验收。
进程组清理、单进程 rlimit 或空 VM 创建成功不能证明整树生命周期及聚合资源限制。

## 结果、错误与恢复

调用证据写到项目绑定的外部 Host 状态目录，不能落入可写工作区或暴露的运行时树。
旧工作区调用日志只供人工核验，不自动升级为可信证据。
业务成功、启动/退出、效果、证据提交和清理分别报告；退出码零不独立证明任意写入效果。
证据更新失败保留已有业务结果及恢复依据，不为补日志重跑调用。

已启动后取消、超时或异常退出仍可能有副作用，不能宣称自动回滚。
未知清理保留原生所有权和已持有的读取资源，阻止继续原生执行；Host 重启不复活旧 grant 或重放未知调用。
每路输出最多保留 2 MB，超过预算终止进程树；这不是磁盘写入配额。

| 错误码 | 含义 |
| --- | --- |
| GITGO-E3801 | 原生沙箱不可用 |
| GITGO-E3802 | 启动被拒绝 |
| GITGO-E3803 | 策略无效 |
| GITGO-E3804 | 输出超限 |
| GITGO-E3805 | 执行失败，效果可能未知 |
| GITGO-E3806 | 先前清理未确认，阻止新执行 |
| GITGO-E3812 | 可信 Git 保护后端不可用，拒绝执行 |
| GITGO-E3813 | Git 配置不能完整保护，拒绝执行 |
| GITGO-E3814 | 超出内部 Git 命令/覆盖参数范围 |
| GITGO-E3815 | 未找到执行工作区之外的操作员 Git |

遇到清理未知先检查原生进程与保留债务；新的用户授权不能替代清理证明。
不要通过关闭隔离、放宽运行时目录或裸 Host 重试处理错误。

## 验证入口

源码测试：

```text
python -B -m pytest tests/test_native_sandbox.py tests/test_runtime_cleanup_evidence.py -q
```

实际 Windows frozen Host 可通过环境变量 `GITGO_SANDBOX_TEST_HOST` 指向已构建的 `gitgo-host.exe`，再运行：

```text
python -B -m pytest tests/test_native_sandbox.py tests/test_windows_sandbox_minimum.py -k packaged -q
```

上述原生测试会使用自有临时工作区/运行时和临时 ACL，必须在授权的测试环境运行。
缺少实际 Host 的 packaged 测试会跳过，不能把跳过视为通过。
既有 `scripts/run_sandbox_acceptance.py` 先做源码回归，再构建真实 onedir Host 并运行打包测试；

## 自定义工具与注册测试

自定义程序注册自测在可丢弃的私有目录执行，保存的工具版本不依赖源码草稿继续存在。纯计算与 Host 桥接程序使用私有执行目录；桥接的每个业务调用继续经过现有工具管道。受批准的 privileged 程序输出经过文件服务和经验检查后发布；执行批准本身不豁免输出检查。

`run_test` 的执行与测试清单登记分开：pytest 在私有业务视图运行，临时文件不发布；运行时确认退出与输入版本后，由原清单组件登记。Windows 注册测试使用 pytest 支持的 sys 捕获、私有日志与临时夹具适配，不开放 NUL 设备或权威状态文件。直接父目录只允许属性查询与路径穿越，不允许列目录、文件读写或继承访问。

这些源码接线仍在完整 Native Host、安装及发行组合验收中；不同于完整开发运行时兼容已完成。任意 Python 程序自己的 Windows mode-0700 临时目录调用仍可能被 AppContainer 拒绝。测试退出状态及有界版本连续性也不证明测试语义充分。


经验来源收集由项目绑定的知识服务访问状态；原生执行器不提供 `lesson_harvest` 状态处理器。来源状态区分已检查、缺失与不可用，观察不会自动保存或确认成知识。Git历史读取使用现有受保护执行边界，来源文件使用对象绑定读取；不支持的保护后端不回退为裸进程。


公共搜索和页面抓取由固定网络服务承载，继续使用公共读取策略及当前Provider配置；原生脚本不会因此获得联网权限或Provider凭据。这些同步网络请求声明为不可立即中断：取消前不会发起，但在途请求依照现有传输超时结束。搜索提供方生成的摘要及返回链接不等于逐页核验的事实。


普通文件、文档和批量提交拒绝修改 `.git` / `.gitgo` 元数据，返回 `GITGO-E3526`；Windows 对应的尾点、空格和命名流写法也在效果前拒绝。项目状态维护仍须使用专用状态操作。此边界不代表所有旧状态持久化、备份恢复或旧 Git 传输已经迁移。


### 工具记忆备份与恢复

`memory_snapshot` / `memory_restore` 处理本项目 `.claude`、`.codex`、`.codebuddy` 的文件数据，属于配置备份恢复，不是自动确认经验。使用项目配置的本地备份节点，不能通过工具参数选择其他工作区。

新快照保存于该备份节点绑定的 Gitgo 状态存储，采用不可变数据与有限保留；不会继续向 `backup/.gitgo/memories` 写新目录。备份/迁移应包含对应产品状态，单独复制业务目录不包含新快照。旧磁盘快照保留只读兼容，不自动移动或删除。

每次最多 128 个文件、合计 16 MiB，每来源保留最近 5 个档案引用；链接、特殊文件与嵌套 Git/Gitgo 元数据不支持。超限明确失败，不截断后宣称完整备份。逐文件读取不构成文件系统原子快照。

恢复复用原冻结文件候选、经验检查、版本复查、写锁及删除恢复引用。提醒续轮使用返回的候选和反馈引用；目标变化、必需检查失败或未知时不提交。部分/未知效果不能当作自动回滚后重试。空目录创建、目录/文件形态转换和跨位置档案移植需要明确迁移。

### Windows Git 兼容范围

应用使用的本地 Git 读取、提交和命名 remote 的 fetch/push 复用受保护入口。标准 http/https/git/ssh/file 传输及操作员全局 SSH/凭据配置保留；仓库提供的可执行 hook、自定义传输、SSH/凭据命令明确拒绝。配置来源不能通过包含项目文件伪装成全局配置。该入口不授予网络或发布授权，也不替代已有发布检查。

自定义过滤器不能静默当作未过滤字节；自定义 merge driver 的 cherry-pick、本地接收端 per-worktree 配置或 updateInstead 检出更新、同一 remote 混合本地/网络 URL 暂不支持。传输只接受一个命名 remote，不开放自定义 upload/receive 程序或任意参数。远端服务器自身的配置仍由远端运营者管理。

已用正式冻结Host验证隔离仓库的真实 push/fetch、执行前检查之后才出现的本地接收 hook 不执行，以及继承 Git 环境不会使新项目采用外仓身份。全局 SSH/凭据兼容另用无真实凭据的命令及回环 HTTP 认证挑战验证，未据此宣称完整 SSH/HTTPS 服务器传输均已验收。
