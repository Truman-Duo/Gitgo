# Unix 运行与凭据维护说明

## 凭据升级与清理

凭据索引 version 2 可以读取旧 version 1，记录活动凭据与待清理的不透明引用，不保存 API key 明文。旧程序不能读取 version 2；升级后不要直接用旧包修改索引。回滚前使用新版完成清理并核对备份，不把旧索引覆盖回来。

保存新配置和清理旧凭据分别报告。配置保存成功但旧凭据无法清理时，Provider 界面提示待清理状态；后续保存和新版卸载会重试。系统服务不可用、锁定、拒绝授权或超时不会被当作成功删除，最后的待清理引用保留。状态查询只显示数量。

卸载前退出所有 Gitgo 实例。原生凭据删除失败会保留程序、索引、命令入口和 PATH，供恢复服务后重试。`--keep-config` 保留配置与凭据。无法确认属于本次安装、被重定向或已经修改的 PATH 配置会保留并提示，避免覆盖个人 dotfiles。卸载后的用户状态和项目目录继续保留；旧无安装所有权记录的目录不能自动接管。

凭据写入和清理的提交失败会阻止相应原生操作或保留重试记录。源码故障注入、CI keyring 往返与真实桌面授权交互是不同验收范围，不能互相替代；硬件故障与所有文件系统的掉电恢复尚未认证。

## Unix 命令退出与取消

命令正常退出、取消或调用方断开时都会尝试清理所属执行范围。清理信息独立于业务结果，进入运行时诊断和回执；清理未确认时通过既有工具通知显示。已经完成的业务效果保留，不应仅为了重新获取诊断而重复执行。

- Linux 支持受监督命令和被收养后代的有界清理；权限错误、超时或身份不明会报告清理不完整，不扩大终止对象。
- macOS 当前支持受控会话。任意程序自行 setsid/double-fork 脱离后不能保证完整回收，报告 `owned-session-only`、`complete=false`。这不是 OS 原生沙箱。
- 未通过受监督入口创建的 Unix 子进程只清理已拥有的根进程，明确报告能力限制。

用户收到清理不完整通知时，应先检查剩余进程，再决定是否重试。冻结包、真实终端任务取消以及桌面 Keychain/Secret Service 的交互仍需按目标平台验收。当前原生包的支持范围、触发和下载方式见 [原生包维护说明](native-package-automation.md)。
