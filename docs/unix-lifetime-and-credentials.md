# Unix 命令生命周期与凭据清理

这份说明绑定 PR #29 的整改源码，不表示新 frozen 包或所有平台已验收。

## 原生凭据的重试索引

凭据索引升级为 version 2，可读取旧 version 1。新版包含活动 `secrets`
映射和只存不透明引用的 `pending_cleanup`；不保存 API key 明文。
旧版本读取 version 2 会拒绝，避免无感丢弃清理记录。升级后不要用旧包修改
或删除该索引；需要回滚时先用新版完成清理并核对备份，不能把旧索引复制回去。

Keychain/Secret Service 写入前先分配引用、落盘创建意图，再请求系统写入。
写入超时或索引提交失败时，最后一份引用仍可重试。保存新配置和删除旧凭据
是不同事实：清理失败不会把已经保存的新配置报成失败，Provider 界面会提示
旧凭据待清理。下一次配置保存会重试，也可通过新版卸载的 credential-cleanup
入口重试。状态查询仅公开待清理数量，不返回引用或系统凭据内容。
新 API key 使用新的配置引用；旧配置落盘记录仍有效期间不覆盖/删除其凭据。
配置落盘失败留下的新凭据仍在索引内，可由后续清理或卸载回收。

系统删除确认前不移除最后的重试记录。Secret Service clear 返回 1 不直接
算成功；只有无错误的删除成功，或成功的空搜索确认不存在，才可移除引用。
失败、锁定、拒绝访问及超时均保留索引。清理检查点落盘失败也保留旧记录。
跨进程文件锁串行化索引与原生凭据副作用，不改变 Host 的权限审批边界。

卸载先清理凭据，再处理命令链接/PATH/程序目录。凭据清理失败保留完整重试
入口；`--keep-config` 不调用凭据删除。此整改不声称后续 PATH/文件删除已具备
与安装相同的完整事务，也不将模拟服务测试当成真实桌面凭据交互验收。
卸载前应退出所有 Gitgo 实例；单次索引锁不等于卸载后允许另一个实例继续
创建凭据，也不替代整个安装目录的生命周期管理。

## 命令的受控生命周期

Unix 命令和隔离工具 runner 通过同一监督入口创建。监督者先建立独立会话，
在命令启动前持有其生命周期和私有控制通道；源代码与 frozen Host 使用同一
实现。工作命令不继承控制通道。拥有者断开、正常结束或取消均触发清理。
启动确认有独立上限：源码 5 秒、frozen 20 秒；冷启动签名/加载开销不等于
命令不受支持。启动失败仍关闭控制通道并回收监督者，不无限等待。

监督者只向自己仍占有的进程组发信号，不根据 ps 快照或后来查询的 PGID
扩大终止权限。payload 父进程先退出也不会导致提前放弃受控会话。

- Linux：可用时启用 subreaper 与 pidfd，处理被内核收养的 detached 后代；
  用 pidfd 定向发信号，不把单个 PID 提升成整组权限。清理有时间上限，失败
  或不能确认时报告 `complete=false`。这仍不是 OS 沙箱或无逃逸证明。
- macOS：保证受控会话的清理，并监督嵌套 Gitgo runner 的控制通道；任意程序
  自行 setsid/double-fork 脱离时没有 Linux 的收养/pidfd 原语。本轮明确返回
  `owned-session-only`、`complete=false`，取消/超时说明清理未完全确认。
  不能据此声称完整停止所有 detached 后代；更强的 macOS 覆盖尚待设计与实机验证。
- 未经本入口创建的 Unix Popen：只处理自己拥有的根子进程，返回
  `unmanaged_root_only`，不尝试扩大到采样得到的其他组。

命令返回的 `cleanup` 区分受控范围和完整性。测试用临时合成命令及无关哨兵
验证边界；Linux 原生、真实 Keychain/Secret Service 和 frozen 包仍须独立验收。
