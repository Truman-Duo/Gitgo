# Rust 原生边界（Issue #45 阶段一候选）

本候选基于 Alpha 3.1。构建、源码测试、真实 frozen 执行及最终发行包验收分别记录，不能把源码编译成功视为阶段完成。完整沙箱目标继续由 #17 和 #45 跟踪。

## 接口与权威

Python 保留工具注册、准入、权限、调用日志、SQLite/CAS 状态、候选发布和恢复判断。Rust 不审批调用、不接受 AUTO 绕过、不建立第二份持久恢复账本。已有 `native_invocations.v1` 先持久化意图，之后才进入原生创建/启动。

固定 C ABI 版本为 1。请求有大小限制并拒绝未知字段；调用前必须提供完整响应缓冲区，不能为获取响应长度而重发启动。错误、ABI 不匹配或未知响应均拒绝继续；panic 封闭该模块实例。OOM、abort、断电、Host 强制退出不能由 Drop 推断已清理。

| 操作 | 输入范围 | 结果 / 取消 |
| --- | --- | --- |
| `job_create` | 已有恢复 ID、整树进程数/内存/CPU 预算 | 不可复用的进程内 token；不创建业务授权 |
| `launch` | 既有授权对应的 profile、工作目录、冻结命令/环境、明确继承句柄表 | 每个 Job 最多一次尝试；过程与线程资源归 Rust；不开放 shell/任意创建标志 |
| `job_query` / `job_retire` | 同一 Rust 模块实例的 Job token | 原取消对象沿 Python 调用链请求退休；必须观察整树归零且关闭成功 |
| `job_recover` | 既有恢复记录核对后的恢复 ID | 只打开旧命名 Job；不存在可作为原生边界消失观测，不重放命令、不自动结清业务证据 |
| ACL 操作 | 既有固定访问掩码、已固定文件 token、有界二进制描述符 | 只支持完整安全流或限定的 DACL/MIC 写入；授权、冲突核对和恢复记录保持原通路 |

资源保留不等于授权有效。参数、工具合同、任务版本、模式和权限仍在原准入通路核对，组合/自造工具的叶子调用没有额外豁免。已发出的模型网络请求不因此被无条件打断。

Windows 运行实现摘要纳入原工具合同，包含真实二进制 SHA-256、大小和 ABI。加载器不接受模型或环境指定的库地址；持有逐级目录与无写入/删除共享的映像句柄，核对实际加载模块的对象身份。旧授权不能用于内容或 ABI 改变后的新运行时。源码/安装整体仍须是可信运行时，原生 ABI 不是向不可信进程开放的权限服务。

Rust 用不同类型处理 Kernel HANDLE、AppContainer SID、LocalAlloc 描述符文本和属性列表；对应 `CloseHandle`、`FreeSid`、`LocalFree`、属性列表删除。未知退休保留资源所有权及原恢复债务，重复清理不得关闭被系统复用的新句柄。ACL 恢复继续检查原对象、完整描述符、库存及祖先边界；不把恢复权限扩展到日常 DACL/MIC 路径。

本次迁移边界是 AppContainer 工具调用与 ACL 资源。通用可信 Host 启动监督器、存储原生 worker、稳定读取与 Linux 隔离继续沿用各自已存在的边界，不能把它们表述为已全部迁至 Rust。

## 平台与构建

| 平台 | 阶段一 Rust 模块 | 继续使用的现有能力 / 明确缺口 |
| --- | --- | --- |
| Windows 10+，x86_64 | AppContainer 启动、Job 整树限制/退休、过程/线程与 ACL 临时资源 | 仍要求专用可信运行时及操作员访问准备；真实源码、frozen 与最终包须分别验收 |
| Linux x86_64 / aarch64 | 相同 ABI、能力与明确不支持结果 | 执行继续使用现有 namespace/cgroup/seccomp；Rust 执行迁移属于阶段三 |
| macOS 26 arm64 | 相同 ABI、能力与明确不支持结果 | 安全读取保留；通用执行与受保护 Git 仍拒绝，属于阶段四 |

使用 Rust 1.90.0 与已提交 Cargo.lock；运行时不下载编译器或依赖。构建前安装该工具链，再运行：

```text
python -B scripts/build_sandbox_native.py
python -B -m pytest tests/test_native_sandbox_abi.py -q
```

构建目录为源码 checkout 内的忽略目录，产物不提交 Git。Host 的 PyInstaller hook 要求实际库存在并纳入包；发行冒烟从 frozen Host 内加载库，不能被开发机 PATH 中的库替代。所有原有发布检查继续生效。

### macOS 后续方案的可行性

原生方案需分别证明文件/进程/网络限制、整树聚合预算与崩溃恢复；现有安全读取、健康探针限制、进程组和单进程 rlimit 均不足以证明通用开发沙箱。

Virtualization 方案还需带相应 entitlement 的宿主、支持的硬件、隔离的来宾映像与来宾内整树预算/清理协议。GitHub 托管 ARM macOS runner 不支持嵌套虚拟化；其构建/能力审计只能验证接口，VM 攻击与生命周期验收必须安排支持虚拟化的真实宿主。阶段一保留两条方案的选择，不发布无隔离占位后端。

## 验收边界

复用现有原生测试中的正常、文件/网络拒绝、环境过滤、整树预算、超时、取消、Host 退出及 frozen 管道；新增真实 Rust ABI、加载对象、不可重放启动及重复退休检查。权限撤销、模式/机制更新、未知调用日志与证据失败继续由原合同与恢复回归覆盖。

阶段完成必须列出相同候选提交上的三平台构建、Windows 实际迁移路径、最终包与故障结果。未执行、跳过、失败和仅模拟的故障分别披露；在这些结果齐备前，本文件只说明候选实现，不声称阶段已通过。
