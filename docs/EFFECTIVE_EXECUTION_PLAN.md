# 执行与审批：当前能力及边界

更新日期：2026-10-18。范围：Issue #17；实现状态概览见[沙箱能力摘要](SANDBOX_ARCHITECTURE.md)。

## 已接入的执行依据

工具执行沿用 ToolPipeline、ExecutionContract、现有 permission request、用户 decision 和 grant。
工具声明决定执行类别和受审查的文件动作；模型输入、业务 effect 和工具自述不能授予权限。

原生调用由 Host 固定规范参数、工具注册版本、任务作用域、超时及 SandboxPolicy，runner 使用并核对同一份调用快照。
回执中的 `execution_basis` 由 Host 计算，关联该次执行依据；它不是授权凭据，也不是持久化启动许可。
显式审批读取还绑定实际文件对象，见[审批文件读取](APPROVED_FILE_READ.md)。

准备与前置拒绝不消费授权。实际准入重新核验所需整组授权，在现有进程内锁下消费一次；
同一个单次 grant 不能被并发调用重复使用。审批不会扩展原生 OS 的文件或网络权限。

## 已实现但未启用的描述

源码中的 `ReadExecutionPlan` 提供有界、不可变的读取计划描述及校验。
它尚未形成贯穿持久化准入与原生能力验证的生产启动入口；调用其准入检查仍明确拒绝。
不能将构造成功、摘要匹配或现有局部 ReadPlan 当作完整权限计划已启用。

没有增加第二套权限库，也没有从工具 JSON 接收 Host 的私有计划。

## 结果与恢复

- 启动前拒绝与启动后未知分别记录；成功退出不独立证明业务效果。
- 业务结果、证据提交和清理状态分别呈现。证据提交失败保留已有结果及恢复依据，不重跑调用。
- 原生清理未确认时保留资源债务和相关对象引用，阻止继续原生执行；不能按超时归还资源。
- Host 恢复后不重新载入可执行旧 grant；缺少活跃文件对象保护时需要重新审批。新审批也不能作为重放旧未知调用的依据。
- 数据库提交与 OS 启动之间存在非原子窗口。现有进程内一次性消费不等于完整、跨 Host 的持久化工具启动事务。

## 验证与范围

授权并发竞争、参数/对象/工具变化、恢复后旧授权失效、私有字段拒绝、可信回执及未知清理分别有对应测试。
协议测试证明授权和结果处理；只有实际原生/打包测试能支持对应 OS 隔离结论。
当前已完成版本、结果及跳过项统一见[验证摘要](SANDBOX_ARCHITECTURE.md#验证版本与结果)。

完整工具持久化准入、写入/Git/服务的通用权限计划及聚合预算不在本轮启用范围。
现有受保护 checkpoint 是[独立的显式存储接口](CAS_LIFECYCLE.md)，不能替代这些执行前提。
