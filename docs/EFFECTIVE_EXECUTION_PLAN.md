# 有效执行计划：接入合同与实现顺序

状态：设计候选，2026-10-13。属于 Issue #17 / PR #25；不是 effective manifest 已实现或安全验收通过声明。沿用 [沙箱架构](SANDBOX_ARCHITECTURE.md) 的威胁模型和阶段门槛。

## 当前代码中的接入障碍

`ExecutionContract` 目前只声明执行类别和具名 broker。`permission_broker.tool_contract_digest` 绑定工具定义，`ProcessToolRunner.run` 另外构造 `SandboxPolicy`。两者尚未共享编译后的权限计划。

ToolPipeline 的参数准备会重映射工作区及注入 Host 参数，部分前置检查也在此后运行。因此不能在原始模型参数上计算一个新摘要，便认为它覆盖了实际启动权限。当前外部资源授权检查还会消费 grant，而普通敏感调用在另一个位置消费；两条路径必须先收敛。

本次实现仅完成 ToolPipeline 的进程内授权准入前置：准备阶段只预览，参数、前置条件、治理和 RingGate 检查通过后，重新选择并验证整组授权，在现有 grant 锁内一次消费。一个授权同时覆盖调用和多个资源时，只扣一次。并发调用不能共同使用最后一次授权。

这不形成持久化准入。授权消费之后、调用日志写入或启动之前仍有故障窗口；窗口内不得声称已经执行，也不得无证据恢复授权。独立的 privileged 注册门仍需与后续统一计划衔接。本次不扩大可访问资源或启用任何新平台能力。

## 不同对象的职责

| 对象 | 内容与权威来源 | 使用位置 |
| --- | --- | --- |
| 工具声明 | Host 注册的执行类型、受审查的资源动作、参数规范化规则、可信代码版本 | 现有 AgentTool/catalog |
| 调用意图 | 用户/模型输入，经纯参数规范化和工作区重映射；本身不授予权限 | ToolPipeline |
| 有效权限计划 | Host 编译后不可变的资源动作、对象身份、deny、网络/IPC、限额、运行时身份及策略版本 | 审批、broker、原生后端共同消费 |
| 已绑定执行 | 有效计划 + Host execution/task/process/parent 身份 + 本次参数 + 截止时间/租约 | 持久化准入、原生启动与监督 |
| Host 结果 | 是否启动、树身份、退出、清理、效果及证据持久化事实 | 现有 StorageRuntime、事件与恢复 |

这些是现有服务的合同，不增加第二套权限库、恢复状态机或高权限常驻服务。工具 JSON 不能构造或覆盖 Host 计划、租约、树身份或结果。

## 编译器的输入、输出与拒绝规则

输入由 Host 提供：工具声明、规范化参数、项目/任务身份、策略版本、安装清单、资源解析器持有的对象及各后端能力证据。不能用“审批通过”作为后端具备某项隔离能力的证据。

输出分为可落实的不可变计划与带具体原因的阻断结果。未知字段/版本、未注册 broker、未知动作、缺少对象保护或任一必需能力无法落实时，返回阻断结果；不产生可用于启动的 permit。不能把未实现字段填成空列表后宣称编译完成。

计划必须覆盖：

- 逻辑工作区与稳定对象身份；gitdir/common-dir/worktree/submodule 等关联对象及保留名称；
- 文件动作和资源边界、受保护 deny、具名服务目的地与操作、网络/IPC/设备规则；
- 工具源码/定义、可信运行时/helper 和安装清单身份；
- 单调用与任务/项目资源上限、scratch/cache 身份、输出和协议长度上限；
- 所需原语、编译器/策略/后端版本，以及允许的授权作用域和有效期限。

动作权限来自显式受审查声明，不能从 `read_only`、业务 effect、handler 名称或任意 `resources` 字符串猜测。deny 优先于 allow；管理 ACL 的 operator 使用单独管理合同。

schema 使用有界、确定的规范化编码：严格 JSON 类型，拒绝 NaN/Infinity、重复或未知字段，禁止 `default=str` 将未知对象转成可批准内容；数量/时长采用明确单位的整数。不可变对象的成员也必须不可变，不能在 frozen dataclass 中留下共享可变 dict/list。

## 审批摘要与执行身份

需要明确区分授权比较与一次执行的身份，避免每次生成 execution ID 就使任务授权无法匹配，也避免忽略 execution ID 后丢失真实关联。

1. 授权摘要绑定上述有效权限范围，以及 task/process、稳定工作区、工具/运行时和策略版本。单次批准还绑定准确的规范化调用参数。
2. 启动摘要绑定授权摘要、本次实际计划、Host execution/parent 身份、参数和本次截止时间/租约。由 Host 在准入事务中建立其与批准记录的关系。
3. 工具返回的摘要或 execution ID 只是工具数据，不参与授权或替代 Host 关联。
4. 任何放宽、对象替换或策略/工具身份不匹配都使旧授权失效。初版不自动证明跨版本的权限子集，不把旧工具摘要升级成有效计划摘要。
5. 任务授权需要明确的动作/参数子集规则。在该规则实现前，只接受同一规范化权限范围；无法证明属于批准范围的调用重新审批或阻断，不能继续依靠“同工具名即整任务允许”。

审批等待期间可以释放资源句柄；恢复时重新取得并核对已批准对象，不能只根据相同路径复用旧结果。实际启动阶段所需对象必须保持到相应资源操作结束。

## 调用链的目标顺序

```text
Host 注册验证
  → 纯参数规范化 / 工作区映射 / schema 验证
  → 编译资源动作与后端能力，取得必要对象保护
  → 预览或请求精确审批（等待不占用已消费授权）
  → 前置条件 / 治理 / RingGate / 取消检查
  → 复核当前计划、工具与对象身份
  → StorageRuntime 原子记录授权消费、预算租约和启动意图
  → 使用同一计划启动原生后端或执行受限 broker 动作
  → Host 监督及持久化结果
```

编译、预览或前置拒绝不消费 grant。准入提交后即使未成功启动也不能自动退还授权；恢复服务根据持久化事实处理，未知结果保留 ambiguous。Host 强杀、满盘、COMMIT 失败与跨 Host 并发必须有专门故障测试，线程锁不提供这些保证。

准备函数需逐一审查为无副作用的规范化逻辑。会访问资源或执行代码的准备工作本身是需要声明、计划和准入的操作，不能以 prepare hook 绕过执行边界。

组合工具每个叶调用都经此链。父计划只允许 Host 调度，不传递任意叶权限；恢复绑定父计划、组件计划及可信已完成前缀。作者代码注册测试也需要独立计划，模拟结果不能产生后续真实调用权限。

## 平台边界与稳定对象依赖

Windows 的 ACL 安装/恢复句柄代码可作为研究依据，但不能直接作为通用文件访问 lease：它涉及管理权限，不能阻止所有外部 WRITE_DAC，且尚未提供受限文件/Git 动作协议。

Linux 的 resolve/stat 结果和一次路径 hash 同样不构成持续的对象保护。后端必须在真实操作中消费已验证对象，或在受限 helper 内重新解析并打开；检查后再由普通 Host 按原路径操作不满足合同。

需要独立验证普通文件、重解析点/链接、硬链接、缺失保护名称、父目录替换，以及 Git 关联目录。运行时/helper 还需要不可变安装身份和受保护的加载路径。无法获得对应证明的能力必须 BLOCKED，不能标记 READY 再把限制仅写入文档。

macOS 保持生产执行不可用。Windows/Linux 也必须逐能力说明：现有原生隔离、完整元数据保护、硬磁盘/文件数配额、聚合预算、身份及清理证明分别验收；不能用某一项成功推断其他项已实现。

## 实现次序和验收边界

1. **进程内准入归一（本次）**：资源检查无消费；整组授权重新验证并一次扣减；失败不部分扣减；一次性授权并发只有一个获准调用。现有源码正向操作与组合恢复回归保持。
2. **动作和资源合同**：清点 Host broker/prepare/注册测试入口；实现严格计划 schema、能力编译和稳定对象接口。未知/缺失能力必须明确阻断，不提供宽松默认。
3. **同一计划贯穿审批与执行**：移除 runner 重新生成权限默认值，后端和 broker 消费计划；测试批准后参数、策略、对象、工具、runtime 变化。启动前实际身份保护与原生正向/拒绝测试必须一起交付。
4. **持久化准入与恢复**：与现有 StorageRuntime 事务整合授权/租约/intent，覆盖掉电模型、Host/child 强杀、证据失效与并发恢复；再补全可信 Host envelope。

每个实现提交保留准确测试版本和未覆盖项。仅第 1 项通过时，不能标记阶段 A、完整 manifest 或 B1–B6 完成，也不能据此请求安全验收通过。
