# 更新检查与验证范围

关联任务：[安全自动更新与回滚 #21](https://github.com/Truman-Duo/Gitgo/issues/21)。

## 当前状态

源码已有签名清单验证、整包下载、隔离解压与[确认更新/回滚入口](update-preparation.md)。在明确选择的新管理安装中，发行公钥与渠道地址必须在初始安装时固定，`/update` 才可手动检查、确认下载和申请更新。Linux/Windows 在确认退出且完整清理后交接，macOS 在确认后等待手动重启。缺少策略时不联网；打开页面、刷新本地状态或普通启动不会自动检查/下载。普通旧安装不会被自动接管。

管理安装复用[事务与恢复引擎](update-transactions.md)的唯一 ledger。模拟模式仅供隔离测试，不是管理安装的授权来源。最新实际包证据见 [Linux 双架构验收](linux-managed-update.md)与 [Windows 管理更新](windows-managed-update.md)。

自动检查默认关闭，正式发布地址与可信公钥未预置。检查需要初始安装固定的本地策略、已登记安装信息和兼容描述；缺失时拒绝继续。下载不会自动运行候选，替换还需要独立确认、稳定启动器、独占运行锁和启动健康检查。正式发布、生产传输和可见终端人工验收仍分别跟踪。

## 当前验证行为

- 支持 stable 与 preview，严格匹配产品、平台和架构，不自动切换渠道。stable 不接受预发布版本。
- 使用 Ed25519 detached signature 验证更新清单的精确 UTF-8 字节；只信任本地配置的公钥，不信任清单携带的密钥。
- 验签成功后才解析清单。拒绝重复字段、未知 schema、缺失字段、非法数字、超限大小与过深嵌套。
- 按 SemVer 2 比较版本；普通更新不降级，相同版本的不同 build metadata 不触发替换。
- 检查发布时间与有效期，有效期最多七天；清单过期或系统时间不适用时拒绝。
- 对传入的已有检查记录校验发布序号、内容摘要、版本与时间；拒绝序号倒退、同序号改写和同版本换包。相同已验证清单可以重试。
- 只允许明确列出的 HTTPS 发布域名，拒绝凭据、查询参数、片段、非标准端口和危险路径；实际传输逐跳验证重定向，限制超时、总传输时长和流式字节数。
- 比较新旧数据兼容描述，包括每条数据库迁移的版本及摘要、配置与 Provider 格式版本和迁移摘要。缺少本地描述或发生变化时阻止更新，不执行迁移。
- 检查结果可以是“关闭”“已是当前版本”或“发现候选”。候选只包含已验证元数据，不代表下载、安装或回滚已经获准或完成。

元数据目标包括 Windows x86_64、macOS arm64、Linux x86_64/aarch64；离线检查测试不等于相应平台的实际包验收，后者按上述独立记录核对。

## 下载与隔离解压

准备操作只能由明确调用触发，不支持自动下载。它重新检查完整签名清单，不接受手工构造的候选对象作为授权。默认总开关关闭时，不访问网络、时钟、磁盘或用户配置。自动检查开关不构成自动准备授权。

- HTTPX 使用启用证书验证的全新客户端，支持本地环境代理与 CA 配置；不继承应用的认证、Cookie，不转发服务端 Cookie。重定向最多三次，目标仍须在本地允许域名中。
- 仅接受完整的 HTTP 200，要求原始、未额外 HTTP 压缩的响应。不做断点续传，也不把 HTTP 206 当作完整包。
- 默认网络各项超时为 15 秒、单次传输总时限为 600 秒。流式核对响应上限、可选 Content-Length、签名声明的精确大小，以及最终 SHA256；不把整个发行包载入内存。
- 下载后、解压后再次核对签名与有效期；过期、取消、网络/代理错误、磁盘失败或包损坏均拒绝准备。
- 暂存父目录必须由本地调用方提供，已存在、为规范绝对路径，并与明确提供的安装、项目、配置、运行状态等保护路径完全分离。POSIX 检查用户所有权、私有权限和祖先目录防替换条件；Windows 的独立 NTFS 适配核对所有权、私有 DACL、卷/文件身份与祖先条件，不跳过权限检查。
- 每次使用随机的新目录，先写 `.part`，校验后安全展开，全部成功才返回 `staged`。失败只清理本次创建的目录；强制杀进程/断电可能留下私有残片，它不会成为当前安装。此阶段没有扫描、接管或清理历史残片的功能。
- ZIP 支持已有 Windows 包的平铺布局、Stored/Deflate，不支持 ZIP64、多卷、加密或特殊文件；Unix tar.gz 要求一个目录外壳与单一 gzip member，支持普通文件、目录和有效的包内相对符号链接，拒绝拼接 member 和压缩流尾部额外数据。
- 不调用 `extractall`。完整检查路径、大小写/Unicode 冲突、重复条目、链接图和父节点后才写入文件；拒绝绝对/越界路径、反斜杠、控制字符、Windows 设备名/数据流、硬链接、设备/FIFO、稀疏文件、外部/悬空/循环链接，以及穿过链接写文件。
- 包内 Unix 链接最后创建，支持 PyInstaller 框架的前向引用、相对父路径和有限链式引用。暂存不恢复归档所有者、时间戳、setuid/setgid 或组/其他用户权限。
- 默认上限：10,000 条目、最多两倍数量的显式/隐式路径、4 GiB 文件总量、2 GiB 单文件、8 MiB 元数据、1 MiB 单次 tar 元数据读取及单个 PAX/GNU 扩展记录、1,000 倍展开比例、32 层路径及 300 秒处理时限。ZIP 中央目录在库进行批量解析之前检查真实条目数；tar 的隐藏 PAX 元数据也计入上限。

`staged` 仅表示签名绑定的压缩包已安全展开，**不表示可安装、可执行、已更新或可回滚**。这里不启动候选程序或安装/卸载脚本，也不修改注册、PATH、项目、数据库、配置、秘密或现有程序。临时目录由同一用户控制，不能作为抵御同用户恶意进程的沙箱；后续应用阶段必须重新验证工件并建立安装锁与所有权权威。

tar.gz 使用有界的临时未压缩 tar 文件，再展开 payload；峰值磁盘空间包含下载包、tar 暂存和最终 payload，并非只等于下载大小。检查时限在处理点协作检查，网络阻塞另受 HTTPX 超时限制；这不是 OS 级 CPU/内存/磁盘配额。真实包规模、权限/ACL、网络、代理与设备故障还需各平台验收。

## 清单与发布契约

更新清单 schema 1 与发行包的 product/build manifest 分开维护。它包含产品、release ID、渠道、序号、有效期、版本、平台、架构、整包格式、下载地址、字节数、SHA256、源码 commit/tree、数据兼容描述和最低更新器版本。

签名 envelope schema 1 包含固定算法 `ed25519`、本地可信 key ID 和标准 Base64 签名。清单限制为 128 KiB，签名 envelope 为 1 KiB，包的声明大小不得超过 2 GiB。Windows 整包格式为 ZIP，Unix 整包格式为 tar.gz；差分更新不在当前范围。

签名私钥由发行维护者管理，不能进入客户端、源码或日志。SHA256 不能代替发布者签名。被签名的兼容描述和来源信息仍必须与实际解压出的工件对照，不能只凭清单宣称包已通过验证。

## 尚未完成的边界

- Dashboard 的 `/update` 仅在项目列表可用，General 中显示真实 Host 只读版本号。新管理安装可明确选择渠道、确认下载及申请更新/保留上一版回滚；普通旧 Host 的只读 schema 1 状态仍兼容。本地状态刷新不联网，UI 输入/渲染与隐藏 PTY 测试不计为正式终端视觉验收。
- 已有 HTTPS 流式传输器，但测试使用 HTTPX MockTransport 和本地生成的 ZIP/tar.gz；尚未进行真实 HTTPS 服务、企业代理、正式 CDN 和发行包下载验收。
- 独立纯检查/准备函数仍接收显式调用方输入；新增应用适配器把签名验证后的 high water 保存在同一安装 ledger，下载取消/失败不降低。签名缓存不是另一套 high water 权威，重启、刷新和下载均重新校验签名、范围、兼容、有效期及 ledger。成功下载不构成程序替换授权。
- 打包器新增明确选择的更新数据证据生成：Unix 的 `--update-evidence`、Windows 的 `-UpdateEvidence`。默认构建未启用；独立 Windows 验收 CI 明确选择新的管理模式并生成证据，见 [Windows 管理更新](windows-managed-update.md)。旧包缺少描述时不会自动猜测或放行。
- 选择生成时，将构建环境中的 SQL 迁移与配置/Provider 写入代码指纹和实际冻结 Host 的独立结果比较，匹配后才写入数据契约。源码与冻结字节码采用相同规范化格式，包含 Python minor 标识；变化时保守拒绝，而非执行迁移。证据只覆盖列明的迁移与写入模块，不证明所有应用逻辑或所有历史数据都兼容。
- 下载后的适配器核对完整 product/build manifest、来源、inventory 和数据证据。确认交接后由稳定 bootstrap 重新验证，取得独占锁后才切换和运行限定健康探针；不完整的清理不能授权即时替换。兼容描述变化时保守拒绝更新，不迁移用户数据库。
- 管理安装已有启动前恢复门禁和实际双版本验收；早期模拟/占位文件测试不能代替这些证据。历史虚拟机突然停止实验也不证明物理掉电耐久性。
- Windows NTFS/Job 适配和 Linux 双架构自动化已有独立记录；Windows 可见终端人工验收暂缓，macOS 仅支持手动重启后替换。正式信任根、发布流程、真实生产 CDN/代理和各平台人工验收未由本轮自动化完成。
- 测试使用一次性测试密钥、注入传输和保护数据哨兵；实际包与平台证据按确切 head 分别记录，不据此宣称生产密钥分发、所有系统时间异常或所有断电时点已验证。

产品及各平台的实际可用范围仍以[版本](VERSION.md)与[已知限制](KNOWN_ISSUES.md)为准。自动更新在完整安装、故障回滚及数据保护验收完成前继续保持关闭。
