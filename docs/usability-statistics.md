# 后台可用性统计

使用当前源码启动项目运行服务后，统计线程自动启动，正常采集不打断对话。它记录派生指标，不自动评分、修改模型行为或授予权限。

## 保存位置与内容

统计跟随项目状态，通常位于用户状态目录下的 `projects/<project-id>/usability/`，不同终端不会因此分开计数。隔离测试沿用自己的状态根目录。

记录任务/请求/工具与问题事件计数、可关联耗时、上下文字符数、真实 Provider 用量、模型/协议以及有来源时的终端信息。alignment 用量按用途和阶段区分。新的统计库不复制用户消息、回答、思考正文、工具参数或凭据。

字符数不是 token 数，未知用量不是零，事件数不是对话数量。只覆盖仍然保留的源记录；采集积压、源缺失或明细损坏会标记，不能据此声称所有使用都已完整记录。

## 故障与保留

采集独立于前台任务，有资源与保留上限；失败会留诊断并通过现有错误通道通知。旧进程需要正常退出后用新代码启动；不能由源码测试通过推导所有已安装旧包自动启用了新统计。

读取使用已有只读 CLI：

```text
<gitgo-python> -B -m backend.core.usability --project-root <project-state-directory> --days 30
```

真实对话及原始运行数据不应上传。当前验证范围见 [测试结果](VALIDATION.md)。
