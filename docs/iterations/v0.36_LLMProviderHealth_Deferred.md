# v0.36 延后设计：LLM Provider 健康信息并入 Providers 面板

> 记录原 `/config` 中 LLMConfigPanel `Status` 标签页的信息，标注哪些真实、哪些是假/死数据，
> 以及未来并入 `Providers` 标签页时所需的接口与后端连接。

---

## 背景与决定

v0.36 之前，`/config` 打开的 `LLMConfigPanel` 有两个标签页：`Providers | Status`。
经与用户确认，`Status` 标签页的「LLM provider 健康状态」与 `Providers` 标签页的「配置选择态」语义有重叠，
且 `Status` 标签页中大量数据实为假数据/死数据。决定：

- **删除 `Status` 标签页**，只保留 `Providers` 单标签。
- 把真正有价值、且尚未被 `Providers` 内化的信息记录于此，未来完善 `Providers` 时逐项并入。

已删除的代码：

- `cli/dashboard/src/components/LLMConfigPanel.tsx`：`renderStatusTab()`、`CfgTab` 类型、`TAB_LABELS`、`useLoopData` 依赖、`breakerStateToStatus`/`healthByProvider` helper。
- `cli/dashboard/src/input/overlayKeymaps.ts`：`switchTab` / `statusIgnore` 动作、`LLMConfigCtx.cfgTab` 字段、Tab 切换键位（←/→）。

## Status 标签页原有信息逐项盘点

| 信息 | 数据来源 | 现状 | 建议去向 |
|---|---|---|---|
| Daemon 在线状态 | 硬编码 `"online"`（未读任何字段） | ❌ 假数据 | 前端 `useLoopData.daemonOnline` 已可用，如需展示直接消费即可 |
| 每个 provider 熔断器状态 `open/half_open/closed` | `gitgo_loop_status.providers[].breaker_state` | ❌ 死数据（后端恒返回 `providers: []`） | 需后端先实现熔断器，见下方「待实现」 |
| Failover ON/OFF | `gitgo_llm_status.failover_enabled` | ✅ 真实配置 | 并入 Providers（当前只显示 failover 指向的 provider 名，不显示开关态） |
| Failover 优先级顺序 | `gitgo_llm_status.failover_order` | ✅ 真实配置 | 并入 Providers（当前只显示单个 failover 名） |
| Providers 在线数 X/N | 由 `breaker_state !== "open"` 派生 | ❌ 依赖死数据 | 等熔断器实现后再并入 |
| 活跃 Worktrees 数 | `gitgo_loop_status.processes[].worktree_path` | ✅ 真实（daemon 实时） | 归 `/processlist`（`ProcessList.tsx` 已消费 `useLoopData.processes`），不在 Providers 重复 |
| Project 名 | 平凡信息 | ✅ | 不需要 |

## 接口与后端连接

### 前端 hooks

**`useLLMConfig(client, project)`**（`cli/dashboard/src/hooks/useLLMConfig.ts`）

- 返回 `{ providers, activeProvider, failoverEnabled, failoverOrder, loading, error, fetchStatus, saveProvider, switchProvider, deleteProvider, toggleFailover }`。
- 通过 `gitgo_llm_status` 拉取；`failoverEnabled` / `failoverOrder` 是配置态，**当前已可用**，只是 Providers 面板尚未渲染。

**`useLoopData(client, project, refreshSec)`**（`cli/dashboard/src/hooks/useLoopData.ts`）

- 返回 `{ processes, toolEvents, providers: ProviderHealth[], daemonOnline, loading, error, mainConversation, agentConversations }`。
- 通过 `gitgo_loop_status` 拉取；`processes[].worktree_path` 与 `daemonOnline` 是真实数据；`providers[].breaker_state` 目前恒为空（后端未实现，见下）。

关键类型定义：

- `ProviderHealth`（`hooks/useLoopData.ts`）：`{ id, breaker_state, failures, available }` — 前端类型已备好，后端未填充。
- `ProcessInfo`（`hooks/useLoopData.ts`）：含 `worktree_path`。
- `LLMProvider` / `LLMConfigState`（`hooks/useLLMConfig.ts`）：`LLMConfigState` 含 `failover_enabled` / `failover_order`。

### 后端 MCP 工具

**`gitgo_llm_status`**（`mcp_tools/llm_config.py:17`）

- 调用 `backend/core/llm_config.py` 的 `LLMConfigManager.load(ws)`，读 `.gitgo/llm_config.json`。
- 返回 `{ project, providers(key 已脱敏), active_provider, failover_enabled, failover_order }`。

**`gitgo_loop_status`**（`mcp_tools/loop.py:14`）

- 优先走 daemon：`get_client(project).send_command({"cmd": "task", "action": "status"})`。
- 失败回退 `_loop_status_from_history(project)`（`loop.py:217`，从 `HistoryManager` 重建进程树）。
- 返回 `{ project, processes, recent_tool_executed, providers, daemon_online }`。

### 后端数据源（daemon）

- `backend/core/daemon/__init__.py`：`loop_status` / `task status` 命令返回 `"providers": []`（约 1479–1483、1559–1563 行）。
- `backend/core/llm_config.py`：`LLMConfigManager` 只做 CRUD + active switch，**没有熔断器（circuit breaker）实现**，因此 `breaker_state` 无处产生。

## 待实现（未来并入 Providers 时）

1. **熔断器（Circuit Breaker）**：在 LLM 调用路径（`backend/core/loop/llm.py` 的 provider 调用封装，或 `LLMConfigManager`）实现 `open/half_open/closed` 状态机——失败 N 次 → open，冷却后 → half_open，成功 → closed。并填充 `gitgo_loop_status` 的 `providers[].breaker_state`。之后前端才能在 Providers 里展示健康点。
   > 提醒：前端 mock `cli/dashboard/src/mock/mockData.ts` 的 `MOCK_PROVIDERS`（`closed/half_open/open` 熔断态）目前是占位假数据，等真熔断器落地后由 `gitgo_loop_status.providers` 真实填充替换。
2. **Failover ON/OFF 与优先级顺序并入 Providers**：`useLLMConfig` 已返回 `failoverEnabled` / `failoverOrder`，只需在 `renderProjectsList` / `renderDualColumn` 渲染，无需后端改动。
3. **Daemon 在线状态**：前端 `useLoopData.daemonOnline` 已可用，若未来需要展示直接消费该字段即可。
4. **Worktrees 数**：归 `/processlist`（`ProcessList.tsx` 已消费 `useLoopData.processes`），不在 Providers 里重复。
