# Gitgo v0.28 — Contract Dependency Checking

> 2026-05-30 | 功能依赖检测

---

## 问题

修改一个文件后，gitgo 当前只检查该文件本身是否违反 contract（如架构约束）。
不检查**依赖此文件的其他模块是否还能正常工作**。

例如：修改 `backend/core/knowledge/lesson.py`（拆分为 models/manager/harvest）后，
dashboard 无法启动——因为 lesson.py 的 re-export 路径变了。
但如果拆分发生在未被测试覆盖的模块，gitgo 无法检测到这个断裂。

## 方案

在 Gate A 的 Policy Engine 检查集中，新增一个 dependency check：

1. **静态依赖图**：从 project contract 的 `decided_features` 中提取 `location` 和 `signature` 字段
   - `location`: 功能所在的文件路径
   - `signature`: 功能的类名/方法名/函数名

2. **变更影响分析**：当 `compare_files` 检测到某个文件被修改或删除时：
   - 检查该文件是否在 contract 的 `decided_features` 中的 `location` 字段
   - 如果是：检查 `signature` 是否仍然存在于文件中
   - 如果签名消失：Gate A BLOCKED，输出受影响的功能名称

3. **跨文件依赖**：如果一个 decided_feature 的 `signature` 在另一个模块中被 import：
   - 检查那个模块是否在本轮变更中
   - 如果是：验证 import 的签名在新版本中是否仍然可用

## 与现有系统的关系

- `decided_features[].location` 和 `decided_features[].signature` 已经在 contract 中
- `compare_files()` 已经产出变更文件列表
- Gate A 的 Policy Engine 检查集已经存在
- 本次改动只在检查集中新增一条规则
