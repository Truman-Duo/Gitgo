### 3.3 _back_to_list 返回流程（关键修复）

```python
def _back_to_list(self):
    # 1. 停动画
    if self._page_anim: self._page_anim.stop()

    if self.workspace:
        ws_ref = self.workspace
        self.workspace = None

        # 2. 断开 scroll 信号（防 paint 回调）
        ws_ref.commit_scroll.verticalScrollBar().valueChanged.disconnect()

        # 3. 先切页面再移除（关键顺序）
        self.stack.setCurrentIndex(0)
        self.stack.removeWidget(ws_ref)

        # 4. 脱离 widget 树，不主动 delete C++ 对象
        ws_ref.hide()
        ws_ref.setParent(None)  # Python GC 自然回收

    # 5. 更新项目列表页
    self.project_list._refresh_table()
```

**设计原因**：之前 6 轮迭代中 `deleteLater()` 和 `shiboken6.delete()` 均在 Qt 事件重入时触发 `STATUS_STACK_BUFFER_OVERRUN`。最终方案不主动删除，交由 GC。

### 4.4 PanelState — 跨 Mixin 共享状态容器（v0.14 新增）

**背景**：WorkspacePanel 通过 10 个 Mixin 类组合而成，Mixin 间通过 `self.xxx` 隐式共享 39+ 个属性。新开发者接手 UI 时无法判断属性的读写来源。

**PanelState 规则**：
- 任何被 2+ 个 Mixin 访问的属性，必须在 `PanelState.__init__` 中定义
- 每个属性标注 Producer (P) 和 Consumer (C)，可直接从字段注释追踪影响范围
- Mixin 内通过 `self.state.xxx` 访问共享属性
- 局部属性（仅一个 Mixin 使用）仍用 `self._xxx`，不放入 PanelState

**关键属性分类**：

| 类别 | 属性 | P | C |
|------|------|---|---|
| 业务状态 | `config` / `project` / `session` | panel | all |
| 选中状态 | `selected_formal` / `selected_incoming` | panel.init | commits/syncpush/trial |
| 流程状态 | `_merging` / `_merge_indices` / `_scanning` | commits/panel | commits/builder |
| 后台 Worker | `scan_worker` / `sync_worker` / `push_worker` / `trial_worker` / `triage_worker` | panel/syncpush/trial | panel |
| Workshop UI | `merge_btn` / `sync_btn` / `push_btn` / `msg_box` / `commit_canvas` / `ws_box_layout` / `fm_box_layout` | workshop_tab | commits/syncpush |
| Explorer UI | `file_tree` / `diff_panel` / `diff_preview` | explorer | panel/explorer |
| Incoming UI | `trial_scroll` / `trial_box_layout` / `bridge_widget` / `confirm_widget` | incoming_tab | trial |
| Tab/Stack | `tab_bar` / `tab_stack` / `action_lo` | builder | panel/builder |

**新增属性的步骤**：
1. 在 `panel_state.py` 的 `PanelState.__init__` 中添加 `self.xxx = None`
2. 标注 `# P: xxx, C: yyy`
3. 在 Producer Mixin 中 `self.state.xxx = value` 写入
4. 在 Consumer Mixin 中 `self.state.xxx` 读取

### 5.2 CommitCanvas（统一提交区）— v2 重构后

**文件**: `frontend/commit_canvas.py`

**v2 关键架构变化**：标题行从 `workshop_tab.py` 移入 CommitCanvas 内部，与下方 columns 共享**同一个 widget 树**，保证天然对齐。

```
CommitCanvas (QWidget, objectName="commit_canvas")
  outer (QVBoxLayout, margins=0, spacing=4)
    ├── hdrs (QHBoxLayout, spacing=52)    ← 标题行，与 columns 布局参数完全一致
    │   ├── ws_hdr (QLabel#ws_hdr, setFixedWidth(148), stretch=0)
    │   └── fm_hdr (QLabel#fm_hdr, stretch=1)
    └── columns (QHBoxLayout, spacing=52)
        ├── ws_column (QWidget, setFixedWidth(148), stretch=0)
        │   └── ws_layout (QVBoxLayout, spacing=4) → WorkspaceCommitBox × N
        └── fm_column (QWidget, stretch=1)
            └── fm_layout (QVBoxLayout, spacing=4) → FormalCommitBox × N
```

| 属性 | 值 |
|------|------|
| objectName | `commit_canvas` |
| QSS | `background: {t.bg}` |
| 标题行 spacing | 52 (与 columns 一致) |
| ws_hdr | `QLabel#ws_hdr`, `setFixedWidth(148)`, 默认隐藏 |
| fm_hdr | `QLabel#fm_hdr`, stretch=1, 默认隐藏 |
| ws_column | `QWidget`, `setFixedWidth(148)` |
| fm_column | `QWidget`, stretch=1 |

**为什么是 setFixedWidth(148) 而不是 setMinimumWidth(148)**（这是本版本最重要的 Bug 修复）：

`setMinimumWidth()` 只设下限，不决定实际分配。当 stretch=0 时，QHBoxLayout 按 `sizeHint()` 分配宽度。QLabel（ws_hdr）的 sizeHint 和 QWidget 包裹 wordWrap QLabel（ws_column）的 sizeHint 不同，导致标题行和内容行的 ws 列宽度动态偏离。`setFixedWidth()` 锁死宽度，消除 sizeHint 差异。

**paintEvent 绘制**：
- x0 = `ws_column.geometry().right()`, x1 = `fm_column.geometry().left()`
- 贝塞尔曲线: `path.cubicTo(cx, ws_y, cx, fm_y, x1, fm_y)`
- 线宽 1.5px，`setBrush(NoBrush)` 只描边
- 箭头: `QPolygonF` 三角形 (x1-6, fm_y±3)，指向 fm 侧
- `try/finally: p.end()` QPainter 异常安全
- 防御守卫: `if self.ws_column.geometry().width() == 0: return` (避免 layout 未完成时绘制)
- connections 数据结构: `list[tuple[ws_y, fm_y, color_hex, dashed]]`
- `resizeEvent` 中通过 `_line_refresh_cb` 回调（QTimer.singleShot(0)）在布局完成后刷新线条

**滚动联动**：`commit_scroll.verticalScrollBar().valueChanged` → 16ms 单次防抖 QTimer → `_refresh_commit_lines()`

**虚线规则（B-5）**：connections 数据结构为 `list[tuple[ws_y, fm_y, color_hex, dashed]]`
- 实线 (`SolidLine`): pushed > synced > 默认 blue
- 虚线 (`CustomDashLine [4,2]`): `is_incoming` amber / 全部关联 ws commit 为 docs/chore/style → teal
- 颜色优先级：`is_incoming` > pushed > synced > commit_type(docs/chore/style → 虚线) > blue 默认

### 5.3 WorkspaceCommitBox（v2 重写 — 单一 QSS 驱动）

**文件**: `frontend/commit_box.py`

**v2 核心改变**：从三层样式冲突（Global QSS ↔ Widget setStyleSheet ↔ QPainter）改为**单一 QSS 驱动**，状态通过 `setProperty` + `unpolish/polish` 触发 Qt 内部增量重算。

**删除的旧机制**：
- ❌ `_apply_style()` 方法 — 每次状态变化调 `setStyleSheet()`
- ❌ `enterEvent` / `leaveEvent` — QSS `:hover` 伪状态替代
- ❌ 基类 `CommitBox` — 不再需要

**新机制**：
```python
# 状态切换三步骤
self.setProperty("selected", value)    # Step 1: 设 property → Qt 内部标记
self.style().unpolish(self)            # Step 2: 强制 Qt 丢弃旧样式缓存
self.style().polish(self)              # Step 3: Qt 重新匹配 QSS 规则
```

**summary 最大高度**: `setMaximumHeight(48)` (防 wordWrap 撑爆)

### 5.4 FormalCommitBox（v2 重写 — QSS border-left 替代 QPainter）

**文件**: `frontend/commit_box.py`

**v2 核心改变**：
- 左侧 3px 竖线从 `paintEvent → fillRect()` 改为 **QSS `border-left: 3px solid`**
- 删除 `enterEvent`/`leaveEvent`，`:hover` 由 QSS 接管
- 删除 `_apply_style()`，所有状态切换走 `setProperty` + `_polish_all()`

**构造**: `FormalCommitBox(idx, title, subtitle, parent)`
**布局**: QFrame `#fm_card`, `QVBoxLayout(margins 13,6,28,6, spacing 2)`
  - 左 margin=13（而非 ws 的 10），因为 QSS `border-left-width: 3px` 吃掉内容 rect 3px → 实际文本缩进 = 13+3 = 16px

**QSS 状态属性选择器优先级**（后定义覆盖前定义）：

| 状态 | property | 背景 | border-left 颜色 |
|------|----------|------|-----------------|
| normal | — | `t.bg` | `t.blue` (默认) |
| synced | `[synced="true"]` | `t.success_bg` | `t.success` |
| pushed | `[pushed="true"]` | `t.success_bg` | `t.success_txt` |
| incoming | `[incoming="true"]` | — | `t.amber` (仅改变 border-left) |
| selected | `[selected="true"]` | — | `t.blue` (不改变文字/背景) |

**QSS 优先级的关键规则**：`[selected]` 必须在 QSS 中最后定义（最高优先级）。Qt QSS 对同 specificity 的选择器按源码顺序决定优先级（后定义覆盖先定义），而非 CSS 的"最后匹配 wins"。

**⋯ 按钮**: `QPushButton("⋯")`, fixedSize 18×18, 右上角绝对定位 (`resizeEvent` 中 `move(width-22, 5)`), inline stylesheet（唯一保留的 widget 级样式，因为其颜色不跟随 formal box 状态变化）
**右键菜单**: 编辑消息 / 编辑编号 / Dissolve / Clear sources
**双击**: 编辑消息
**菜单触发**: 右键 (`contextMenuEvent`) 和 ⋯ 按钮 (`clicked`) 共享菜单构建逻辑，通过信号发送 action

**删除的 v0.x 机制**：
- ❌ `_set_active_formal()` — QGraphicsOpacityEffect 非选中卡片 → 已删除，不再需要
- ❌ `paintEvent` — fillRect 竖线 → QSS `border-left` 替代（与边框/背景在 Qt 渲染管线中同步，无异步闪烁）
- ❌ `_accent_color()` 方法 — 颜色优先级由 QSS 规则顺序隐含表达

## 十一、CommitBox / CommitCanvas v2 重构返工记录

> 2026-05-12 | 本轮重构经历多次返工，以下记录所有错误路径和最终正确解法，供后续参考。

### 11.1 重构目标

消除三层样式系统冲突（Global QSS ↔ Widget setStyleSheet ↔ QPainter），修复 6 个已知 Bug（Canvas闪烁、WS文字遮盖、标题不对齐、Formal高亮残留、主题切换颜色残留、Formal竖线异步）。

### 11.2 标题与 Box 不对齐 — 4 轮返工

**这是本轮最顽固的 Bug，经历 4 轮修复才找到根因。**

| 轮次 | 尝试 | 结果 |
|------|------|------|
| 1 | workshop_tab.py 标题行中 `hdrs.addSpacing(52)` 与 Canvas columns `setSpacing(52)` 不一致 | ❌ addSpacing 是累加值，setSpacing 是间隙值，语义不同 |
| 2 | 将标题行从 workshop_tab.py 移入 CommitCanvas 内部（同一 widget 树） | ⚠️ 大幅改善，但 resize 时仍有偏差 |
| 3 | 调整 fm_hdr padding-left：10px→13px（匹配 FormalCommitBox 的 margin）→16px（13+3 border-left-width 吃内容 rect） | ⚠️ 初始对齐，resize 后偏差 |
| 4 | **根因定位**: `setMinimumWidth(148)` 只设下限，stretch=0 时 QHBoxLayout 按 sizeHint() 分配。QLabel sizeHint ≠ QWidget 包裹 wordWrap QLabel 的 sizeHint → 动态宽度偏差。**最终解法**: ws_hdr 和 ws_column 都改为 `setFixedWidth(148)` | ✅ 完全解决 |

**教训**：在 QHBoxLayout + stretch=0 的场景中，必须用 `setFixedWidth` 而非 `setMinimumWidth` 来保证对齐。`setMinimumWidth` 只是下限约束，实际宽度由 `sizeHint()` 决定——不同类型的 widget 有不同的 sizeHint，导致宽度动态偏离。

### 11.3 QSS 语法错误 — `}};` 双花括号

**现象**：QSS 中 `background: {t.bg2}};` 渲染为 `background: #2a2a2a};` —— 末尾多了 `}`。

**根因**：f-string 中 `{t.bg2}};` —— Python 将 `{t.bg2}` 替换为颜色值，后面的 `}` 原样输出。

**修复**：所有 `{t.xxx}};` 改为 `{t.xxx};`（去掉多余 `}`）。

### 11.4 QSS border-left-width 吃内容 rect

**现象**：fm_hdr 文字位置与 fm box 文字位置差 3px。

**根因**：Qt QSS `border-left-width: 3px` 不仅视觉上画边框，还会吃掉 content rect 的 3px。所以 box 内部文本实际缩进 = margin(13px) + border-left(3px) = 16px。

**修复**：fm_hdr padding-left 从 10px（匹配 ws margin）→ 13px（匹配 fm margin）→ **16px**（匹配 fm margin + border 总占用）。

### 11.5 QSS 属性选择器优先级

Qt QSS 不支持 CSS 的 specificity 计算。相同 specificity 的选择器，**后定义的覆盖先定义的**。

**QSS 中必须按此顺序定义（低优先级在前）**：
1. `#fm_card` (默认: bg, border-left blue)
2. `#fm_card[synced="true"]` (synced 背景+边框)
3. `#fm_card[pushed="true"]` (pushed 背景+边框)
4. `#fm_card[incoming="true"]` (incoming 仅边框)
5. `#fm_card[selected="true"]` (selected 边框, **最后** = 最高优先级)

与 CSS 不同——CSS 中 `.card.selected` 不管写在文件哪里都比 `.card` 优先级高。Qt QSS 中必须靠源码顺序保证。

### 11.6 setUpdatesEnabled 防闪烁

批量添加 box widget 时，每个 `addWidget` 可能触发 layout 重算 → 视觉闪烁。

**方案**：
```python
self.fm_container.setUpdatesEnabled(False)
try:
    for fc in commits:
        box = FormalCommitBox(...)
        self.fm_box_layout.addWidget(box)
finally:
    self.fm_container.setUpdatesEnabled(True)
```
**关键**：`try/finally` 确保即使中间抛异常也能恢复更新。
