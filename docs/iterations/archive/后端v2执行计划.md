## B-1：Incoming → Workshop 跨 Tab 数据流 — ⚠️ 最高风险，最后执行

### 目标

Accept 确认后需要触发的完整状态链：
1. 标记 Incoming 卡片 done
2. 延迟 800ms 后自动切到 Workshop Tab
3. 在 Workshop 中插入 incoming formal commit
4. LSB 更新文件树（新增 Incoming 区段）
5. 日志记录

### 实现方案

```python
# trial.py (TrialMixin)
def _on_confirm_accept(self):
    change = self._selected_change
    self._current_card.mark_done("accepted")
    QTimer.singleShot(800, lambda: self._post_accept(change))

def _post_accept(self, change: IncomingChange):
    self.tab_bar.setCurrentIndex(0)                            # 切 Tab
    self._insert_incoming_formal(change)                       # 插入 formal
    self.lsb.add_incoming_section(change)                      # 更新 LSB
    self.log(f"✓ Cherry-pick queued — {change.hash[:7]} added to workshop")
```

```python
# commits.py (CommitMixin)
def _insert_incoming_formal(self, change: IncomingChange):
    fc = FormalCommit(
        ticket="",
        message=change.title,
        commit_type="incoming",
        source_indices=[],
        is_incoming=True,
        incoming_hash=change.hash,
    )
    self._formal_commits.append(fc)
    self._refresh_formal_boxes()

    idx = len(self._formal_commits) - 1
    self._select_formal(idx)
```

### Claude 反馈

- **关键问题**：`_post_accept` 中 `self.lsb` 引用要求 CommitMixin 和 LSB 互相引用。当前架构中它们是独立的，需要依赖注入或信号连接
- **800ms 延迟**：硬编码。如果 `mark_done` 有动画则不同步。建议用 `QPropertyAnimation.finished` 信号替代 QTimer
- **波及范围**：涉及 3 个 Mixin + LSB 的协调，是 v2 中最复杂的跨模块操作

### 执行建议

最后执行。依赖 F-1（LSB 全局化）、F-6（Incoming 卡片）、F-7（Bridge 确认）、B-4（持久化）。

## B-2：Dissolve vs Clear Sources 后端语义 — ✅ 中风险

### 目标

两个右键菜单操作的后端行为明确化：

| 操作 | Formal Commit | Workspace Commits | 连接线 |
|------|--------------|-------------------|--------|
| Dissolve | 删除 | 恢复可选（取消合并态） | 消失 |
| Clear Sources | 保留（独立） | 禁用（opacity 0.3） | 消失 |

### 实现方案

```python
# commits.py
def _on_dissolve(self, formal_idx: int):
    """反悔：删除 formal，workspace commits 恢复"""
    fc = self._formal_commits[formal_idx]
    self.session.remove_formal_commit(formal_idx)

    for ws_idx in fc.source_indices:
        box = self._ws_boxes[ws_idx]
        box.set_selected(False)
        box.set_merged(False)

    self._formal_commits.pop(formal_idx)
    self._refresh_formal_boxes()
    self._refresh_commit_lines()

def _on_clear_sources(self, formal_idx: int):
    """封存：保留 formal，workspace 变为禁用"""
    fc = self._formal_commits[formal_idx]
    fc.sources_cleared = True

    for ws_idx in fc.source_indices:
        box = self._ws_boxes[ws_idx]
        effect = QGraphicsOpacityEffect(box)
        effect.setOpacity(0.3)
        box.setGraphicsEffect(effect)
        box.setEnabled(False)

    fc.source_indices = []
    self._refresh_commit_lines()
```

### 数据模型扩展

```python
@dataclass
class FormalCommit:
    ticket: str
    message: str
    source_indices: list[int]
    is_dissolved: bool = False
    sources_cleared: bool = False
```

### Claude 反馈

- `_on_dissolve` 当前在 `_dissolve_formal_commit` 中已有基础实现（pop + refresh_boxes）
- `_on_clear_sources` 用 `QGraphicsOpacityEffect(0.3)` + `setEnabled(False)` 禁用 — 需要 WorkspaceCommitBox 有对应的 `:disabled` QSS
- effect 不能复用在多个 widget 上

## B-3：两步确认的 Session 状态 — ⚠️ 中风险

### 目标

在 `SyncSession` 状态机中增加 `INCOMING_CONFIRMING` 中间状态，支持 Accept 两步确认。

### 实现方案

```python
# core/sync_session.py
class SessionState(Enum):
    IDLE = "idle"
    SCANNING = "scanning"
    # ... 现有状态 ...
    TRIAL_CHECKING = "trial_checking"
    INCOMING_REVIEWING = "incoming_reviewing"
    INCOMING_CONFIRMING = "incoming_confirming"   # 新增
    FAILED = "failed"

def step_start_accept_confirm(self, change: IncomingChange):
    assert self.state == SessionState.INCOMING_REVIEWING
    self._pending_accept = change
    self.state = SessionState.INCOMING_CONFIRMING

def step_confirm_accept(self) -> IncomingChange:
    assert self.state == SessionState.INCOMING_CONFIRMING
    change = self._pending_accept
    self._pending_accept = None
    self.state = SessionState.IDLE
    return change

def step_cancel_accept(self):
    assert self.state == SessionState.INCOMING_CONFIRMING
    self._pending_accept = None
    self.state = SessionState.INCOMING_REVIEWING
```

### Claude 反馈

- `INCOMING_CONFIRMING` 需要定义状态转换守卫：只能从 REVIEWING 进入，只能退出到 IDLE（确认）或 REVIEWING（取消）
- `_pending_accept` 是临时状态，不应被持久化
- 需确认所有已有代码中没有 `if state == INCOMING_REVIEWING` 被新状态影响的场景

## B-4：Incoming 已处理状态持久化 — ✅ 低风险

### 目标

Triage 执行完毕后将结果写入 config，避免重启后重复显示已处理的 incoming。

### 实现方案

```python
# core/sync_session.py
def step_triage_incoming(self, action: str, change: IncomingChange):
    runner = self._trial_runner
    if action == "accept":
        runner.cherry_pick(change.hash, target="release")
        self._record_processed(change.hash, "accepted")
    elif action == "promote":
        runner.fetch_to_branch(change.hash, branch=f"incoming/{change.hash[:7]}")
        self._record_processed(change.hash, "promoted")
    elif action == "discard":
        self._record_processed(change.hash, "discarded")

def _record_processed(self, hash: str, action: str):
    self.project.processed_incoming[hash] = {
        "action": action,
        "time": datetime.now().isoformat(),
    }
    ConfigManager.save(self._config)

def step_check_trial(self) -> list[IncomingChange]:
    all_changes = self._get_trial_log()
    processed = self.project.processed_incoming
    return [c for c in all_changes if c.hash not in processed]
```

### 数据模型

```python
# models/project_config.py
@dataclass
class ProjectConfig:
    # ... 已有字段 ...
    processed_incoming: dict[str, dict] = field(default_factory=dict)
```

### Claude 反馈

- `ConfigManager` 的 JSON 编解码需要确认支持新字段
- 旧 config 文件可能没有 `processed_incoming` 字段 → 需要 migrate / `__post_init__` 兼容
- 项目当前有两个测试配置，migrate 时需处理

## B-5：连接线数据模型扩展 — ✅ 低风险，首发

### 目标

`_refresh_commit_lines()` 返回的 connections 扩展为四元组 `(ws_y, fm_y, color, dashed)`。

### 实现方案

```python
# commits.py
def _refresh_commit_lines(self):
    t = get_theme()
    connections = []

    for fm_idx, fc in enumerate(self._formal_commits):
        if not fc.source_indices:
            continue

        # 颜色 + 线型由 formal commit 状态决定
        if fc.is_incoming:
            color, dashed = t["amber"], True
        elif fc.pushed:
            color, dashed = t["success_txt"], False
        elif fc.synced:
            color, dashed = t["success"], False
        elif fc.commit_type in ("docs", "chore", "style"):
            color, dashed = t["teal"], True
        else:
            color, dashed = t["blue"], False

        fm_box = self._formal_boxes[fm_idx]
        if not shiboken6.isValid(fm_box):
            continue
        fm_y = fm_box.mapTo(self.canvas, fm_box.rect().center()).y()

        for ws_idx in fc.source_indices:
            ws_box = self._ws_boxes[ws_idx]
            if not shiboken6.isValid(ws_box):
                continue
            ws_y = ws_box.mapTo(self.canvas, ws_box.rect().center()).y()
            connections.append((ws_y, fm_y, color, dashed))

    self.canvas.set_lines(connections)
```

### Claude 反馈

- 数据结构从当前三元组 `(ws_y, fm_y, color)` 扩展为四元组 `(ws_y, fm_y, color, dashed)`
- `CommitCanvas.set_lines()` 和 `paintEvent` 签名需同步更新
- 颜色优先级：is_incoming > pushed > synced > commit_type > default
- 与 F-3 同步执行
