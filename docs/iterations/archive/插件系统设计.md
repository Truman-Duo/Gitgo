# 插件系统设计 — Phase 0.5

> 在同步工作流的关键节点开放 Hook 接口，允许第三方/后续开发者挂载自定义逻辑，无需修改主程序。

---

## 设计原则

1. **解耦** — 主流程不依赖任何具体插件，插件不存在或报错不阻塞核心流程
2. **渐进** — 先实现 Python 插件，后续支持子进程协议（非 Python 语言）
3. **无状态** — 每次插件调用均为独立调用，插件不持有工作流内部状态
4. **沙箱** — 插件在独立命名空间执行，不能影响主程序全局状态

---

## Hook 点定义

在工作流的关键节点触发插件回调，按时间线排列：

```
扫描 ──────────────────────────→ on_scan_complete(entries) → 过滤/排序/标注
                                        ↓
Commit 选择 ────────────────────→ on_commit_select(commits) → 推荐合并索引
                                        ↓
Commit message 生成 ────────────→ on_commit_message(selected, config) → 建议 message
                                        ↓
Sync 执行（复制文件到 backup）───→ on_sync_start(entries, msg) → 拦截/放行
                                        ↓
Sync 完成 ─────────────────────→ on_sync_complete(result) → 后置处理
                                        ↓
Push 执行 ─────────────────────→ on_push_start() → 拦截/放行
                                        ↓
Push 完成 ─────────────────────→ on_push_complete(result) → 后置处理
```

### 核心钩子签名

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Any


class SyncPlugin:
    """插件基类 — 所有钩子均为可选覆盖，默认无操作"""

    name: str = ""
    version: str = ""

    # ── 扫描阶段 ──

    def on_scan_complete(self, entries: list[dict]) -> list[dict]:
        """扫描对比完成后调用。

        - entries: FileEntry 的 dict 表示（JSON 兼容序列化）
        - 返回值：替换 entries，可过滤、排序、添加标注
        - 插件可修改 entry 的 `selected` 默认值
        - 返回空列表 = 使用原始 entries
        """
        return entries

    # ── Commit 整合阶段 ──

    def on_commit_select(self, commits: list[dict]) -> list[int] | None:
        """在 commit 选择界面打开前调用。

        - commits: CommitInfo 的 dict 表示（type/scope/subject/...）
        - 返回值：建议选中的 commit 索引列表
        - 返回 None 或空列表：不干预默认选择
        """
        return None

    def on_commit_message(self, selected: list[dict],
                          project_config: dict) -> str | None:
        """在打开编辑器生成 commit message 前调用。

        - selected: 已选中的 CommitInfo 列表
        - project_config: ProjectConfig 的 dict 表示（含 prefix/format 等）
        - 返回值：建议的 commit message 字符串
        - 返回 None：走默认编辑流程（系统编辑器）
        """
        return None

    # ── Sync 阶段 ──

    def on_sync_start(self, entries: list[dict],
                      message: str) -> str | None:
        """sync 复制文件到 backup 之前调用。

        - message: 本次 sync 的 commit message
        - 返回非空字符串：中断 sync 并以该字符串作为错误消息提示
        - 返回 None：放行
        """
        return None

    def on_sync_complete(self, result: dict) -> None:
        """sync 完成后调用，不论成功或失败。

        - result: {"success": bool, "commit_hash": str, "files_count": int}
        """
        pass

    # ── Push 阶段 ──

    def on_push_start(self) -> str | None:
        """push 到 GitHub 之前调用。返回非空则中断。"""
        return None

    def on_push_complete(self, result: dict) -> None:
        """push 完成后调用。

        - result: {"success": bool, "remote": str}
        """
        pass
```

## 插件发现与加载

### 搜索路径

| 优先级 | 路径 | 说明 |
|---|---|---|
| 1 | `{exe_dir}/plugins/` | 随程序分发的插件 |
| 2 | `~/.vernier/plugins/` | 用户全局插件 |
| 3 | `{project_dir}/.gitgo/plugins/` | 项目级本地插件 |

搜索规则：
- 扫描每个路径下的 `.py` 文件（Python 单文件插件）和包目录（含 `__init__.py`）
- 插件文件/包名去掉 `.py` / `_` 后作为插件 ID（如 `auto_merge.py` → `auto-merge`）
- 重复 ID 按优先级覆盖（用户插件覆盖分发插件）

### 插件注册

每个插件文件/包必须暴露全局变量 `plugin_class`：

```python
# auto_merge.py
from gitgo.plugin import SyncPlugin

class AutoMergePlugin(SyncPlugin):
    name = "auto-merge"
    version = "0.1.0"

    def on_commit_select(self, commits):
        # 按时间窗口分组，推荐连续的同类型 commit 合并
        ...

plugin_class = AutoMergePlugin
```

### 配置启用

每个项目通过 `commit_format.plugins` 指定启用的插件列表：

```json
{
  "projects": [{
    "name": "MyApp",
    "commit_format": {
      "prefix": "MYAPP",
      "plugins": ["auto-merge", "commit-msg-gen"]
    }
  }]
}
```

- 空列表或缺失 = 不加载任何插件
- 列表中引用了不存在的插件 ID = 静默跳过 + 日志警告

## 调用约定

### 执行流程

```
工作流到达 Hook 点
  → 查询当前项目启用的插件列表
  → 从插件注册表获取插件实例（缓存）
  → 依次调用每个插件的对应钩子方法
  → 聚合结果（策略取决于钩子类型）
  → 继续工作流
```

### 结果聚合策略

| 钩子 | 聚合策略 |
|---|---|
| `on_scan_complete` | 链式传递：插件A的输出 → 插件B的输入。任一插件返回空列表则中断链。 |
| `on_commit_select` | 合并去重：所有插件的推荐索引合并为 set。 |
| `on_commit_message` | 优先级取第一个非 None 返回值（按插件列表顺序）。 |
| `on_sync_start` | 所有插件返回 None 才放行，任一返回非空则中断并显示该消息。 |
| `on_push_start` | 同上。 |
| `on_sync_complete / on_push_complete` | 全部执行，不聚合。 |

### 错误处理

- 单个插件抛异常 → 捕获异常 + 日志警告 + **跳过该插件继续执行**
- 所有插件均失败 → 相当于没有插件，走默认流程
- 插件加载时语法错误 → 日志警告 + 不注册
- 对用户可见的错误仅限 `on_sync_start` / `on_push_start` 的阻断消息

## 子进程协议（后续扩展）

非 Python 插件通过子进程 + stdin/stdout JSON 接入：

```
主程序 → stdin: {"hook": "on_commit_message", "args": {...}, "seq": 1}
插件   → stdout: {"result": "...", "seq": 1}
```

- 超时：5s，超时视为返回 None
- 插件路径在 `plugins/` 下的可执行文件（Linux）或 `.exe`（Windows）自动识别为子进程协议
- 环境变量 `GITGO_PLUGIN=1` 通知插件运行在子进程模式

## 与周边模块的关系

| 模块 | 关系 |
|---|---|
| **SyncSession (Phase 2)** | SyncSession 状态机直接调用插件 Hook，插件成为状态转换的观察者 |
| **GUI/CUI** | Hook 的阻断消息通过 UI 提示框显示（`on_sync_start` 返回的错误） |
| **Config** | `ProjectConfig.plugins` 字段（`list[str]`）控制每个项目启用哪些插件 |
| **core.py** | `sync_to_backup()` / `push_to_backup()` 函数签名增加可选的 `plugin_context` 参数 |
| **build.py** | 打包时需包含 `plugins/` 目录 + `--add-data` 分发内置插件 |

## 示例插件场景

### 1. 自动合并推荐（auto-merge）

扫描 workspace commit 列表，按时间窗口和 type 分组，推荐连续的同类型 commit 合并为一个。

### 2. 智能 message 生成（commit-msg-gen）

分析已选 commit 的 diff 摘要和 Conventional Commits 信息，自动生成格式正确的正式 commit message。可集成 LLM API（用户自备 key）。

### 3. 安全检查（security-check）

`on_sync_start` / `on_push_start` 中扫描待同步文件是否包含疑似密钥/密码，命中则阻断并提示。

> **注意**：内置的 Push 前安全检查（见 `iterations/Push安全检查设计.md`）是独立于插件系统的硬功能，在 `core.push_to_backup()` 中直接调用。插件版的 security-check 是其可选替代/增强，两者可共存。
