# Gitgo v0.24+ — 知识传承 + 著作权 + 漂移检测

> 设计日期：2026-05-19 | 基于 v0.23 源码 | 讨论驱动设计

---

## 一、背景

v0.21-v0.23 解决了"管 git"和"管状态"。但 vibe coding / 人+AI 编程场景下还有三个缺口：

1. **LLM 记忆管理**：LLM 反复踩同一个坑，没有自动记录和跨项目迁移
2. **著作权管理**：push 出去的代码包含 AI 痕迹，用户希望"人类作者模式"
3. **漂移检测**：LLM 遇到困难时绕过问题，悄悄删除功能或更换技术栈

---

## 二、Lesson 系统（知识传承）

### 核心原则

- **成功后才触发萃取**：失败只是记录，成功+人确认后才形成正式教训
- **双层架构**：抽象层（跨项目通用）+ 实例层（单项目具体），实例继承抽象
- **判据化**：每条知识附带可自动执行的检查规则——push 前跑一遍
- **Git 化**：知识库在 backup repo 的 `.gitgo/knowledge/` 下版本管理

### Lesson 结构

```yaml
id: "qt_006"
tech_stack: "python+qt6+pyside6"
category: "api_migration"
severity: "high"

# ── 判据（永远展示给 LLM，低 token 消耗）──
trigger: "在 PySide6/Qt6 中使用图标"
rule: "使用 QStyle.standardIcon(QStyle.StandardPixmap) 替代 Qt5 的 QStyle.SP_* 枚举"

# ── 解析历史（默认截断，可打开）──
resolution_history:
  show_by_default: false
  original_problem: "Qt5→Qt6 图标 API 迁移"
  failed_approaches:
    - approach: "QStyle.SP_DialogOkButton"
      error: "AttributeError: Qt6 removed SP_* enum"
      feedback_source: "human"
    - approach: "QApplication.style().standardIcon()"
      error: "返回 QPixmap 而非 QIcon，类型不匹配"
      feedback_source: "human"
  final_solution: "QStyle.standardIcon(QStyle.StandardPixmap.SP_DialogOkButton)"

# ── 检查规则（自动执行）──
check:
  type: "regex_scan"
  pattern: "QStyle\\.SP_\\w+"
  in_files: "**/*.py"
  message: "Qt6 已移除 SP_* 枚举，使用 QStyle.StandardPixmap 替代"
  severity: "error"

# ── 元数据 ──
verified_in: ["gitgo", "myapp"]
verified_count: 2
harvested_from: "gitgo:session_042"
harvested_at: "2026-05-19T12:00:00"
last_verified_at: "2026-05-19"
```

### 自动收割流程

```
step_sync 成功（人确认了）
  │
  ├→ 1. 读取本次 session 的操作日志
  │    - 有没有反复修改的同一个文件？
  │    - 有没有被取消后又重试的 formalize？
  │    - 有没有被 rejected 后又被 accepted 的 trial change？
  │
  ├→ 2. 如果检测到"多次失败 → 最终成功"的模式
  │    - 自动生成 Lesson 草稿（unverified）
  │    - 写入 .gitgo/knowledge/instances/<project>/pending.jsonl
  │
  ├→ 3. 在下次 GUI/CLI 会话中展示草稿 → 人确认/编辑/删除
  │    - 确认后 → 正式归档
  │    - 人可标记"值得萃取为抽象层"
  │
  └→ 4. 如果同一个 pattern 在 N 个不同项目中都确认
       - 提示用户萃取为抽象层知识
       - 之后所有同技术栈项目自动继承
```

### 存储结构

```
.gitgo/knowledge/
├── abstract/              ← 跨项目通用知识
│   ├── python.jsonl
│   ├── react.jsonl
│   └── qt.jsonl
├── instances/             ← 单项目实例
│   └── <project_name>/
│       ├── lessons.jsonl
│       └── pending.jsonl
├── contracts/             ← 项目合约（见第四节）
│   └── <project_name>.yaml
└── checks/
    └── pre_push_rules.json  ← 从 abstract 层自动生成
```

### 与 Claude Code Skill 的关系

**双向互转**：
- Skill → 导入为抽象层知识（人手动或 gitgo 解析 Skill 格式）
- 抽象层知识 → 导出为 Skill 草稿（同一知识在 N 个项目验证后自动提示）

**区别**：
| | Skill | Lesson |
|---|-------|--------|
| 来源 | 人主动编写 | 自动收割 + 人确认 |
| 语气 | 规范性 | 经验性 |
| 更新 | 人手维护 | sync 时自动更新 |
| 默认展示 | 全部展示 | trigger+rule 展示，历史截断 |

### CLI / MCP

```bash
gitgo lesson list --project X [--abstract] [--tech-stack python] --json
gitgo lesson add --project X --trigger "..." --rule "..." [--abstract]
gitgo lesson verify --id qt_006     # 标记为已验证
gitgo lesson promote --id qt_006    # 实例 → 提升为抽象层
gitgo lesson search "QStyle" --project X --json
```

MCP 新增 6 个工具：`gitgo_lesson_list / add / verify / promote / search / pending`

## 三、Authorship 过滤（著作权管理）

### 核心原则

- **只在 push 时转换** —— workspace 一切不变
- **可配置粒度** —— 标准清洗 / 激进清洗
- **Commit message + 代码注释 + AI 配置文件** —— 三个维度独立控制

### 清洗规则

| 维度 | 标准 | 激进 |
|------|------|------|
| Commit message | 去除 `Co-authored-by:` `via Cursor` `Generated with Copilot` 等 | 同标准 |
| 代码注释 | 不处理 | 去除 `# Generated by` `// AI-generated` `# via Claude` 等 |
| AI 配置 | 排除 `CLAUDE.md` `.claude/` `.codex/` `.cursor/` | 同标准 |
| Git 元数据 | 保留 | 保留 |

### 配置（`sync_config.json` 项目级）

```json
{
  "authorship": {
    "mode": "human_only",
    "strip_commit_coauthors": true,
    "strip_code_comments": false,
    "exclude_tool_configs": [
      "CLAUDE.md", ".claude/", ".codex/", ".codebuddy/", ".cursor/"
    ]
  }
}
```

### CLI

```bash
gitgo push --project X --strip-authorship
gitgo push --project X --strip-authorship --aggressive
```

### MCP

`gitgo_push` 已有 `skip_security` 参数，新增 `strip_authorship: bool` 和 `aggressive: bool` 参数。

## 四、漂移检测（Project Contract）

### 核心原则

- **合约是机器可读的功能清单** —— 不是 README，不是散文
- **sync 成功后自动更新** —— 人确认=合约自动反映当前状态
- **push 前自动对比** —— 检测到漂移 → hold → 人等会儿决策

### 合约格式（`.gitgo/contract.yaml`）

```yaml
project: gitgo
created: "2026-05-19"
updated: "2026-05-19"

tech_stack:
  - python>=3.10
  - pyside6
  - qt6

decided_features:
  - name: dark_mode_toggle
    location: frontend/workspace/workshop_tab.py
    signature: "method _toggle_dark_mode"
    introduced: "2026-05-12"
    last_modified: "2026-05-17"
    confirmed_count: 3  # 经过几次 sync 确认

  - name: commit_canvas_bezier
    location: frontend/commit_canvas.py
    signature: "class CommitCanvas"
    introduced: "2026-05-10"
    last_modified: "2026-05-14"
    confirmed_count: 5

architecture_constraints:
  - "不使用绝对定位（move/resize/setGeometry）"
  - "不跳过 git hooks"
  - "CLI 调用经过 step_* 方法，不直接 mutation"
```

### 检测规则

| 检测 | 触发条件 | 严重度 |
|------|---------|--------|
| 技术栈漂移 | 新增未声明的 import/依赖 | warning |
| 功能删除 | decided_feature 的文件被删除或签名消失 | **error** |
| 架构漂移 | architecture_constraints 中声明的规则被新代码打破 | **error** |
| 依赖替换 | 已有依赖被完全不同的库替换 | warning |

### 交互

```
[DRIFT DETECTED] dark_mode_toggle
  签名 "_toggle_dark_mode" 已从 workshop_tab.py 中消失。
  该功能已跨 3 次 sync 确认。

  (a) 同意 — 有意的设计变更，更新合约
  (b) 拒绝 — LLM 在绕路，需要重新实现
  (c) 忽略本次 — 继续 push，合约不变（下次还会提醒）
```

### CLI / MCP

```bash
gitgo contract show --project X
gitgo contract update --project X   # 手动刷新合约
```

MCP 新增：`gitgo_contract_show / update`

## 六、和已有系统的关系

```
Identity Guard (v0.23)          Lesson System (v0.24)
────────────────────            ─────────────────────
检测身份文件被删除               → 触发自动收割（如果是意外删除）
检测目录骨架崩塌                 → 触发自动收割（如果是 LLM 覆盖）
快照工具记忆到 backup            → 知识库自己也版本化在 backup
export include_identity          → 新增 knowledge/contract 导出

Template System (v0.22)         Lesson System (v0.24)
────────────────────            ─────────────────────
模板变量填充 commit message      → 知识库补充：commit 时自动附加相关教训
CLI --mode template             → CLI --mode lesson（同级）

Governance (v0.21)              Lesson System (v0.24)
────────────────────            ─────────────────────
patterns 检测共变模块            → contracts 检测架构约束
quality 度量采纳率               → lesson verified_count 度量知识可靠性
```

**零冲突，纯加法。** 新系统利用现有 hook 点（step_scan/step_sync/step_push），不修改已有流程。
