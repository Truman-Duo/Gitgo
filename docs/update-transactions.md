# 更新事务：模拟验收范围

关联：[安全自动更新与回滚 #21](https://github.com/Truman-Duo/Gitgo/issues/21)。前置行为见[更新检查与隔离解压](update-discovery.md)。

## 当前状态

新增明确选择的 [POSIX 管理安装/启动层](managed-installation.md)：schema 2 的本地登记、独立 bootstrap、共享内核运行租约与启动前恢复，复用本文件的事务引擎。默认 legacy 安装保持不变，不接管旧目录。该层尚不开放应用更新或激活开关，完整更新交接与发行/平台验收仍待完成；以下模拟模式和管理模式必须区分。

项目列表首页新增 `/update` 软件更新状态面板；工作区聊天、Agent 详情和进程列表不提供该命令，手工输入也不会打开更新面板。面板只读取本地 `update.status`，显示实际 Host 版本、stable 渠道及禁用状态；刷新不联网、不下载、不切换、不回滚。额外参数（如 `/update apply`）不被支持。后端没有开放启用或应用更新的操作，环境变量和 Provider 配置不能赋予更新权威。

`/config general` 的 `Gitgo Version` 是独立只读信息，来源为 `product.version` 返回的实际执行 Host 版本，不从可编辑配置或 Dashboard 的包版本猜测。旧 Host 不支持新操作、协议内容不合法或读取失败时显示不可用，而不是声称已更新到某个版本。它不占用可编辑设置的选择行。

当前增加的是 **POSIX 模拟安装事务原型**，不是已发布的自动更新器。只能显式登记一个最初为空、归当前用户所有、权限私有的独立目录；拒绝接管非空目录或真实安装。登记含模拟标记、安装 ID、根路径、设备/目录身份、产品目标、数据兼容描述与本地保护路径。没有安装器、Dashboard、Host 或真实启动入口调用它。

控制/事务父目录和两把锁的设备/inode 身份也固定在登记中；原路径下复制一个新目录、重建锁文件，不能获得原安装的操作权威。读取登记返回独立快照，修改调用方读到的字典不会改变捕获的权威。

更新总开关默认关闭；关闭时应用操作不读登记、不锁目录、不检查时钟、不联网、不改磁盘。开启也只能显式调用模拟操作。它不操作现有 Gitgo、系统 PATH、用户配置、秘密、数据库、项目或工作树，不执行包内安装/卸载脚本，不杀进程。

## 候选进入事务的门禁

不以 `staged` 对象、用户确认、一个布尔值或调用方声称的文件摘要代替验证。模拟应用重新验签、核对目标/渠道/版本/有效期/最低更新器/数据兼容及已有渠道记录；重新核对压缩包大小和 SHA256，并在本安装拥有的新目录重新安全展开。

- `product.json` 要求目标渲染的 schema 2，产品、版本、平台、架构、主命令与当前支持的组件布局一致；组件必须是普通文件，Unix 组件需有用户执行权限。
- `build-manifest.json` 要求 schema 1，版本、目标、声明的源码 commit/tree 与签名一致、来源不脏；完整文件/链接清单必须与实际展开内容对应，不依赖清单排序。元数据只读、有大小限制，不导入候选代码。
- 候选不能携带本地 `.gitgo-install-owner` 或 PATH 所有权记录；这些权威不应来自远程发行包。
- 原型提出独立 `update-data-contract.json` schema 1，包含与签名一致的 `data_compatibility`、顺序迁移列表、配置/Provider 版本及证据文件路径/摘要。列出的普通文件字节必须匹配摘要；不执行数据库或配置迁移。

打包器现有**默认不启用的证据生成选项**（Unix `--update-evidence`、Windows `-UpdateEvidence`）：比较构建环境与实际冻结 Host 的迁移 SQL/写入代码指纹，匹配后生成证据文件与数据契约，再进入构建 inventory。旧发行包及未选择该选项的包仍缺少描述，继续拒绝，不猜测兼容性。

Host 的检查角色先于普通应用初始化，使用 storage facade 内的受限内存数据库验证迁移 SQL；不读取配置、不初始化原生凭据、不迁移真实数据库。内存连接禁止外部数据库、文件临时存储、扩展与文件函数。进程有超时和输出上限，父进程只传明确的测试配置位置，不转发 API key；这仍不是 OS 沙箱。

可显式向模拟事务提供冻结 Host 健康驱动，核对真实产品版本、目标和数据指纹。驱动保持运行范围清理事实与子进程业务结果分离；macOS 现有 owned-session-only 报告不完整时不能提交更新。生成的 `update-probe-result.json` 保留这项限制，并明确 `update_commit_authorized=false`。生产安装协调、稳定启动门禁和独立更新 helper 仍未接入，不能把证据生成或内存健康检查当作完整产品启动/回滚验收。

### 独立模拟恢复进程

新增明确调用的内部角色 `update-recover-simulation`，在普通 Host、Provider 和项目 daemon 初始化之前处理请求。它**仅恢复已经登记的 POSIX 模拟安装**，不创建或接管真实安装、不检查发行网络、不应用新包、不执行候选程序。采用与 `SimulationStore` 相同的 ledger、目录身份与两把锁，不创建第二套恢复状态。

请求经有界 stdin JSON 传递，携带调用方从本地登记捕获的安装 ID、根目录设备/inode、完整保护路径及一次性 nonce；恢复前重新打开并核对。非模拟标记、身份变化、保护路径缩减、重定向目录及无法确定的文件布局不被接管。有运行锁时报告 busy，不杀项目进程。无效输入和系统异常只输出稳定错误，不回显用户路径或输入内容。

显式协调器要求安装目录之外的独立、私有冻结 Host，并对整个 Host 组件目录核对预先捕获的文件树摘要；限制执行时间、输入和输出，隔离测试配置位置，不继承 API key。返回的版本/状态还要与重新取得运行门禁后的持久记录对应，不能只相信子进程说“恢复成功”。进程清理报告单独返回，macOS 的 `complete=false` 保留，不作为允许提交生产更新的证据。

可选择实际冻结工件验证：提供 `GITGO_UPDATE_TEST_HELPER` 指向专门构建、独立且私有的 `gitgo-host`，运行 `tests/test_update_recovery_helper.py`。测试会新建隔离模拟安装和配置/项目/数据库哨兵；不执行占位候选程序，不改调用方提供的 Host，也不操作日常安装。未提供工件的三个冻结案例明确跳过，源码跨进程退出/恢复测试仍执行。该验证不是两个真实产品版本升级，更不是生产安装或断电验收。

### 完整真实工件准备验证

可显式提供 `GITGO_UPDATE_TEST_ARCHIVE` 和 `GITGO_UPDATE_TEST_STAGE`（同一份干净构建的 Unix 完整归档及 staging），运行 `tests/test_update_real_artifact.py`。测试使用内存生成的一次性 Ed25519 签名与注入的 HTTPX 原始流，核对真实整包摘要、安全解压、完整组件清单、来源和实际数据证据，并演练坏签名、错误摘要、取消及中断传输的隔离目录清理和保护资料不变。macOS 额外验证：即使真实包验证通过，清理范围不完整仍不能获得健康通过。

测试声明的较旧版本仅是检查器输入，不代表已经安装了另一份真实产品。结果是整包准备/验证与安全拒绝证据，不能冒充两个真实版本升级、正式 CDN/代理、发行公钥分发或真实终端验收。未提供工件时六个案例明确跳过。

## 记录、切换与恢复

控制目录与可切换程序分开，同卷切换仅在模拟根内进行。单一 ledger 原子记录当前版本/完整目录身份、两个渠道各自的接受高水位及当前事务。控制文件限量、拒绝链接/硬链接、验证所有权和私有权限；写入使用随机独占临时文件、文件同步、替换、父目录同步。

版本应用顺序：

`准备完成 → 保存旧版意图 → 旧目录保留 → 发布新版意图 → 新目录就位 → 模拟健康检查 → 提交`

每个切换前先保存意图，移动后同步相关父目录。**两个目录移动不等于一次原子切换**；缺口期间模拟启动门禁不放行，重新打开后先按 ledger 与完整目录证据恢复。

- 新版未提交：保守恢复已登记的旧版，而不是猜测新版可以继续运行。
- 模拟健康检查要求结构化结果及匹配的产品、版本、目标、来源；还复查新旧目录内容。只有肯定的匹配结果才提交。
- 失败新版移动到本次失败槽，恢复旧版；不删除旧包、失败包、项目或数据库，不恢复数据库旧快照。
- 回滚意图、失败新版移走、旧版恢复及终态落盘都可再次恢复；重复恢复不重复执行业务工具或产生新的切换。
- 更新序号/摘要记录在破坏性切换前与准备记录一起保存；回滚不降低高水位，完全相同的签名发布可重试。已是当前版本的有效新清单也保存渠道高水位。stable/preview 不互相覆盖。
- 控制记录损坏、所有权/根目录改变、未知/重复目录、路径重定向、已登记内容或权限被修改、恢复写入失败时返回 `recovery_required`，保留对象和诊断；不重新建立基线，不递归删除未知目录。
- 临时控制文件和中断准备残留不会被当作权威，也不会自动接管或清理。最多保留 32 次事务目录，达到上限停止新的准备，另行维护。

## 并发与模拟启动门禁

有独立的安装操作排他锁与运行期间共享锁。应用/恢复必须取得排他运行锁；只要一个已登记模拟使用者仍持共享锁，就报告 busy，不杀 PID，不切换。锁文件保持同一 inode，不通过删锁文件“解锁”。进程结束后 OS 释放它持有的锁。

锁文件身份既在打开安装时检查，也在实际打开的描述符上核对；重建/替换会被拒绝，避免旧进程和新进程使用不同锁文件而产生第二套权威。

模拟启动只在无待恢复事务、当前与保留证据匹配时放行当前目录，并在使用期间保持共享锁。这还没有接入真实 Dashboard、Host、daemon 或安装器；不能证明现实中所有使用者都已退出，也不是跨产品的真实退出协议。

## 证据与限制

测试在 macOS ARM64/Python 上使用临时占位程序、内存测试密钥、模拟迁移证据和保护数据哨兵，覆盖切换/回滚各步骤异常、控制损坏、目录重定向、摘要/合同不符、磁盘/同步/重命名失败、重复恢复、渠道高水位、跨进程运行锁及子进程强制退出。

暂存与模拟事务的正向测试仅在 POSIX 主机运行；Windows CI 会跳过这些需要 POSIX 所有权与锁语义的用例。独立的平台边界测试在所有主机运行，检查非 POSIX 适配器缺失时先拒绝操作，以及关闭状态不访问任何依赖。跳过正向用例不构成 Windows 更新支持或验收证据。

原有注入健康驱动只读模拟元数据；新增冻结数据驱动可在临时 profile 中启动 Host 的限定检查角色，但不启动真实项目、完整 Dashboard 或业务工具。二者都不能证明整个产品可运行，也不构成隔离执行沙箱。真实方案仍需独立冻结 helper、安装器共同锁、正式退出/启动协议及真实冻结包回滚验收。

尚未接入正式安装登记/所有权记录、安装器共同锁、实际组件与数据指纹生成、发布信任根、Windows ACL/占用文件处理、正式退出协议、UI、生产 launcher 或历史清理；Windows/Linux 实机与真实冻结包未验收。文件/目录同步及强制退出测试不证明真实掉电、硬件写缓存或恶意同用户进程的安全性。

因此这不是可直接更新当前程序的发行功能，不能据模拟事务通过而打开自动更新。正式包集成与各平台故障验收完成前仍保持关闭。
