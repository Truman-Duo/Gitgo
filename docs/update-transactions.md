# 更新恢复与失败处理

关联 [Issue 21](https://github.com/Truman-Duo/Gitgo/issues/21)。当前管理安装已接入固定启动器、运行租约、确认交接、健康检查和保留版本回滚；不是只有模拟事务的原型。安装方式见[管理安装](managed-installation.md)，交互见[手动更新](update-preparation.md)。

## 更新保证

替换前重新验证发布者签名、目标、版本、有效期、防重放记录、完整包及数据兼容描述。下载成功或用户确认不能绕过这些检查。兼容描述变化时拒绝，不执行真实数据库或配置迁移。

切换只修改已登记且身份未变的程序目录，保留上一版。当前状态由同一安装记录确定；启动器先恢复未完成事务，再决定可启动版本。不会扫描未知历史目录并自动采用其中的程序。

健康检查在独立临时资料中执行实际 Host 检查和 Dashboard `--version`，不运行用户任务、不调用模型或读取用户秘密。业务退出码、清理事实和事务提交分别核对，缺少任何必要证据均不能报告更新成功。

## 常见失败

| 情况 | 行为与处理 |
|---|---|
| 其他实例持有运行租约 | 返回 busy；正常关闭相关实例后重新确认，不删锁文件 |
| 拥有的进程树清理未知 | 不允许交接；保留资源与失败状态，不能把根进程退出视为整树结束 |
| 包过期、被修改或验签失败 | 不切换；重新检查和准备，不能手工修改记录放行 |
| 候选健康检查失败 | 恢复旧程序；无法确定目录或持久状态时停止并保留证据 |
| 切换中断 | 下次由固定启动器恢复；不能重放已消费的用户请求 |
| 磁盘、同步或持久化失败 | 明确失败；保留已提交状态和必要诊断，不猜测成功 |
| 登记、目录或锁身份不符 | 拒绝接管；不通过重建锁或改写登记自动修复 |

显式回滚仅恢复最近一次成功更新保留的上一版，不回滚数据库/配置，不降低渠道防重放序号。保留记录和诊断有数量上限，超限明确拒绝；管理清理不删除未知内容或用户项目。

## 验证范围

源码故障注入覆盖切换、回滚、提交、重复恢复及并发运行锁；Windows 与 Linux 另有真实双版本冻结包测试，见 [Windows](windows-managed-update.md) 和 [Linux](linux-managed-update.md)。模拟模式仅用于隔离测试，不是实际安装授权或产品验收替代。

现有证据不证明所有硬件物理掉电耐久性、恶意同用户进程隔离、生产 CDN/代理或完整可见终端交互。macOS 只允许等待电脑重启的交接，实际跨重启升级/回滚尚待验收。正式更新源未配置，后台自动更新继续关闭。
